# 仪表歌词显示与封面曲目身份

2026-11-11；实现基线 `04cee50`。用户反馈仪表导航区域显示歌词，音乐图片偶尔闪烁。本次修正已确认的音乐元数据来源问题，导航显示与图片闪烁的实车结果继续待验。

## 日志定位

用户提供的 Release 20025 日志保留了部分启动记录与会话末段，不含本次活动会话完整识别、初始订阅和图片传输过程。保留片段包含19次将歌词作为 `5001` 媒体组标题发送的记录；同一片段里的完整歌名-歌手标签稳定，网易云媒体会话唯一匹配成功并报告真实播放状态。

71次 `5201` 道路字段来自宿主 HUD 文本，并未包含歌词。活动路线只发送组件、道路和距离，没有 guidanceState 或 `5202` 转向更新。这确认了当前导航适配缺口，但不能证明接收端为何在用户所述导航区域展示音乐。该片段没有封面引用或文件传输记录，仅有 cover/coverUrl 键存在；不能据此认定每次闪烁都是一次空图片发送。

## 依据与差异

沿用已核 CarWith 4.0.14 原始 DEX：classes2 `f5.d.q` code item `0x3350a8` 将歌词写入 song，并在 `0x335124..0x335168` 构造完整歌名-歌手标签；`0x335194..0x3351b2` 同时提供 coverUrl 与 Bitmap cover。位置为 DEX 文件偏移，指令正文位于 code item 加16 bytes处。详见研究仓库 `research/connection/spec/carwith-4.0.14-host-evidence.md` 和 `carwith-artwork-voice-20261110.md`。

此前完整标签匹配仅用于播放状态，显示和图片加载仍使用歌词标题。歌词变化会改变图片缓存中的曲目身份：即使是同一首歌，图片刷新失败也可能按换曲失败清除旧图。这是代码中可复现的路径，尚未绑定到本次每个实车闪烁时刻。

现在平台读取一次实际媒体会话元数据快照，沿用标准匹配和完整标签匹配的唯一性检查。桥接只有在完整标签对应唯一真实曲目时替换歌名、歌手，并将同一份结果交给音乐显示与图片缓存。没有拆分连字符；其他宿主字段保留。缺少授权、没有匹配、多个匹配、候选文本不能通过已有编码校验时保留宿主输入。进度通知和普通曲目信息继续沿用原处理。

平台读取不改变主线程播放监视器目标；播放监视器继续匹配原始宿主信息。协议编码、图片传输与订阅规则沿用现有实现，本项没有新增 Apple 状态或转向枚举。G03 的导航状态、机动和车道映射仍需各自补证，不能把宿主 action/turn 直接复制到 iAP 字段。

新增诊断记录标出媒体元数据匹配、是否纠正展示、图片来源类型、加载代际、解码结果及交付图片长度/摘要。图片地址和像素内容不会写入诊断。
