# 仪表图片频闪：带图片的元数据直接替换

日期：2026-11-10；修改基线 `67b68e3`（Release 20013）。修复与本记录同次提交；未打包、未实车复测。

用户日志出现36对空/非空图片引用，35对间隔不超过30 ms。
`CarLifeArtworkLoader.update()` 原先先走 `track()` 的换曲清空，再加载同一条元数据中的
图片。曲目身份变化和图片刷新相邻时，会额外发布空图片并迫使接收端切换引用。
完整统计与运行边界见研究仓库
`research/connection/spec/media-feedback-20013-20261110.md`。

新增会话内 `HostArtworkState`，由加载器原有锁串行访问：

- 带可读取图片来源的元数据先读取替换图，再发布；没有中间空图片。
- 相同解码图片字节不重复发布，宿主对象或曲目信息变化不单独重发同一图片。
- 换曲而无图片、明确空来源、新曲所有图片来源失败，仍清理旧图。
- 同曲图片刷新失败保留该曲已有图片；过期加载、后续无图更新和关闭继续隔离迟到回调。

慢加载期间会保留上一张已交付图片，成功后替换；新曲读取失败则清空。
既有读取超时和资源上限保留。日志没有图片内容或完整曲目身份，不能证明所有重复引用
都来自同一个宿主字段变化，接收端具体清图事件也未闭合。
