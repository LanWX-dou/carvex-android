# 音乐、导航、通话调试日志

既有日志主要记录消息编号和字段编号，不能直接确认歌词进入了哪个字段，也难以对照音乐暂停、导航结束和通话音频的状态变化。本次增加三类日志：`debug music event=...`、`debug navigation event=...`、`debug call event=...`。日志沿现有 `BridgeStore` 复制、导出和落盘路径记录，Debug 与 Release 均启用，不需要安装 Debug 包才能获得这些信息。

| 类别 | 观察内容 |
|---|---|
| 音乐 | 宿主曲目信息及 Intent 选定字段、标准化歌名/歌手/专辑/应用、进度、媒体会话权限及匹配、原始播放状态和 wire 状态、`5000` 订阅与 `5001` 字段、`5002` 停止订阅、`5003` 控制输入、音频源状态 |
| 导航 | HUD 动作、`navi_turn`、道路和距离、转向图片长度与摘要、开始/结束输入、桥接样本及未完成的映射、`5200`/`5203` 订阅、`5201`/`5202`/`5204` 实际字段、缓存和发送受阻原因、提示音源状态 |
| 通话 | 电话状态权限及监听注册、每个监听来源的 IDLE/RINGING/OFFHOOK、聚合活动状态、iAP 电话订阅与未安装的元数据提供器、媒体音频让路、麦克风格式选择、SETUP 请求/响应/失败、音频输入闸门及宿主接受/拒绝计数、TEARDOWN |

协议字段日志包含 `direction`、十六进制 `id`、`source`、`field` 与 `index`。音乐分组字段例如 `field=0.1 name=title`，导航道路例如 `id=5201 field=3 name=currentRoad`。两者分别标记业务类别，不因仪表所在页面而混称导航。

运行期发送使用单调递增的 `tx` 编号，关联字段、`queued accepted=...` 和 `transport completed=...`。字段日志发生在提交尝试时；未获运行状态授权会出现 `blocked`，不代表消息已经发送。入队、传输完成与车机实际显示分别判断，传输完成日志明确保留 `receiver display unverified`。

文本预览最多取 96 个 UTF-16 字符，转义后最多 192 个字符，附原始字符数和截短 SHA256 摘要，以便比较同一歌词或道路。图片仅记长度及摘要；不展开整个 Intent、Parcelable、联系人、号码、通话标识或 PCM 内容。iAP 字段展示限制顶层和分组数量，异常分组只记录解析失败和长度。电话状态 OFFHOOK 包括拨号和保持，不能当成对方已经接听。

会话内另保留最多 192 个字段/采样键的最新记录，以及每类最多 128 条关键事件，其中保留最初 12 条和近期事件。高频歌词、距离和音频采样不会挤掉关键事件区；清空日志或开始下一次连接会清除该区，导出仍按原有时间顺序合并。这是有上限的诊断保留，不是完整抓包。

本次只增加观测，不改变协议字段、顺序、订阅、控制状态或重试行为。导航路线/机动及订阅沿既有 accessoryd `0x1000027f4`、`0x1001777c0`、`0x10017527c` / `0x10017593c` 路径；基线二进制 SHA256 为 `2b0a2010e6d2605e07d87f05659c932e03de34476a76431196a9bb58da7dc4fe`。导航状态、箭头及车道映射仍是既有未完成项，详见[路线结束缓存记录](2026-11-10-g03-navigation-end.md)。通话麦克风与 iAP 电话元数据分开记录，详见[通话麦克风记录](2026-11-10-call-microphone.md)。

复现时从连接开始保留日志，保持导航活动，播放音乐后暂停再恢复，最后结束导航。通话另记录拨号、通话活动和挂断。通过应用现有日志导出入口导出，按三类前缀过滤，并用同一会话时间戳对照实际仪表现象。
