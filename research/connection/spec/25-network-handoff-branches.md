手机新增 `StartSessionSyntax` 只产生内部归一形式：已知组重新组织、标量槽合并；不是向车机发送的新报文。平台观察仍收到原字段顺序。JVM文本转换、CF分配/失败、Unicode等价未闭合；不声称逐位复刻CF行为。

## 2. 4301 已知字段分支覆盖

原入口：accessoryd `0x10016d3ac`，成功平台调用 `0x10016db74 → 0x100063fd0`。错误路径汇入 `0x10016df6c`，设置失败结果并清理，未进入该平台调用。

| 字段 | 原getter/行为 | 本批实现 |
|---|---|---|
| `0/0` USB地址 | CString，数组追加 | 检查语法并保留数组；不当作无线候选 |
| `1/0` SSID、`1/1`口令 | CString，标量替换 | 逐次校验，末值替换 |
| `1/2` channel、`1/4` security | U8 | 必须1字节；不猜security枚举 |
| `1/3` Wi-Fi地址 | CString，数组追加 | 跨重复组累加；后续本地IP解析策略不变 |
| `2` port | BE U32 | 语法必须4字节；1…65535是后续Android TCP约束 |
| `3` deviceID、`4` pubKey、`5` srcVer、`6` sdkVer | CString，标量替换 | 先检完整语法，再使用现有ID/公钥hint/版本来源逻辑 |
| `7/0` assetID、`7/1` assetVer | CString / BE U32 | 即使当前不消费资产，也校验已知字段；跨重复组保留槽 |
| `8` mutualAuth | Bool | 1字节且值0/1；缺失仍unknown，不建立信任 |
| 未知outer/leaf | 跳过继续 | 不递归解释未知载荷，不新设拒绝参数 |
| 空/部分消息 | 仍可调用平台 | 不发明默认地址/端口/凭据，不自动生成就绪端点 |

关键汇编复核点：USB CString/append `0x10016d5dc–0x10016d604`；外层port getter/store `0x10016d678–0x10016d688`；asset槽 `0x10016d6d8–0x10016d720`；Wi-Fi getter在 `0x10016d7d8/0x10016d7f4/0x10016d82c/0x10016d854/0x10016d888`；Bool在 `0x10016d950`。已知组的内部TLV边界继续使用本项目已有严格framing规则；未宣称Apple迭代器所有畸形边界已等价。

CString getter `0x100067ee4` 检查TLV总长至少5，读取最后value字节判断NUL；允许空CString，也允许中间NUL但末字节仍须NUL。U8 `0x100067e4c` 要求总长5；U32 `0x100067df0` 要求总长8且BE；Bool `0x100067e74` 检查总长5与0/1值。

## 3. 5703 与联网不是同一完成状态

原5703 handler `0x1001703cc` 按顺序处理0–4，忽略5/6及未知；字符串/数值getter失败不异步交平台。BSSID按原始长度保留，不擅加6字节必填。成功只证明平台任务已安排。

WiFiSharing `0x2431186ac` 仍显示单独的平台条件：SSID为nil，或者口令对象存在但security为0时不配置；security≥3进入诊断并映射0，不能仅此推断全局拒收。此次未恢复其三项映射对象的最终语义，**现有Android security映射未改变，也不提升为苹果标准**。

当前App已有5703-only分支，不会永久强制等待4301：

- 没请求4301且5703足以满足本地联网规则，可交接给网络和发现路径。
- 已请求4301时，保留现有本地最多30秒的等待预算；到期仍可用5703-only，不因重复5703续期。
- 本批修正部分5703提前退出；如果始终没有可用配置，到原deadline报告错误。
- Android 13+采用指定Network的NSD；Android 10–12在无直接4301端点时仍明确报不支持，因为现有NSD入口无法限定Network。未通过接纳全局任意候选绕过这个限制。

这是当前本地策略，不是已经证明iPhone固定等待30秒，也不是完成了5703-only的全部邀请/车辆匹配分支。

## 4. 网络就绪和发现仍待补齐

`NetworkLinkReadiness` 只要求非空接口名和至少一个非loopback/any-local/multicast本地地址；不要求互联网，不把IPv6 link-local一律删掉，不把此检查称作车机可达。后续socket仍绑定选中Network；IPv6 scope按选中接口处理。实际路由、服务和控制端口连接另验收。

本轮只读检查发现以下仍OPEN，未盲改：

1. 网络复用需要更完整的生命周期监视；当前复用路径不新注册专门onLost订阅，后续主要由实际socket故障反馈。
2. 4301/Bonjour/邀请的车辆身份融合未复原。当前发现器接受同Network候选，即使deviceID与4301规范化值不同；仍检查公钥hint一致性并由后续安全路线验证。不能把旧源码注释“固件只要求邀请头存在”当作完整身份匹配证明。
3. 仅5703信息、直接4301、已有网络三入口的真实异步并行/优先级仍不完整。没有添加固定端口、猜测车型或强制IP族。
4. security映射、保存/更新/清除凭据的provider与实际OS关联回调仍缺证据；第一次/重连/取消完整时间线未复原。
5. 4301已知字段语法补齐不等于所有合法部分请求都能在Android合并成端点；跨消息累积凭据需要明确身份/生命周期规则，当前不从旧会话补默认值。

因此网络/启动输入G5仍PARTIAL，网络就绪G6仍需目标环境证据。
