# 18 — Identification 核心字段：逐条件与副作用复核


## 1. 防止“看过函数”冒充“分支覆盖”

本轮从原始accessoryd重读8个函数，与既有`.bin`完整比较，再用Capstone 5.0.7重解码；同时直接重读35项核心switch偏移表。源镜像SHA-256为 `2b0a2010e6d2605e07d87f05659c932e03de34476a76431196a9bb58da7dc4fe`。

[identification-core-branches.json](../evidence/identification-core-branches.json) 保存每条条件跳转、条件取值、间接跳转和直接调用/跳转的地址、原字节、目标及符号；[复核工具](../tools/inspect_identification_core_branches.py)只读输出JSON，不覆写旧证据。

8个局部函数共有78条条件跳转、6条条件取值、2条间接控制转移。**这不是78个已验证的协议分支，也不是覆盖率**：其中包含日志、对象释放和指针认证检查；反过来，switch、调用返回值与跨函数组合又不能仅按跳转数计数。真正的语义复核见下表；依赖未闭合的部分显式标为OPEN。

## 2. 核心语义分支表

地址省略`0x`；ID是1D01外层字段号，不是内部状态。真假表示该行条件的两条结果，不把局部返回值等同于最终1D02/1D03。

| 分支ID / 地址 | 条件 | 成立时 | 不成立时 | 状态、副作用及边界 |
|---|---|---|---|---|
| IC-01a / `100067eec–7f00` | TLV总长≥5 | 检查最后一个值字节 | status=1、返回NULL | 至少含一个值字节；上层缓冲范围仍是调用前提 |
| IC-01b / `100067f18–7f28` | 最后值字节=0 | status=0、返回param+4 | status=1、返回NULL | 不是“任意位置找到NUL即可”；本函数不排除中间NUL |
| IC-02a / `1000f2bc4`、`1000f2bcc` | framing指针非NULL且status=0 | 交CFStringCreateWithCString，编码`0x08000100` | 返回NULL，不调用CF转换 | 两个检查独立，不能只取一个 |
| IC-02b / `1000f2bf8–2c10` | 尾调用的指针认证检查通过 | 尾调用CF函数 | trap | 安全/编译器路径，不解释为协议拒绝；不在Android伪造PAC |
| IC-03a / `10004f114–f128` | 输出槽存在且status=0 | 把转换结果写入槽，返回0 | 进入拒绝/释放路径 | 此处未额外检查CF返回值非NULL；转换结果NULL的完整运行语义OPEN |

## 3. 必须沿全局dispatch核对，不能只看core switch

本轮直接恢复的core switch包括：0..7、12/13、14/15/16/17/24/26、19、34。8/9、20等在该switch落“未处理”，但**全局注册表会先把8/9分派给power handler、20/21分派给vehicle handler**，正常路径根本不要求core处理它们。

当前手机 `Bootstrap.kt:489–496` 从局部未处理分支推导“8/9等是未登记ID”的注释不成立。其既有 `identificationIgnoresUnlistedParameterIds` 测试甚至把8/9编码为CString，然后要求1D02；该测试通过只能证明本地现状，不能证明苹果接受该形态。

完全未知的ID另有原始链：全局handler缺失→callback返回1→ForEach返回非0→初始handler不进入required/checkAll成功路线。未知字段放在消息开头、中间或末尾均不自动变成“安全忽略”；具体指令与原始证据见[17](17-identification-feature-message-branches.md)。

## 4. 与当前手机实现的精确差异

手机源码定位：`protocol-carplay/src/main/java/io/github/iamr0s/carvex/sessioncore/IapIdentifyInfo.kt`、`carplay/core/Wire.kt`、`carplay/Bootstrap.kt`。对应文件SHA-256保存在本章新JSON，不覆盖12/14旧快照。

| 条件 | 当前手机 | 24A446有界事实 | 后续实施要求 |
|---|---|---|---|
| 0..5重复合法标量 | IapFields singleton getter直接拒绝重复 | 先释放旧值，再解析新值 | 有序字段处理，不全局放宽IapFields所有用户 |
| 6/7重复合法列表 | 直接拒绝重复 | 新集合替换旧集合 | 分清列表内重复ID去重与同字段重复替换 |
| 12/13出现但内容畸形 | 只在required里检查出现，未解析值 | 真正解析成功、13还有集合重复检查 | 不能仅向required列表增8/9后就结束 |
| 0..5值为`41 00 42` | `IapWire.text`取第一个NUL，得到`A` | getter因末字节非0返回失败 | 针对此消费者补framing，别盲改全局text全部协议 |
| 值为`41 00 42 00` | 读到第一NUL | framing通过，CF也以CString为输入 | 不额外发明“禁止中间NUL”的苹果规则 |
| 空串`00` | 返回空串 | framing通过 | 是否还受field/feature语义约束必须再追，不能一律补非空限制 |
| 缺8/9 | 仍可接受 | required-success不完整 | 将provider条件、宽度与状态一起接入，见15 |
| 部分合法后字段失败 | parser抛异常，Bootstrap发1D03后throw | 初始消息进入拒绝/授权/可再次提交；更新消息又有不同副作用 | 字段修复须与16的事务生命周期配套 |
| rawParameters保存 | 保存全部原字节及顺序 | 有各字段消费者与成功/错误状态 | 保存原始数据不能替代解析成功和能力验证 |

## 5. 独立回归向量（拟议，尚未执行）

以下是后续用例的oracle输入，不是本轮新增已通过的测试。输入基线须来自完整注册/承载/feature合同，禁止测试夹具自动补齐被故意删掉的字段。

| 向量 | 需要观察的分支与结果 |
|---|---|
| 字符串长度0 / `00` / 无NUL / `41 00 42` / `41 00 42 00` | 分别验证宽度、末NUL、中间NUL；把framing成功与CF/feature成功分开 |
| 标量同ID：合法→合法、合法→非法、非法→合法 | 替换与释放；首次失败不能被最后有效值掩盖；记录是否停止遍历 |

| 真unknown插在最前/中间/末尾 | 都检查遍历结果和发送路径；不能只测unknown是否被存入rawParameters |
| 同样字段序列分别放1D01与1D06 | 验证初始/更新状态、保留/替换/部分副作用不同，而非复用一个全量parser |
| 发送1D02/1D03失败、回调前后换epoch | 不仅断言异常，还检查已发布身份、发送消息、是否能重试和旧信息是否泄漏 |
