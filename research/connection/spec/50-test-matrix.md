# 连接与视频验收矩阵

这是 `LOCAL_DESIGN` 验收计划，不是宣称已经跑过的测试。默认全部 `NOT_RUN`；必须有具体设备、构建、日期、输入记录、观察及结论后才改为通过。用户此前“声音正常”的反馈不能批量填绿。

后续本地单测与合成线上字节向量的实际执行见[63](63-alignment-batch1.md)、[65](65-identification-lifecycle-batch2.md)、[66](66-identification-core-batch3.md)、[67](67-connection-mainline-batch4.md)。第四批完整890项通过，含SETUP缺字段/错误类型/拒绝/条件RECORD/清理及网络输入向量；这些不是下表目标环境与实车项目的替代，不自动把整行NOT_RUN改为通过。

## 1. 每次样本必须记录

- 手机系统/App版本与实际构建标识、车机型号和可获得的固件版本、无线配置。
- 首次配对、已配对重连或断线恢复；测试前哪些配对/网络/应用记录存在。
- 源蓝牙和目标IP连接的独立身份、生命周期、接口、地址族；隐私标识匿名化。
- 发送端单调时间线；可取得的车机原日志；必要时车机画面录像。
- 分别判定编码输出、写入网络、车机接收、解密、解码、实际显示、持续更新、重连。
- 若某层不可观察，写“未观察”，不得用下游或上游的单一日志伪造该层直接证据。

## 2. 正向场景

| ID | 场景与前置条件 | 应收集的检查点 | 通过标准 | 状态 |
|---|---|---|---|---|
| T01 | 首次使用；尚未bond。删除已有记录只在用户另行允许时做 | 系统配对/UI授权、服务、iAP2、网络、控制、视频全部 | 车机实际出现可辨识画面并持续变化；不能从已配对起点冒充首次 | NOT_RUN |
| T02 | 已配对、应用新进程 | 旧记录选择、新连接、重新验证、视频 | 不重新要求无必要的全量配对；本次会话验证完成且显示 | NOT_RUN |
| T03 | 正常退出后重连 | 旧资源释放、下一attempt新状态、端口/连接ID | 第二次独立成功，旧回调不污染新会话 | NOT_RUN |
| T04 | 车机上电/重启后重连 | 车机状态变化、发现/邀请、对端记录验证 | 重新建立完整有效链路和显示；不假定保留原地址 | NOT_RUN |
| T05 | 蓝牙反向发起 / 手机主动发起各路径 | SDP、实际发起方、最终选中socket、另一连接清理 | 一条明确的iAP2源链路，序号无跨socket混用 | NOT_RUN |
| T06 | 支持的4301启动路径 | 能力声明、4301字段、网络与端点来源 | 按实际路径建立，不强加未经证实的5703前置 | NOT_RUN |
| T07 | 观察到5703网络配置但无4301的设备 | 凭据接收、后续平台/服务/邀请路径 | 后续路径有证据且成功；不能把“有Wi-Fi”算完成 | NOT_RUN |
| T08 | IPv4及IPv6 link-local各支持场景 | 发现结果、scope、源接口、实际控制/视频socket | 两类地址分别实测，不用IPv4成功证明IPv6 | NOT_RUN |
| T09 | 视频持续更新 | 自定义运动/递增计数画面、发送与显示时间线 | 实际车机连续更新，无冻结/断连；观察时长和容忍值在测试前记录 | NOT_RUN |
| T10 | USB对照（单列，非无线验收替代） | USB链路/网络/iAP2路径 | 单独报告，不计入无线T01–T09通过 | NOT_RUN |

## 3. 异常与边界

这些是计划，不在本轮对用户设备主动断网、清配对或注入报文。

| ID | 受控变化 | 要验证的行为 | 状态 |
|---|---|---|---|
| N01 | RFCOMM已连但没有Detection/SYN进展 | 精确报链路协商等待，释放该attempt资源 | NOT_RUN |
| N02 | 链路帧截断、粘包、重复、校验错、序号回绕 | 按原协议重组/丢弃/重传语义；不得错交业务消息 | NOT_RUN |
| N03 | 控制session ID/版本不同；认证与识别顺序不同 | 按协商schema，不写死抓包中某次ID/顺序 | NOT_RUN |
| N04 | 证书/挑战拒绝、状态过期、错误对端记录 | 安全失败不会自动变成成功或复用上一链路授权 | NOT_RUN |
| N05 | 网络参数缺字段/长度错/不支持安全类型 | 报字段与分支；不把缺省凭据套入另一台车 | NOT_RUN |
| N06 | Wi-Fi已关联但无可用IP/路由或IPv6 scope | 不报告控制可达，指出网络就绪子条件 | NOT_RUN |
| N07 | 服务发现不响应、错误接口、SRV端口变化 | 区分有据可查的其他端点路径与无根据猜端口 | NOT_RUN |
| N08 | 控制响应CSeq错、拆包、Content-Length截断、拒绝状态 | 不把它归给下一请求，不以2xx掩盖正文不完整 | NOT_RUN |
| N09 | 视频SETUP streams为空/多个/type不符/dataPort无效 | 对照原消费者的结构校验拒绝，错误不升级为视频成功 | NOT_RUN |
| N10 | 视频端口拒绝或发送背压 | 控制与视频通道故障分开，终止/清理边界明确 | NOT_RUN |
| N11 | 缺少配置、错误NAL封装、非关键帧起播、错误密钥 | 单侧“发送成功”仍不得算首帧验收；定位接收/解密/解码层 | NOT_RUN |
| N12 | 连接建立中断蓝牙/Wi-Fi/取消UI | 按当前路径清理，晚到回调不推动新attempt | NOT_RUN |
| N13 | 显示中断网，再恢复 | 明确旧流结束与新会话验证、配置与关键帧重新供给 | NOT_RUN |
| N14 | 同车重复快速连接/取消 | 无旧socket、网络lease、定时器、encoder/资源状态泄漏 | NOT_RUN |
| N15 | 识别字段缺失、出现但解析失败、当前承载缺组件分别取样 | required-success而非出现计数；参数6/7方向和拒绝body可对应到[12](12-identification-contract.md) | NOT_RUN |
| N16 | 收到1D03后对同link再次提交；与更新识别分开 | state3允许再次1D01的局部路径与实际发送/授权结果；不默认重建链路或无限重试 | NOT_RUN |
| N17 | 关闭时无control、TEARDOWN失败、部分流注销先于发送 | 本地return0、keepalive最终返回、真正peer ACK三者分开；[24](24-disconnect-reconnect.md) | NOT_RUN |
| N18 | 完整响应缺CSeq/不匹配、旧connection迟到响应分别取样 | 当前App同步/异步分派与原局部对象/token关系分别记录，不把unmatched响应当waiter已完成 | NOT_RUN |
| N19 | 不同owner的timeout及覆盖条件 | kind5控制创建输入、event provider、底层消费/fallback、本次实际deadline分开；不能将10/60直接作总attempt预算 | NOT_RUN |
| N20 | 配置变化、NotSync附件与实际NAL不一致的离线样本 | type1配置在正确世代帧前写出；bit4不替代实际随机访问验证；[31](31-video-codec-contract.md) | NOT_RUN |
| N21 | 帧加密后append/write失败及新对象/旧对象恢复 | 不擅自复用nonce或重置旧对象；主载荷/尾段加密次数独立；全失败生命周期须继续核对 | NOT_RUN |
| N22 | iAP2 control>2、两份SYNACK版本／session／window变化、link与control版本独立组合 | 回发／提交／上层支持集合一致，不能只检查最终connected；先做受控离线peer测试，不直接注入用户车机 | NOT_RUN |
| N23 | 实际请求构造器输出初始／更新／视频SETUP及info | 版本头presence与声明来源一致；检查序列化bytes，不只检查手写测试字典；[62](62-version-capability-audit.md) | NOT_RUN |
| N24 | 4301、Bonjour与info的版本／能力冲突或缺失；formal/experiment、bit38/46组合 | 来源保留、实际route及不支持原因可核查；不以世代日志或自动认证降级代替实现 | NOT_RUN |
| N25 | 已审接收库最低build读取成功／失败及阈值边界；build触发不同AAD／显示分支 | 先验证有界离线行为，再判断当前声明是否完整；不盲换版本号，不推定固定最低值 | NOT_RUN |

## 4. 独立性与负证据

本项目自写解析器与自写发送器互测，只是局部测试，不能证明苹果兼容。优先用已定位的原函数、带原偏移的真实记录及真实车机观察交叉验证。对当前24A446尚无运行覆盖的场景保持未验证。

原始记录只覆盖某段时，未出现某条消息可能源于截断/过滤/另一承载，不能据此宣称该消息不需要。反过来，某次出现过也不等于每次必须出现。
