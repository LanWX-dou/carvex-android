## 2. 证据不能互相冒充

| 标签 | 证明范围 | 不能证明 |
|---|---|---|
| `STATIC24` | 本基线原函数生产/消费字段、分支及静态状态变化 | 真车实际走过该分支、所有车机都接受 |
| `ASM24` | 关键原指令及常量、跳转，与原函数字节定位一致 | 调用者总是满足该路径条件 |
| `EMU24` | 在注明输入、桩函数和模型限制下执行原指令 | 完整 iOS 栈、真实无线环境或完整安全链 |
| `CAPTURE_OTHER` | 指定旧版本抓包中实际存在的字节和方向 | 24A446 行为、报文缺失必然意味着协议不存在 |
| `LOG_OTHER` | 指定原始日志记录的事件、承载、时间 | 网络抓包等价性、对端已经解码/显示 |
| `ANDROID_NOW` | 当前工作树中可定位的实现分支（静态源码审计） | 测试 APK 与源码一致、运行时走过该分支、苹果规范或注释中的“实测”已经验证 |
| `USER_REPORT` | 用户对特定一次测试的反馈 | 未说明版本/车机/条件的完整测试矩阵 |
| `LOCAL_DESIGN` | 本文定义的诊断、测试、日志组织规则 | 苹果原生枚举、报文格式或规定超时 |
| `OPEN` | 尚缺直接证据的精确问题 | 可以任选一个值并宣称兼容 |

同一结论可以有多个独立标签；数量不替代证据相关性。原反编译 C 中的错误签名、指针类型、符号恢复不可直接当协议类型。影响长度、条件、端序、加密或状态转移时查汇编及原字节。

## 5. 出版约束

1. 每条有协议效力的结论要说明版本、生产者/消费者、适用路径和证据。
2. 缺失字段不自动解释为零、false 或“不支持”；必须追查消费者缺省处理。
3. 会话 ID、连接 ID、端口、随机数、密钥不得复制成固定 iPhone 常量。
4. 不用一台车的 workaround 代替全协议规则；不把 Android 本地调度器超时写成苹果规定。
5. USB 单列；无线成功不得借用 USB 路径替代。
6. 仅本目录可写；原固件、旧文档、参考项目及所有车机端均只读。
