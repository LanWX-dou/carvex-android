# spec/03 — 中继事务

## 3.1 发送一条隧道数据

**R-3.1** 发送顺序必须是：`pack(type, data)` → 得 `0x5500` 字节 → 放进 `0x5164` 的 param0（ID 0）→ 经 iAP2 会话发送。
依据：A03.1

**R-3.2** 在该 relay 事务路径中，检查会话存在且未关闭、`data` 对象指针非 NULL、`type < 3`、对应槽位已启用；不满足则不发。`0x100084e14` 的 `cbz x2` 是对象指针检查，不证明拒绝零长度对象。参考会话为避免无意义请求选择拒绝空 bytes，这是本地策略；零长度信封格式向量不证明对端会接受它。
依据：A03.1、A06.1

**R-3.3** 本构建发送后记录"最近命令 = `0x5164`"，可用于诊断；此字段本身不证明响应配对规则或并发窗口。
依据：A03.1、A01.2

## 3.2 接收分派

**R-3.4** 收到顶层中继消息必须按 msgID 分派：

| msgID | 处理 |
|---|---|
| `0x5264` | 取第一个参数（不是按 ID 搜索）→ 解信封 → 按内层 ID 分派（R-3.5）|
| `0x5265` | 中继失败：终止隧道，按 R-3.7 |
| `0x5266` | 中继成功：立即发 `0x5163` 拉下一条 |
| 其它 | 丢弃 + 记错 |

依据：A03.2、A03.3

**R-3.5** 内层消息 ID 分派：`0x5503` → 信息更新；`0x5501` → `type` 槽位投递；其它 → 丢弃 + 记错。
依据：A02.3、A03.2

**R-3.6** 本构建先校验 unpack 返回对象的长度大于 5（`0x100084694`–`0x1000846a0`）；对 `0x5501` 此对象是 param1 数据，对 `0x5503` 是整条内层消息。再检查 `type < 3` 且槽位非空。relay 层透传数据，不自行解码；最终 type=2 handler 另按 T56 校验。该长度门不等于所有业务的通用最短报文。
依据：A04.1、A04.2

## 3.3 成功 / 失败

**R-3.7** 收到 `0x5265` 必须视为**认证会话级失败**（对端固件把 AuthState 置 1）：停止隧道、清理槽位、不得继续重试 `0x5164`。
依据：A03.3、A06.2

**R-3.8** 收到 `0x5266` 后必须立刻发 `0x5163`（无参数），再等待下一条 `0x5264`。
依据：A03.3

## 3.4 停等与在途

**R-3.9** 参考实现采用保守停等策略：同一时刻只保留一条请求，未收到响应前不主动流水线发送。这不是已证明的对端协议限制；完整并发/超时机制仍待核实。
依据：A03.4

**R-3.10** 采用 R-3.9 策略时提供发送队列，按到达顺序逐条发出；队列容量、超时和取消由客户端定义，不冒充固件规定。
依据：A03.4、A07.3

## 3.5 空载荷与重读

**R-3.11** `0x5264` 的第一个参数缺失或其内层消息长度不足时，实现必须按“空载荷/格式错误”处理，不得当作零长度数据投递给 `type` 槽位；后续未知参数不应改变第一个参数的读取结果。
依据：A03.5

**R-3.12** 只有外层 `0x5264` 缺少首参数时，已读分支才依据 `MFi4RelayReadRetryDelayMs` 的布尔结果决定是否等 1 ms 后构造 `0x5163`；结果为零时返回失败。内层缺 param1、空参数值或短数据不适用此重读分支。参考实现默认关闭重读；可显式设置 `max_retry`，次数上限为本地策略（`OPEN-TUN-6`）。启用后调用 `tick()` 处理到期任务，不在接收回调里立即发送。
依据：A03.5

## 3.6 能力协商

**R-3.13** 解析 `0x5503` 的 `0xF2` 后，能力调度在 `auth+0x58 == 0`、本次掩码非零且不同于已处理掩码时执行。已处理掩码是动作历史：只 OR 入实际执行动作的位，不能每次用新掩码覆盖。参考 `on_capabilities(mask, action_pending=...)` 要求调用方提供闸门状态，不自行推断完成时机：

| 变化 | 动作 |
|---|---|
| bit0 由 0→1（优先分支） | 发 `0x5502` 请求一次信息更新；同一次固件调用不再落入 bit2 分支 |
| bit0 未在本次调用新置位，且 bit2 由 0→1 | 启动 `type=2` 的槽位 |
| 其它位 | 记录但不解释（`OPEN-TUN-3`）|

依据：A03.6、A04.3；分支优先级见 `analysis/03` §3.6

**R-3.14** 不得因未知位而拒绝消息或中止隧道。
依据：A03.6

**R-3.15** 首次 `0x5502` 的启动条件仍为 `OPEN-TUN-7`。没有目标 profile 或运行证据时不得声称“主动发不会破坏对端”；按已确认协商门控推进，额外主动查询只可用于明确授权的实验。
依据：A03.6

## 3.7 与其它分发的顺序

**R-3.16** 中继只能作为消息分发的**末端兜底**：先尝试常规 iAP2 消息处理、再尝试扩展处理，两者都未命中才交给中继。实现不得在中继里处理 `0x5264/0x5265/0x5266` 之外的 msgID。
依据：A09.1
