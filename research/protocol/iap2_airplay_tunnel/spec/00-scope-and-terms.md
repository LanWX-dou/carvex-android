# spec/00 — 范围、术语与方向声明

## 0.1 范围

**R-0.1** 本规范描述设备侧（模拟 iPhone）在 iAP2 链路上实现"隧道中继"所必需的行为：中继请求 `0x5163/0x5164`、信封 `0x5500/0x5501/0x5502/0x5503`、`type` 分派、能力协商、错误与拆除。
依据：A01.1、A01.3、A03.2

**R-0.2** 本规范**不**描述：iAP2 链路层（见 `link/`）、iAP2 消息层基础帧（见 `control/`）、AirPlay 控制面（RTSP/Pair-Setup）、媒体编解码与 RTP 时序。
依据：A05.4

## 0.2 方向声明（必须遵守）

**R-0.3** 本规范的方向是 **iAP2-over-AirPlay**（AirPlay 作为 iAP2 的传输）与 **iAP2-over-iAP2**（中继信封）。**不是** "AirPlay 媒体字节装进 iAP2 消息"。任何实现都不得假设存在"把 RTSP/RTP 载荷塞进 `0x55xx`"的封装。
依据：A05.1、A05.4、A01.1

**R-0.4** 若某实现观测到对端确实把媒体字节塞进 iAP2 消息，必须先补齐抓包并更新 `OPEN-TUN-5`，再据此扩展本规范；不得直接按该假设编码。
依据：A05.4

## 0.3 术语

| 术语 | 含义 |
|---|---|
| **信封** | `0x5500`/`0x5501` 消息，携带 `type` 与一块数据 |
| **中继消息** | `0x5163/0x5164/0x5264/0x5265/0x5266`，外层承载信封 |
| **type** | 信封 param0 的 u8 值，0–2 |
| **capabilities 掩码** | `0x5503` 的 param `0xF2`（u64），位含义见 R-3.6 |
| **停等** | 一次只有一条中继请求在途 |
| **ACK 帧** | 链路层 `ctl=0x40`、`len=9`、无载荷的帧（`link/R-2.x`）|

**R-0.5** 本文中"必须/不得"为强制项；"建议"为实现自由；"OPEN"为无证据项，不得当作已确认行为。
依据：A06.1

## 0.4 与其它 docset 的引用

**R-0.6** 引用其它 docset 一律写 `link/R-x.y` 或 `control/R-x.y`，不得复制其条款正文；冲突时以本 docset 的 `analysis/` 证据为准并在 `analysis/06` §6.5 记录。
依据：A07.2
