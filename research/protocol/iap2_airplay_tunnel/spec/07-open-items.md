# spec/07 — 未决项登记与处置

**R-7.1** 本规范中任何"未证明"的行为都必须以下列 `OPEN-TUN-*` 编号出现；实现遇到未登记的行为差异时，必须先补登记再改代码。
依据：A06.1

**R-7.2** `OPEN` 项不得被写成"已知行为"，也不得在测试向量里被断言为固定值。
依据：A05.4

## 7.1 登记表

| 编号 | 内容 | 影响 | 处置 |
|---|---|---|---|
| `OPEN-TUN-1` | 车机收到 `0x5500` 的解析 | 只能按对称假设 | 按 `0x5501` 同构实现，记一次告警 |
| `OPEN-TUN-2` | `type` 0/1 语义与启动条件 | L3 无法声称 | 固件已收窄：合法 type∈{0,1,2}，`2`=T56（A09.2）；0/1 语义仍未知 → `EXP-1` |
| `OPEN-TUN-3` | 能力位 bit1 及保留位 | 协商只处理 bit0/bit2 | 已收窄：合法 type 上界为 2，bit1 无对应槽位（A09.2）；位图语义 → `EXP-3` |
| `OPEN-TUN-4` | 中继是否仅 AirPlay 启用 | 传输选择 | 已收窄：中继是分发末端兜底、无传输分支（A09.1）；实际启用点 → `EXP-4` |
| `OPEN-TUN-5` | AirPlay 隧道帧/MTU/握手 | L4 无法声称 | `EXP-2` + AirPlay 侧文档 |
| `OPEN-TUN-6` | `0x5163` 重试上限/超时及完整并发闸门 | 停等与次数为保守策略，不是已证协议约束 | 核实上层调度；仅外层无首参数分支有条件延时 1 ms 重读 |
| `OPEN-TUN-7` | 首次 `0x5502` 时机 | 交互顺序 | 遵循已证门控，补目标 profile/运行证据，不默认主动查询安全 |
| `OPEN-TUN-8` | handler 对象身份与 `[slot+0x10]` | 不影响线格式 | **已关闭**（A09.4）：provider 是 ObjC block，`[+0x10]`=invoke、`[+0x18]`=descriptor |
| `OPEN-TUN-9` | 对端是否只发一个 param1 | 互操作 | 本侧 last-wins |
| `OPEN-TUN-10` | 是否有 MFi4 SecureTunnel 加解密 | 安全边界 | **已推进**（A09.5/A09.6）：条件式载荷加密、`ccsigma` AEAD、长度 +16；算法参数/KEX 细节仍未证 |
| `OPEN-TUN-11` | 隧道数据绑定哪条链路 | 多链路场景 | 已收窄：每连接 protocolRouter（`+0x38`）→ 连接级（A09.7）；选择点不在本镜像 → `EXP-4` |
| `OPEN-TUN-12` | 无 24A446 AirPlay 样本 | 运行期结论只到 23G90 | 补抓包 |

### 7.2 2026-10-26 定向取证进展

本轮用固件字节关闭/收窄了 6 项（详见 `analysis/09` 与 A09.1–A09.7）：

| OPEN | 结果 | 关键地址 |
|---|---|---|
| `OPEN-TUN-2` | 收窄（type∈{0,1,2}，2=T56）| `0x1000a9bc8` |
| `OPEN-TUN-3` | 收窄（上界 2）| `0x1000a9bf8` |
| `OPEN-TUN-4` | 收窄（分发兜底）| `0x1000feef0` |
| `OPEN-TUN-8` | **关闭**（block invoke）| `0x1000a8ae4`、`0x1000a9bc8` |
| `OPEN-TUN-10` | 推进（ccsigma AEAD、+16）| `0x1001327d0`、`0x100132acc` |
| `OPEN-TUN-11` | 收窄（连接级 router）| `0x10017a64c` |

剩下 6 项（1/5/6/7/9/12）里，1、9 属于对端行为，12 属于运行期样本；5 需跨镜像追踪；6、7 仍可继续核实上层调度及真实交互，不能简单用“实现自由”代替补证。

**R-7.3** 每个 `OPEN` 必须至少被一条 `spec/` 条款或 `analysis/` 结论引用；只登记不引用视为遗漏。
依据：A06.1

**R-7.4** `OPEN` 关闭时必须写明"由哪条证据关闭"，并保留原编号（不复用、不删除）。
依据：A05.4
