# spec 08 错误处理、降级与 OPEN 引用

## R-8.1 错误码速查（客户端调试第一张表）

| 码 | 触发点 | 排查动作 |
|---|---|---|
| `0xfffee704` / `0xffffe5cf` | 进入相应Bad ET分支 | 区分请求头`X-Apple-ET`与字典`et`；getter错误/et=1另有路径（A-38/A-39） |
| `0xffffe5a9` | key/iv 长度不是 16 | 检查 ekey 是否被 FairPlay 正确解出；eiv 是否被误加密 |
| `0xffffe59e` | FairPlay 上下文为空 | 是否漏了 `/fp-setup` 或提前发 `/setup` |
| `0xfffee703` | FP 核心处理失败 | 载荷被截断/长度错；或上下文状态错 |
| `0xfffee702` | 响应构造失败 | 服务端资源问题 |
| `0xfffee706` | ACL 拒绝 | 连接来源不被允许（配对/权限） |
| `0xfffee786` | 状态字节非法 | FP 载荷不是核心产出的原始字节 |
| `0xfffee785` / `0xfffee788` | 密钥封装失败 | 入参不是 16 字节，或上下文为空 |
| `0xfffee7e1` | 加密器参数非法 | ChaCha key < 32；CBC/CTR key 或 iv 为 NULL |
| `0xfffee76f` | 未知流类型码 | 对照 R-5.1 |
| `0xfffee645` | 状态不允许设置安全信息 | 时序错（重复设置/太晚） |
| `0xfffee647` | ChaCha key 不是 32 字节 | 对照 R-7.6 |
| `0xffffe596` | 解密输出长度不匹配 / AES 安全信息设置失败映射；tag 错误另由库返回 | 检查具体调用点；不可由此码唯一判断 AAD 或 nonce 错误 |
| `0xffffce12` | vtable 方法缺失 | 对象类型错（不是该协议的流对象） |

依据：A-25。级别：A（码值）/ B（排查动作是经验映射）。

## R-8.2 降级策略（明确允许与不允许）

允许：

- 本构建分派对类型0x78/0x82留下NULL出参，并未在该路径调用 `APSCryptorGetNull`；这只说明本处未创建对象，是否代表目标profile的明文/外层保护仍须另证（R-5.5）。
- 只有在端点能力属性 `G=0` 且类型为 `0x6e`/`0x6f` 时，本分派才建立CTR；不能把ET值直接等同于G，也不能把ChaCha失败后自动切换CTR当作通用降级。

不允许：

- 用明文冒充加密成功（会误导后续排障）。
- 在 tag 失败后继续推进 nonce（会让此后每一帧都错）。
- 把「某条流能解」推广成「所有流可用」。
依据：A-19、A-23。级别：A。

## R-8.3 `OPEN-n` 的引用规则

- 对尚未关闭的OPEN不得给出无证确定值；已部分证明的内容与剩余未知需分开。历史关闭项可引用，但须标状态与证据。
- 每条 `OPEN-n` 必须能在 `analysis/08-open-items.md` 找到登记，且写明「需要什么才能关掉」。
- 关掉一条 OPEN 时，必须同时改：`analysis/08`、引用它的 `spec/` 条目、`STATUS.md` 计数。
依据：A-27。级别：A（纪律条目）。

## R-8.4 禁止的表述（对应 TASK §6 A6）

不得在本文档体系内出现下列表述：

```
全部确认
所有版本可用
所有流都能解
所有流都可用
```

也不得：把构造向量称为「抓包」；对 `OPEN-1` 的算法给出伪代码级实现细节（会误导读者以为可自研）。

`verify.py` C8 用词表扫描 `analysis/`、`spec/` 与本文件，命中即失败。
依据：TASK §6、A-30。级别：A。

## R-8.5 客户端自检清单（交付前逐条过）

1. `/fp-setup` 走的是流消息 `"fp25"`，载荷是核心原始输出（R-1.1、R-1.2）。
2. 循环以 `state` 结束，不是固定轮数（R-1.3）。
3. 区分`X-Apple-ET`请求头与`et`安全信息键；按已核profile构造ekey/eiv，不假定所有流都必填（R-1.4/R-1.5）。
4. `masterKey`/`masterIV` 是两次独立随机（R-3.1）。
5. 派生名字符串与索引格式一字不差（R-4.2）。
6. ChaCha key 是 32 字节且来自正确来源（R-5.2、R-4.6）。
7. 每个加密段tag在尾部，验签及长度检查成功后nonce+1；一条屏幕记录可有两段，AAD为原始128B头（R-7.1–R-7.8）。
8. 记录原始错误与来源，不把未知网络/库错误硬映射为表内某个OSStatus。
依据：本文件全部规则。级别：A。
