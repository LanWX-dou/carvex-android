# spec 00 范围、术语与证据级别

## R-0.1 本规范覆盖什么

本规范只规定「FairPlay 交换的外围 + 密钥材料 + 派生 + 逐帧加密」四段。**不**规定：

- FairPlay SAP 算法内部（`OPEN-1`）；
- MFi 认证协处理器的电气/固件接口；
- 媒体编码、RTP 时基、CarPlay 应用层。
依据：A-07、A-28、A-30。

## R-0.2 三层划分（每条规则都属于且只属于一层）

| 层 | 定义 | 本规范处理 |
|---|---|---|
| L1 | 当前未实现的FP核心/硬件信息接口 | 描述已证接口与缺口；确认目标profile所需合法实现，不编造算法或凭证 |
| L2 | 消息编排与字段语义 | 规定已证路径，完整schema/profile与真实交互仍有缺口 |
| L3 | 密钥派生与帧加密 | 已核KDF、AES局部规则与ChaCha边界；不宣称所有流完整闭合 |

依据：A-08、A-10、A-23。

## R-0.3 证据级别标注（每条规则末尾必带）

- **A 级**：限定函数/路径的汇编与原字节证据，必要时结合已核外部API契约；不能自动推广为完整互操作实现。
- **B 级**：函数体清楚但依赖第三方库语义（例如 CoreUtils 的 CBCFrame），实现需自行对齐。
- **C 级**：只有调用点/符号，只能定方向，需抓包或补充取证。

依据：A-32。

## R-0.4 版本边界

所有常量、码表、错误码**仅对 24A446（iOS 27.0.1 / iPhone 18,1）成立**。
换版本必须重新取证，不得假定兼容。
依据：A-01、`OPEN-14`。

## R-0.5 `OPEN-n` 的使用纪律

未决OPEN不得填写无证确定值；可通过继续静态取证或受控运行验证闭合。部分已证与剩余未知须分开。
关闭后保留历史编号并标CLOSED和依据。所有编号在analysis/08登记。
依据：A-27。

## R-0.6 术语

| 术语 | 含义 |
|---|---|
| master key / master IV | 本机随机生成的 16 字节密钥材料（A-11） |
| ekey | master key 经 FairPlay 加密后的字节串（长度不固定） |
| eiv | master IV 的**明文**（16 字节） |
| KDF整数 `i` | 传给Legacy/Screen派生入口、按无符号64位十进制格式化进KDF名字的整数；其线上字段/是否为流序号仍见 `OPEN-15`（A-17、A-46） |
| 屏幕记录/加密段 | 已核接收路径记录=128B头+body；body可含两个独立加密段，不与TCP分片或RTP消息混同 |

依据：A-11、A-12、A-17。
