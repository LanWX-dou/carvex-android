# FairPlay 密钥与加密流程 — 任务要求（`airplay_fairplay_crypto`）

> **历史任务书**：本文件是上游任务书，现行版本以 `research/protocol/airplay_fairplay_crypto/TASK.md` 为准；本文件保留用于追溯，不再单独修订。


> 本文件是**任务书**，不是协议规范。
> 目标：给出 AirPlay 媒体帧的 FairPlay 密钥交换与加密规范：证书交换、SK 派生、帧 AES、校验标签、密钥刷新、密钥失效处理。
>
> 口径：`CONFIRMED` 只表示“在本阶段证据范围内可复核”；密码学结论必须区分“协议字段”“密钥派生”“算法实现”三层，不能混写。

---

## 0. 阶段定位

```text
AirPlay 控制面（airplay_control_plane）
  └─ RTSP SETUP 协商出媒体流/密钥参数
        ↓
【本阶段】FairPlay 密钥与帧加密
  ├─ 证书交换
  ├─ SK 派生
  ├─ 帧 AES 加密/解密
  ├─ 校验标签
  └─ 密钥刷新 / 失效
        ↓
RTP 时序、视频/音频解码（后续阶段）
```

本阶段只回答：

- 双方交换什么证书/公钥；
- SK 如何从交换结果派生；
- 每个媒体帧如何加密、如何校验；
- 密钥何时刷新、何时失效、失败如何处置。

**不回答**：RTSP 控制面、RTP 抖动缓冲、H.264/AAC 解码、iAP2 隧道分片、内容 DRM 授权。

---

## 1. 目标与完成判据

**目标**：产出可复现的 FairPlay 媒体帧加密规范，使第三方客户端能：

1. 完成证书/密钥交换；
2. 派生 SK；
3. 正确解密车机→设备的媒体帧；
4. 正确加密设备→车机的媒体帧（如适用）；
5. 校验标签、处理密钥刷新与失效；
6. 明确失败分支与不可实现部分。

**完成判据**：

1. 12 项覆盖要求逐项有证据或 `OPEN`；
2. 至少一组真实抓包的“密钥交换 + 加密帧 + 解密结果”闭环；
3. 有独立测试向量：输入帧、密钥、IV、输出密文、标签；
4. 有负向测试：错密钥、错 IV、篡改标签、过期密钥；
5. `verify.py` 可重放；
6. 不把“能解密一条帧”写成“所有流/所有版本可用”。

## 2. 素材与证据来源

| 素材 | 要求 |
|---|---|
| 控制面抓包 | `SETUP` 中的密钥/证书参数 |
| 媒体抓包 | 加密帧、标签、序号、时间戳 |
| 密钥交换样本 | 首次连接、重连、密钥刷新前后 |
| 明文字样 | 如可得，用已知测试图案/静音帧做对照 |
| 参考 | AirPlay/FairPlay 公开资料、密码学标准；只作对照 |
| 实现 | 目标平台密码库（AES、SHA、HMAC 等） |

---

## 3. 方法与证据链

1. **字段级**：从 RTSP/SETUP 和 FairPlay 消息中提取证书、公钥、盐、SK 标识；
2. **密钥级**：记录 SK 派生输入/输出，不把猜测的 KDF 写成结论；
3. **帧级**：对同一帧记录 `seq`、时间戳、IV、密文、标签、解密后明文；
4. **算法级**：AES 模式、填充、IV 构造、标签覆盖范围必须有测试向量；
5. **生命周期**：密钥刷新/失效的触发条件、旧密钥保留窗口；
6. **负向测试**：错密钥/错 IV/篡改/重放/过期；
7. **结论分级**：`CONFIRMED` / `INFERRED` / `OPEN`。

**禁止**：

- 把 FairPlay 传输加密与内容 DRM 混为一谈；
- 只凭一条帧推出全局密钥规则；
- 把“解密成功”当成“密钥交换协议正确”；
- 在文档中记录真实密钥/证书私钥。

---

## 4. 抽样策略

至少覆盖：

1. 首次密钥交换；
2. 重连后的密钥复用/重新交换；
3. 密钥刷新：刷新前、刷新中、刷新后各至少一帧；
4. 密钥失效：旧密钥解密失败、新密钥生效；
5. 视频帧、音频帧各至少一种（如可得）；
6. 错密钥/篡改标签的负向样本。

## 5. 覆盖要求（12 项）

| # | 要求 | 必须回答的问题 |
|---|---|---|
| 1 | **证书交换** | 谁发证书？证书格式、链、用途、有效期？是否验证？ |
| 2 | **密钥交换消息** | 消息顺序、字段、编码、请求/响应、失败响应？ |
| 3 | **SK 派生** | 输入是什么？KDF/哈希？输出长度？SK 标识？ |
| 4 | **AES 模式** | AES-CBC/CTR/GCM？填充？IV 如何构造？ |
| 5 | **帧加密边界** | 加密覆盖帧头还是仅载荷？标签覆盖哪些字节？ |
| 6 | **校验标签** | 标签算法、长度、截断、比较方式？ |
| 7 | **每帧参数** | `seq`/时间戳/IV 如何变化？是否允许重复？ |
| 8 | **密钥刷新** | 何时刷新？刷新消息、旧密钥保留多久？ |
| 9 | **密钥失效** | 过期/失败/断连后如何处理？是否重协商？ |
| 10 | **错误与降级** | 解密失败、标签失败、密钥不匹配如何分类？ |
| 11 | **安全边界** | 中间人、重放、降级、密钥泄露的处理？ |
| 12 | **版本与差异** | AirPlay 1/2、视频/音频、不同车机的差异？ |

### 5.1 重点专题

#### A. 证书交换

- 证书是 X.509 还是其他容器？
- 是否包含叶证书 + 中间 CA？
- 证书公钥算法、曲线、用途；
- 客户端是否必须验证车机证书？失败是否中止？
- 证书与配对身份的关系。

#### B. SK 派生

必须给出：

```text
输入：证书/公钥/盐/随机数/会话参数
  ↓ KDF（待证）
输出：SK（长度、用途、标识）
```

未证实的 KDF 只能写 `INFERRED`，并给出验证方法；不得直接写“就是某算法”。

#### C. 帧 AES

必须给出：

- 加密范围：帧头/载荷/尾部；
- IV 构造：序号、时间戳、随机数、固定字段；
- 模式与填充；
- 标签计算范围与存放位置；
- 解密后的完整性检查顺序。

#### D. 密钥刷新与失效

必须给出状态机：

```text
KEY_ACTIVE → KEY_REFRESHING → KEY_ACTIVE(new)
                    └→ KEY_EXPIRED → 重协商/断开
```

包括刷新触发、旧密钥窗口、丢帧处理、失败回退。

## 7. 非目标

- 内容 DRM/播放授权；
- RTSP 控制面（`airplay_control_plane`）；
- RTP 时序（`airplay_rtp_timing`）；
- 视频/音频解码；
- iAP2 隧道分片；
- 真实密钥/证书私钥的保存或分发。

---

## 8. 已知风险与待决

| 风险/待决 | 影响 |
|---|---|
| KDF/算法未证 | 不能实现兼容解密 |
| 证书验证策略不清 | 可能接受伪造车机 |
| 密钥刷新窗口不清 | 刷新时丢帧/花屏 |
| 多流共用/独立 SK 不清 | 解密错流 |
| 版本差异 | AirPlay 1/2 可能不同 |
| 真实密钥泄露 | 严禁写入文档/仓库 |
