# runtime/ — 运行时证据

本目录只放**可核验的运行时样本**（或其派生的证据说明），不放推测。

## 现有样本

| 文件 | 内容 | 构建 | 用途 |
|---|---|---|---|
| `accessoryd-packets-2026-10-16-221117.log.ips` | accessoryd 逐帧包日志（蓝牙经典 + AirPlay 两次连接）| 23G90 | 会话号、识别/认证顺序的实测依据 |
| `23G90-bt-classic-2026-10-16.md` | 上面这份日志的身份、逐帧时间线、能证明/不能证明什么 | — | 引用入口 |

sha256（日志本体）：

```
7283f8a1d50c6c920198587f816c86aec996b7d749e84be7db771f5a7595dadd
```

`manifest.json` 已把该文件纳入哈希清单，`verify.py` 的 C1 类会在文件被改动时失败。

## 证据强度

- 这份日志是**别的构建**（23G90）产生的，目标镜像 24A446 **没有**对应的运行时样本。因此凡是引用它的结论，正文都标 `23G90`，并在 `A-conclusions.md` 里写明"23G90 行为佐证，非 24A446"。
- 它能证明的是**协议行为**（谁先发、带什么会话号），不能证明**代码实现**（哪条指令写的表）。

## 未决

- `OPEN-RUNTIME-1`：仍缺 **24A446** 同构建的运行时样本。补齐方式：用目标构建的设备抓一次连接，取同一路径下的 `accessoryd-packets-*.ips`，放进本目录并登记 sha256。
- 本目录树下另有两份 sysdiagnose（22H374、21G93），不含 accessoryd 包日志；其 `logs/Bluetooth/*.pklg` 是 HCI 层抓包，本阶段未使用。

## 使用规则

1. 引用运行时证据必须写明**构建号**与**文件路径**，不得写成"实测设备如此"。
2. 运行时证据不能单独支撑一条 `CONFIRMED` 条款；它只能与静态证据并列，或在静态证据缺失时标为"行为佐证"。
3. 任何从运行时样本推断出的语义（例如"这 32 字节是序列号"）必须在正文标明是推断，不得进入 `spec/` 的 `MUST` 条款。
