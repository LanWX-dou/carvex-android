# spec/12 — 客户端实现等级（L0–L4）

本文件给本项目的**建议验收层级**，不是 Apple 官方一致性规范。识别优先的样本流程可按 L0–L4 排查；认证优先 profile 的顺序需单独描述，不能用本表否定它。L4 只是启动交接，完整客户端还需网络/媒体/输入端到端验收。

## 11.1 等级定义与通过判据

`R-11.1`（MUST / CONFIRMED）下表每一级的"通过判据"必须可被第三方用**抓包 + 日志**独立复核，不接受"看起来通了"。

| 等级 | 名称 | 前置 | 通过判据（全部满足）| 依据 |
|---|---|---|---|---|
| **L0** | 链路 | RFCOMM 已连接 | 成功完成所选 profile 的 SYN/SYNACK/ACK，校验和、序号、协商参数正确；建议观察 60 s 无重传耗尽。`ctrl=0xee` 是样本观察，不作为所有车机的必选前序 | `link/R-6.9`、`A05.9` |
| **L1** | 识别 | L0 | 发出 `0x1d00`（`hdr[7]` 与握手确认的控制条目一致）；按适用 profile 校验 `0x1d01` 的类型、长度与必需内容，再发 `0x1d02`；不能仅检查 ID 上限就接受 | `A05.9`、`A03.8` |
| **L2** | 认证 | L1（本 profile） | 完成适用交换，依据经确认的信任锚/证书策略验链并验签，再发成功；样本只验证签名，不证明根信任。后续业务是进展证据，不是验签证据 | `A05.10`、`R-10.2` |
| **L3** | 会话 | 适用识别/认证流程 | 会话号路由、能力名单、收发重组/背压及异常路径通过测试。`0x5702/03`、`0x4e0d/0e` 仅在对端宣告支持且该 profile 需要时测试，不是所有 CarPlay 连接的必经步骤；不强制复制 iOS 的 5 队列 | `A02.5`、`A07.1`、`A08.5` |
| **L4** | CarPlay 启动交接 | 已验证的适用前置流程 | 收到 `0x4301`、按 [spec/14] 的已证实 schema 解码并完成平台交接；平台必填性、错误/重试与后续网络/媒体/输入仍需实机证据。不得要求全部 14 字段非空，调用/返回日志不能单独证明媒体会话可用 | `A05.7`、`A05.11`、`A05.12`、`A05.15` |

依据：`A05.9`、`A05.10`、`A02.5`、`A07.1`、`A08.5`、`A05.7`、`A05.11`、`A05.12`。

## 11.2 等级之间不允许跳

`R-11.2`（SHOULD / INFERRED）作为项目验收策略，分别记录链路、识别、认证及启动交接的证据，不能用收到 `0x4301` 代替前置验证。`analysis/07` 证明的是 **iPhone 端入站处理门控**，不是车机实现；车机发出消息不等于本端接受，更不证明所有 L3 示例消息必经。前置条件未验证时，不能把启动失败单独归因于字段映射。

依据：`A07.1`、`A07.4`、`A07.8`。

## 11.3 L2 的判据为什么可以观测

`R-11.3`（SHOULD / INFERRED）抓包能证明报文顺序，不能单独证明客户端确实完成了证书链验证和验签。L2 应有验证结果与本次会话绑定的证据。样本中的 `0x5702/0x4e0d/0x4e0e` 是 **iPhone→车机**，不是车机回包。10 s 无入站数据最多标为“无后续进展”（可配置的实验超时），不能直接等同于密码学认证失败。

依据：`A05.10`。

## 11.4 L4 的判据依赖运行时交接证据

`R-11.4`（未定义 / OPEN）`0x4301` 的静态 `param_id→field` 映射已经由 `spec/14` 给出；L4 仍依赖运行时平台必填性、错误响应、网络建立和后续 CarPlay 数据面的证据（`OPEN-SES-2`）。在这些证据没补齐之前：

- 可以验收“按静态 schema 解码”，但不能把本端平台调用或 handler 返回 1 当作车机接受；
- 实现方必须把平台必填性、错误/重试、Wi-Fi/IP、控制、媒体、时钟和输入单列为已知风险，并在交付说明里写明。

依据：`A05.15`、`A05.16`、`A05.17`。

## 11.5 每级的自查方式

`R-11.5`（MUST / 建议）每级必须有对应的自动化检查，且检查只读取"抓包 + 日志"，不依赖人工判断：

| 等级 | 自查方式 |
|---|---|
| L0 | 解析抓包：SYN/SYNACK/ACK 三帧齐全，且 SYNACK 的 ctrl 为 `0xc0` |
| L1 | 解析抓包：出现 `40 40 00 06 1d 00` 与 `40 40 00 06 1d 02`，且两者之间出现 `… 1d 01 …`；两次消息的 `hdr[7]` 相同且非 0 |
| L2 | 解析抓包：七步认证序列齐全（含两次 `0xAA00`）；日志里有一条"证书链校验通过"与一条"验签通过" |
| L3 | 解析抓包：`57 02` 发出后收到 `57 03`；未知 ID 的日志锚点至少出现一次（可用构造帧触发）|
| L4 | 解析完整 `0x4301` 消息并验证 schema/平台交接及后续网络/会话结果；日志只记录字段存在性、类型与脱敏诊断，不打印 Wi-Fi 密码或认证敏感材料 |

依据：`A05.9`、`A05.10`、`A08.5`、`A05.11`。

## 11.6 等级之外的"不能声称"

`R-11.6`（未定义 / OPEN）即使 L4 全过，也不得声称下列事项：

1. **24A446 行为一致**：L0–L4 的时序证据来自 23G90（`OPEN-RUNTIME-1`）；
2. **通用于所有车机**：所有观测来自一台 CFMOTO 车机，参数集合可能不同；
3. **双向认证可用**：没有样本（`OPEN-SES-31`）；
4. **会话号规则**：只有 2 个样本（`OPEN-SES-1`）。

依据：`A02.13`、`A05.10`、`A05.15`、`A05.17`。
