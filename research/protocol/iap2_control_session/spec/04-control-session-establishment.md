# spec/04 — 控制会话的建立

## 4.1 初始化

`R-4.1`（MUST / CONFIRMED）控制通道缓冲是 `65535` 字节，且分配是**幂等**的：已分配则复用，不重复分配。

依据：`A05.1`。

`R-4.2`（MUST / CONFIRMED）初始化必须完成三件事，顺序固定：注册消息处理器 → 注册识别参数处理器 → 创建特性。初始化**不得**触碰会话表，也不得发出任何报文。

依据：`A05.2`、`A06.2`。

`R-4.3`（MUST / CONFIRMED）65535 这个数值与单条消息上限一致（`R-3.4`）。实现必须保证缓冲 ≥ 最大消息长，否则一次最大消息就溢出。

依据：`A05.1`、`A03.5`。

## 4.2 版本：来自会话表的一个字节

`R-4.4`（MUST / CONFIRMED）控制会话的"版本"不是协商结果，而是会话表项 `[2]` 的值：

```
版本 = (按类型 0 查到的会话表项)[2]
若查不到表项 → 版本 = 0
```

依据：`A05.3`、`A05.4`、`A02.7`。

`R-4.5`（MUST / CONFIRMED）**版本决定先跑哪套安全流程**：

| 版本 | 先跑的流程 | 传给启动函数的参数 |
|---|---|---|
| `== 2` | 识别（Identification） | `1` |
| `!= 2`（含 0） | 认证（Authentication） | `0` |

两条分支调用同一个"从设备启动特性"的函数，唯一差别是这个参数。实现必须**按版本分岔**，不能固定走一条。

依据：`A05.5`、`A05.6`。

`R-4.6`（MUST / CONFIRMED）由于缺表时版本为 0，**默认行为是"认证优先"**。"识别优先"（版本 2）是需要显式配置的特例，不是默认。

依据：`A05.4`、`A05.5`。

## 4.3 建特性时的奇偶门控

`R-4.7`（MUST / CONFIRMED）创建单个特性时：**奇数特性号跳过识别门控**；偶数特性号必须先通过"该特性已识别"的检查。特性槽按特性号索引，槽位数组长度 29。

依据：`A06.3`、`A06.4`。

`R-4.8`（MUST / CONFIRMED）"已创建"的重复请求不得重复创建，只能记录日志；槽位非空即视为已创建。

依据：`A06.3`。

## 4.4 会话启动消息

`R-4.9`（MUST / CONFIRMED）消息 `0x4301` 是 CarPlay 会话启动消息，由特性 26 的处理器表承载，最终转换为一次平台层"启动会话"调用，参数清单（按固件日志串）为：

```
usbIP, wifiIP, ssid, pass, securityType, channel, port,
deviceID, pubKey, srcVer, sdkVer, assetID, assetVer, mutualAuth
```

依据：`A05.7`、`A05.15`。

`R-4.10`（MUST / CONFIRMED）`0x4301` 的参数 ID → 字段映射按两级嵌套路径实现：外层 `0/1/2/3/4/5/6/7/8`，外层 1 的子 ID `0…4`，外层 7 的子 ID `0…1`；端口和 assetVer 是大端 U32，securityType/channel 是 U8，字符串值必须 NUL 结尾。完整 schema 见 [spec/14](<14-carplay-start-schema.md>)。

依据：`A05.11`、`A05.14`、`A05.15`。

`R-4.12`（MUST / CONFIRMED）`0x4301` 的方向是**入站**（车机 → 设备），已由处理器注册表确认：`0x4301` 唯一映射到 `_iap2_CarPlayStartSession`（`0x10016d3ac`，特性 26 的处理器表 `0x10021e650`），而该表只服务于入站分发。客户端**不需要发送** `0x4301`。

依据：`A05.7`、`A05.11`。

`R-4.13`（MUST / OPEN）解析成功或 handler 返回 1 只代表本端解析/平台交接路径被调用，不代表车机接受或 CarPlay 已建立。字段必填性、错误响应、Wi-Fi/IP、控制、媒体和输入的下游结果必须单独验收（`OPEN-SES-2`）。

依据：`A05.15`、`A05.16`、`A05.17`。

## 4.5 未决

`R-4.11`（未定义 / OPEN）`createFeatures` 的调用点前存在被编译器折叠的片段，**传入的特性号是否为常量**未定。实现应显式传入特性号，不要依赖调用序。

依据：`A06.5`。
