# spec/14 — `0x4301` CarPlay 启动参数 schema

本章面向**设备侧客户端**：车机发送 `0x4301`，客户端解析并据此启动后续 CarPlay 网络/会话。它不是“客户端发送 0x4301”的指南。参数映射来自 24A446 `accessoryd` 的两级跳表和 getter 原始汇编；运行时接收、平台字段必填性和完整 CarPlay 交接仍需实机验证。

## 14.1 消息与遍历

`R-13.1`（MUST / CONFIRMED）消息头必须是标准 iAP2 消息头，消息 ID 为 `0x4301`；handler 从顶层组 `0` 开始遍历参数。外层 ID `0`、`1`、`7` 是嵌套参数组，不能把 14 个字段当作平面 ID `0…13`。

依据：`A05.7`、`A05.11`、`A05.15`。

`R-13.2`（MUST / CONFIRMED）嵌套组的子参数以同一 TLV 规则编码：`len(2B, BE) | id(2B, BE) | value`。外层 1 的子 ID 是 `0…4`；外层 7 的子 ID 是 `0…1`。未识别的外层或子 ID 记录诊断并继续，不得把未知字段重解释为相邻已知字段。

依据：`A04.1`、`A04.4`、`A05.11`、`A05.15`。

## 14.2 字段 schema

`R-13.3`（MUST / CONFIRMED）按下表解码。`string` 是**值区以 NUL 结尾的 UTF-8 C 字符串**；长度包括 4 字节参数头和末尾 `0x00`。`U32` 为大端；`U8` 为单字节；`Bool` 只能是 `0x00` 或 `0x01`。

| 路径 | 字段 | 类型/重复性 | 语义备注 |
|---|---|---|---|
| `0 / 0` | `usbIP` | `string[]`，可重复 | 每次出现追加数组 |
| `1 / 3` | `wifiIP` | `string[]`，可重复 | 每次出现追加数组 |
| `1 / 0` | `ssid` | `string` | Wi-Fi SSID |
| `1 / 1` | `pass` | `string` | Wi-Fi 口令；日志必须脱敏 |
| `1 / 4` | `securityType` | `U8` | handler 后续以宽 CFNumber 保存；线宽仍是 1 |
| `1 / 2` | `channel` | `U8` | 线宽不是 U16 |
| `2` | `port` | `U32` | 线宽是 4，大端；不要按 U16 解码 |
| `3` | `deviceID` | `string` | 设备/连接标识，具体格式未规定 |
| `4` | `pubKey` | `string` | 公钥元数据；具体编码不能由字段名推断 |
| `5` | `srcVer` | `string` | 源版本 |
| `6` | `sdkVer` | `string` | SDK 版本 |
| `7 / 0` | `assetID` | `string` | cluster asset 标识 |
| `7 / 1` | `assetVer` | `U32` | 大端 |
| `8` | `mutualAuth` | `Bool` | 恰好一个字节，0/1 |

依据：`A05.11`、`A05.12`、`A05.15`。

## 14.3 getter 合法性

`R-13.4`（MUST / CONFIRMED）实现必须按 getter 的长度/值检查拒绝畸形字段：U32 总长必须为 8，U8/Bool 总长必须为 5，字符串总长至少为 5 且最后一个值字节必须为 `0x00`；Bool 值大于 1 不是合法 Bool。

依据：`A05.15`；原始 helper `0x100067df0`、`0x100067e4c`、`0x100067e74`、`0x100067ee4`。

`R-13.5`（SHOULD / INFERRED）字符串转换按 UTF-8 处理，并把嵌入 NUL 后的内容视为 C 字符串截断风险；不要把 `pubKey` 当作二进制 DER，除非另有字段/实验明确证明。

依据：`A05.15`（`CFStringCreateWithCString` 的 UTF-8 参数）；编码形式仍属于 `OPEN-SES-2`。

## 14.4 缺失、重复与失败

`R-13.6`（MUST / CONFIRMED）不得把“14 个字段全部非空”写成统一前置条件。handler 初始化空数组和空标量；当前反汇编没有显示字段级必填校验。平台层是否要求某个字段、至少一个 IP 或特定组合，必须作为下游策略单独验证。

依据：`A05.15`（`0x10016d9f0` 零初始化与 `0x10016db44` 继续调用）。

`R-13.7`（SHOULD / INFERRED）数组字段按出现顺序保留重复值；标量重复字段按 handler 的重复写槽行为取最后一次，并记录重复计数，便于发现车机 profile 差异。若产品策略不接受重复标量，应在平台适配层拒绝，而不是改变线协议解析。

依据：`A05.15`。

`R-13.8`（MUST / OPEN）getter 错误时必须停止本次平台交接、记录结构化错误并释放临时对象；当前 handler 的 0 返回路径没有取证到一个统一的 `0x4301` 错误响应，因此客户端不得伪造 ACK/错误消息。该条的错误上报方式和车机重试策略属于 `OPEN-SES-2`。

依据：`A05.15`。

## 14.5 平台交接边界

`R-13.9`（MUST / CONFIRMED）平台调用的第一个实参是 connection ID，不是 endpoint 指针。handler 从 component 的 primary-endpoint UUID 查已连接 ExternalAccessory，并读取 `EAConnectionID`；找不到时得到 0。其余 14 个字段按 `usbIP, wifiIP, ssid, pass, securityType, channel, port, deviceID, pubKey, srcVer, sdkVer, assetID, assetVer, mutualAuth` 顺序传递。

依据：`A05.15`；`0x1000b3ccc`、`0x100063fd0`。

`R-13.10`（MUST / OPEN）收到并解析 `0x4301`、完成本端平台调用、或看到 handler 返回 1，均不能单独作为 CarPlay 成功标准。必须继续验证 Wi-Fi/IP 可达性、控制会话、媒体/音频、时钟、输入和断线恢复；这些不是本 schema 的隐含结论。

依据：`A05.15`、`A02.13`。

## 14.6 编码示例（合成向量）

下列只是 TLV 编码形状测试，不是车机抓包，也不是互操作性向量：

```text
40 40 00 36 43 01
  00 12 00 00                                   # 外层0，含一个子参数
    00 0e 00 00 31 39 32 2e 30 2e 32 2e 31 00   # 子0: "192.0.2.1"
  00 11 00 01                                   # 外层1，含两个子参数
    00 08 00 00 4c 61 62 00                     # 子0: "Lab"
    00 05 00 02 06                               # 子2: channel=6
  00 08 00 02 00 00 1f 90                       # 外层2: port=8080
  00 05 00 08 01                               # 外层8: mutualAuth=true
```

实现测试必须另外覆盖：缺少 NUL、U32 写成 2 字节、Bool=2、未知 ID、重复 IP、空消息，以及同一消息跨链路包边界。合成向量不能证明车机接受这些字段组合。
