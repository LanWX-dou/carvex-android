# spec/01 — 会话对象模型

## 1.1 三个对象

`R-1.1`（MUST / CONFIRMED）会话层有三个互指对象，实现必须能表达它们的关系：

```
endpoint（0x1d8 字节）
  +0x028 → run loop
  +0x068   链路已连标志（1 字节，0/1）
  +0x078 → 消息解析器
  +0x0c8 → 控制缓冲（65535 字节）
  +0x0d0   特性槽数组（29 × 8 字节）

run loop
  +0x010 → endpoint
  +0x018 → link

link（0x268 字节 + 尾部缓冲）
  +0x0b0 → run loop
  +0x118   当前收包
  +0x130   5 槽发送队列指针数组
  +0x1a4   会话表项数（1 字节有效）
  +0x1b8   会话表数组（每项 4 字节）
```

四条指针边构成闭环（`endpoint→runloop→link→runloop→endpoint`），实现不应允许出现"只连一半"的状态。

依据：`A01.1`、`A01.2`、`A02.1`。

`R-1.2`（MUST / CONFIRMED）链路对象的**生命周期独立于会话**：它由建链分配，会话表只是它内部的一段定长数组。断连不清空对象，只把项数置 0。

依据：`A01.2`、`A12.5`。

## 1.2 会话即表项

`R-1.3`（MUST / CONFIRMED）会话表几何固定：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| `link+0x1a4` | 1（有效） | 表项数，0 表示空表 |
| `link+0x1b8` | 4 × n | 表项数组 |
| 项 `+0` | 1 | 会话号（8 位） |
| 项 `+1` | 1 | 数据面类型 |
| 项 `+2` | 1 | 版本 |
| 项 `+3` | 1 | 标志（bit0 被读取） |

初始值与复位值都是 `0xFFFF0100`（小端字节为 `00 01 FF FF`）：项数 0、对端 MOP 缺省 1、对端包长缺省 0xFFFF。实现必须把“项数 0”当作“无任何会话可路由”，而不是“默认会话”。

依据：`A01.3`、`A01.4`。

`R-1.4`（MUST / CONFIRMED）该 SYN 结构最多 **5 项**，生效表为 `0x1b8..0x1cb`。不能把对象尾部其他字段算成 44 项数组。客户端应拒绝计数大于 5 或载荷截断的输入；固件 SYN 解析器具有 `min(n,5)`，但不应照搬可能掩盖畸形输入的截断行为。

依据：`A09.6`、`A02.15`；跨层规则见 `link/R-3.5`、`link/R-3.9`。

`R-1.5`（MUST / CONFIRMED）`link+0x120` 与 `link+0x128` 是两条 8 字节元素表（建链按 `bufSize` 参数创建），**与会话无关**；会话表只由 `+0x1a4`/`+0x1b8` 描述。

依据：`A01.5`、`A11.1`。

## 1.3 每类型发送队列

`R-1.6`（MUST / CONFIRMED）`link+0x130` 是 **5 槽**指针数组，槽位下标即数据面类型；每槽是容量 255、元素 8 字节的列表。类型 0–4 全部有槽，包括没有分发分支的类型 3。

依据：`A01.5`、`A02.8`。

`R-1.7`（SHOULD / INFERRED）队列满的处理未取证。实现应在入队失败时返回明确错误，而不是静默丢弃；固件的入队路径只检查"能否找到会话"，不检查容量。

依据：`A11.4`。

## 1.4 消息处理器是进程级资源

`R-1.8`（MUST / CONFIRMED）消息处理器存放在**全局字典**（消息 ID → 函数），不是会话私有。注册只发生一次（幂等标志），断连不撤销。因此"能处理哪些消息"与"当前是否连接"无关，"消息能否到达处理器"才与连接有关。

依据：`A01.6`、`A01.7`、`A06.2`。

`R-1.9`（MUST / CONFIRMED）全局注册的规模是 **96 条**，来自 **29 项特性中的 27 张处理器表**。特性 8 与 27 没有处理器表，必须允许"有特性但零处理器"。

依据：`A01.7`、`A06.1`。

## 1.5 未决

`R-1.10`（MUST / CONFIRMED）从已验证的 SYN 条目建立映射，在连接提交时启用。24A446 路径为 `ParseSYNData → CheckNegotiation → NotifyConnection`：先复制到工作块，再整体提交到生效块（`A02.15`）。不得硬编码样本会话号 2/3，也不得任意另选号。`OPEN-SES-1` 仅保留首次分配/profile 选择、多会话冲突及跨版本互通规则。

依据：`A01.8`、`A02.15`。
