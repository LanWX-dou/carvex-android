# spec/05 — 识别门控与生命周期

## 5.1 入站准入

`R-5.1`（MUST / CONFIRMED）以下消息 ID **无条件**允许入站（不经认证、不经识别）：

| 集合 | 消息 ID |
|---|---|
| 低号 | `0x0000`、`0x0004`、`0x0005` |
| 识别组 | `0x1d01`、`0x1d05`、`0x1d06` |
| 认证组 | `0xaa01`、`0xaa03` |

依据：`A07.1`。

`R-5.2`（MUST / CONFIRMED）其余入站消息必须**同时**满足三条，缺一即丢弃：

1. 认证状态 == `2`
2. 识别状态 == `6`
3. 消息 ID 在"可收集合"（识别信息对象的 `+0x60` 处）中

依据：`A07.3`。

`R-5.3`（MUST / CONFIRMED）`0xaa06` 是例外：它**不要求认证完成**，但仍要求识别信息对象存在、识别状态 == `6`、可收集合非空且包含 `0xaa06`。汇编 `0x100051100`–`0x100051130` 和 `0x100051170`–`0x100051178` 给出这些检查。不能省略集合条件，也不能额外要求认证成功而使识别优先流程死锁。

依据：`A07.2`、`A05.5`。

## 5.2 出站准入

`R-5.4`（MUST / CONFIRMED）以下消息 ID **无条件**允许出站：

| 集合 | 消息 ID |
|---|---|
| 低号 | `0x0000`、`0x0004`、`0x0005` |
| 识别组 | `0x1d00`、`0x1d02`、`0x1d03` |
| 认证组 | `0xaa00`、`0xaa02`、`0xaa04`、`0xaa05` |

依据：`A07.4`。

`R-5.5`（MUST / CONFIRMED）其余出站消息必须**同时**满足：认证状态 `== 2`、识别状态 `== 6`、消息 ID 在"可发集合"（识别信息对象的 `+0x68` 处）中。

依据：`A07.5`。

`R-5.6`（MUST / CONFIRMED）**入站与出站是两套名单**，不可互换：

| 消息 ID | 入站 | 出站 |
|---|---|---|
| `0x1d01` | 无条件放行 | **需认证 + 识别** |
| `0x1d05` / `0x1d06` | 无条件放行 | 需认证 + 识别 |
| `0x1d00` / `0x1d02` / `0x1d03` | 需认证 + 识别 | **无条件放行** |
| `0xaa01` / `0xaa03` | 无条件放行 | 需认证 + 识别 |
| `0xaa00` / `0xaa02` / `0xaa04` / `0xaa05` | 需认证 + 识别 | 无条件放行 |
| `0xaa06` | 识别完成 + 可收集合包含 ID，不要求认证 | 需认证 + 识别 + 可发集合包含 ID |

依据：`A07.1`、`A07.4`、`A07.6`。

## 5.3 门控的位置

`R-5.7`（MUST / CONFIRMED）入站顺序固定为：**解析出消息 → 门控 → 查处理器 → 调用**。门控失败的消息不得进入处理器查找，即使该消息 ID 有处理器。

依据：`A07.7`、`A08.3`。

`R-5.8`（MUST / CONFIRMED）"记录了 Incoming Message ID"**不等于**"消息被处理"：该日志在门控之前打印。日志分析必须以随后的门控/处理器日志为准。

依据：`A08.4`。

`R-5.9`（MUST / CONFIRMED）出站顺序为：**取消息 ID → 门控 → 发送**。门控失败只返回失败，不发送、不排队。

依据：`A10.2`。

## 5.4 启动与拆除的时机

`R-5.10`（MUST / CONFIRMED）会话层只在链路状态**上升沿**（`0 → 1`）启动，且调用顺序固定：

```
1. 配置 USB 主机角色
2. 控制会话 init
3. 控制会话 start
4. 文件传输 init
5. 文件传输 start
6. 会话日志 init
7. 会话日志 start
```

控制会话必须最先初始化，因为它是消息处理器的注册者（`R-1.8`）。

依据：`A09.3`、`A06.2`。

`R-5.11`（MUST / CONFIRMED）只在**下降沿**（`1 → 0`）拆除，顺序为：控制会话 cleanup → 文件传输 cleanup → 会话日志 cleanup（与控制在前一致，**不是**逆序），且没有 USB 角色撤销。

依据：`A09.4`。

`R-5.12`（MUST / CONFIRMED）状态未变化时**不做任何事**。重复上报同一链路状态必须幂等。

依据：`A09.2`。

`R-5.13`（SHOULD / INFERRED）七个启动调用的返回值全部被忽略：任一启动失败都不会阻止后续步骤，也不会触发回退。实现若选择"失败即中止"，属于偏离固件行为，必须显式声明。

依据：`A09.5`。

## 5.5 "会话已建立"没有状态位

`R-5.14`（MUST / CONFIRMED）本层**没有**"会话已建立"标志。控制通道可用的判定只能由三条共同构成：链路已连标志为 1、会话表存在类型 0 的表项、目标消息通过门控。实现不得引入单一"established"布尔值并声称其来自协议。

依据：`A09.7`。

## 5.6 未决

`R-5.15`（未定义 / OPEN）启动失败是否导致链路状态回退未证明；两个"可收/可发集合"的填充时机未证明。实现必须把"集合何时变得可用"当作外部输入（由识别流程驱动），而不是自行推断。

依据：`A09.8`、`A07.8`。
