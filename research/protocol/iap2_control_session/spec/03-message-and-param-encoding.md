# spec/03 — 消息与参数的编码

本文件只定义**字节布局**。字段语义（某消息 ID 代表什么动作）由 `link/R-6.x` 与本规范 `R-4.x` 分别约束。

## 3.1 消息层

`R-3.1`（MUST / CONFIRMED）一条消息的布局：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| `+0` | 2 | 起始标记 `0x40 0x40` |
| `+2` | 2 | **总长（大端，含这 6 字节头）** |
| `+4` | 2 | **消息 ID（大端）** |
| `+6` | … | 参数区 |

实现必须校验"总长 ≥ 6"，否则连消息 ID 都不能读取。

依据：`A03.1`、`A03.2`、`A03.3`。

`R-3.2`（MUST / CONFIRMED）总长等于 6 加所有参数长度的累加和。编码时必须**先写参数、再回填总长**；解码时必须以总长为准，不得以"游标走到哪"推断。

依据：`A03.4`。

`R-3.3`（MUST / CONFIRMED）消息层**没有**校验和。完整性由包层的头校验与载荷校验提供（`link/R-3.x`）。实现不得为消息层另加校验字段，否则互操作性破坏。

依据：`A03.6`。

`R-3.4`（MUST / CONFIRMED）单条消息上限 **65535** 字节；超过上限必须拒绝，不得截断。

依据：`A03.5`。

## 3.2 字节流重组

`R-3.5`（MUST / CONFIRMED）接收侧按**字节**喂解析器，不按包：

- 一个包里可以有多条消息；
- 一条消息可以跨多个包；
- 解析器返回"一条消息完成"时，会话层才做门控与分派；
- 分派完成后，同一缓冲里的后续字节继续喂。

依据：`A03.5`、`A08.2`。

`R-3.6`（SHOULD / INFERRED）解析器在参数区遇到 `0x40 0x40` 时是否会误判为新消息起点未取证。实现应**以长度字段驱动跳过**参数区，而不是逐字节扫描起始标记；否则参数值中含 `40 40` 时会失去同步。

依据：`A03.7`。

## 3.3 参数层

`R-3.7`（MUST / CONFIRMED）一个参数的布局：

| 偏移 | 宽度 | 内容 |
|---|---|---|
| `+0` | 2 | **总长（大端，含这 4 字节头）** |
| `+2` | 2 | **参数 ID（大端）** |
| `+4` | n | 值 |

值长度 = 总长 − 4。固件的值长 helper 对小于 4 做下溢保护，但实现必须将总长<4 判为畸形 TLV，不能把它当空参数。

依据：`A04.1`、`A04.2`。

`R-3.8`（MUST / CONFIRMED）参数遍历必须区分 `parent` 与 `prev`：顶层 `GetFirstParam(msg,0)` 从 `buf+6` 起，要求首项至少有 4 字节头且不越过消息边界；实现另须明确校验声明长度>=4（固件顶层首项检查不完整）；非零第二参是父参数，父总长至少 5，子项从 `parent+4` 起，子项总长至少 4 且不得越过父值区。`GetNextParam(msg,parent,prev)` 按 prev 的声明长度推进同级项。每次推进前均须校验 len>=4、完整项不超过所属消息/父值区；异常项必须报错，不能当正常结束而接受后续字段。`len=4` 是合法的零值 TLV 形态，是否作为 presence 参数解释由 message profile 决定。

依据：`A03.8`、`A04.3`。

`R-3.9`（MUST / CONFIRMED）参数值区可以按同一格式嵌套子参数。实现必须以 `parent+4` 为起点、以父参数总长减 4 为边界；不能把 prev 当 parent，也不能越过父值区。空父项无子项；对子项不足 4 或声明长度越界必须报告解析错误，不能将固件的 NULL 返回等同于合法序列结束。

依据：`A04.4`、`A04.5`。

## 3.4 编码顺序

`R-3.10`（MUST / CONFIRMED）编码分三步且顺序固定：

1. 建立消息头：写 `40 40`、把总长占位为 6、写消息 ID、把写游标放到 `+6`；
2. 追加参数：每个参数写 4 字节头 + 值，游标前移；
3. 收尾：累加所有参数长度，回填 `+2` 处的总长。

依据：`A03.1`、`A03.4`。
