# spec/00 — 范围与术语

本规范描述 **iAP2 会话层（控制会话）** 的可观察行为：消息如何在会话表中被路由、控制消息如何编码、控制通道在何时被允许收发、断连时释放什么。它接在 `link/`（链路层）之后，**不重复**链路层的成帧、校验、序号、重传、SYN 协商与状态机。

## 0.1 适用范围

`R-0.1`（MUST / CONFIRMED）本规范只约束以下范围：

| 在范围 | 不在范围 |
|---|---|
| endpoint / 链路 / 会话表的对象关系 | 链路成帧、校验和、序号、重传（`link/`） |
| 会话表几何与两个查询方向 | 识别与认证的参数语义（`link/R-6.3`、`link/R-6.6`） |
| 消息层 6 字节头与参数层 4 字节头 | CarPlay 音视频链路、无线投屏 |
| 控制会话的初始化、版本门控、启停顺序 | 外部配件的业务语义（EA 面只描述封装） |
| 识别门控（准入）的两张白名单 | 认证算法、证书链 |
| 拆除、重连、资源释放 | 传输层（RFCOMM / USB / `os_channel`）细节（`link/R-1.x`） |

依据：`A00.1`、`A00.2`。

`R-0.2`（MUST / CONFIRMED）本文中的"会话"指**链路对象内的一条表项**，不是独立对象；"控制会话"指**表项类型为 0 的那条数据面**，其状态全部寄存在 endpoint 对象里。实现若把会话建模为对象，必须保证外部可观察行为与本文一致。

依据：`A01.3`、`A01.4`。

## 0.2 术语

| 术语 | 含义 | 首次定义 |
|---|---|---|
| endpoint | 会话层的宿主对象，`calloc(1,0x1d8)`，持有 run loop、解析器、控制缓冲、29 个特性槽 | `R-1.1` |
| link / 链路对象 | `memset(…,0,0x268)` 起、内含会话表与 5 条发送队列的对象 | `R-1.2` |
| run loop | endpoint 与 link 之间的中间对象，`+0x10` 指 endpoint、`+0x18` 指 link | `R-1.1` |
| 会话表 | `项数@+0x1a4`、`数组@+0x1b8`、每项 4 字节 | `R-1.3` |
| 会话号 | 表项 `[0]`，8 位，同时是链路头第 8 字节（`hdr[7]`） | `R-2.1` |
| 数据面类型 | 表项 `[1]`：0 控制、1 文件传输、2 外部配件、4 会话日志 | `R-2.3` |
| 消息 | 以 `40 40` 起始、带 2 字节总长与 2 字节消息 ID 的字节序列 | `R-3.1` |
| 参数 | 消息内以 4 字节头（总长 + ID）起始的单元，可嵌套 | `R-3.2` |
| 门控 | 消息准入检查：白名单或"认证完成 + 识别完成 + ID 在名单内" | `R-5.1` |

## 0.3 与上一阶段的关系

`R-0.3`（MUST / CONFIRMED）本规范只在链路状态为 `Connected` 之后生效。链路进入 `Connected` 时触发会话层启动，离开时触发拆除。链路层"找不到会话即丢包"的规则由 `link/R-6.9` 与本文 `R-1.3`、`R-2.3` 共同约束。

依据：`A09.1`、`A09.3`、`A09.4`、`A02.3`。

`R-0.4`（MUST / CONFIRMED）当本文与 `link/` 冲突时，以更接近证据的一方为准；本文不修改 `link/` 已确认的任何条款。上一阶段遗留的 `link/OPEN-SES-1`（两条 8 字节表的角色）在本文 `R-1.5` 中被**部分**解答：那两条表与会话无关。

依据：`A01.5`、`A11.1`。

## 0.4 未决项的处理方式

`R-0.5`（MUST / CONFIRMED）凡本文标为 `OPEN` 的条款，实现必须把它们做成**配置项或显式失败点**，不得依赖固件的默认值。所有 `OPEN` 项在 `analysis/` 对应文件里有专门的 `OPEN-SES-n` 条目，说明"缺什么证据、为什么缺"。

依据：`A01.8`、`A03.7`、`A04.5`、`A05.8`、`A07.8`、`A09.8`、`A10.8`、`A11.5`、`A12.6`。

## 0.5 强度标注

**解释边界（2026-10-26）**：本资料不是 Apple 官方规范。`CONFIRMED` 只证明指明固件/样本的行为，不证明全版本兼容。内存布局、5 队列、29 槽、注册数量、状态数值是参考实现内部细节，独立客户端不必复制；必须满足的是已确认的消息格式、顺序约束、边界与门控语义。下文将内部结构标为 MUST 的历史条款按此限定理解。未知 profile 应显式失败，不通过任意配置假装已实现。

| 标注 | 含义 |
|---|---|
| `MUST / CONFIRMED` | 有指令级证据，实现必须照做 |
| `SHOULD / INFERRED` | 结构与机制有据，但存在未取证字段或分支；实现应照做并保留开关 |
| `未定义 / OPEN` | 无足够证据；实现自由选择，但必须在文档中声明选择 |
