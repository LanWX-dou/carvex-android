# 05 — 时钟与时间戳来源

> 覆盖要求第 5、7 项。本文只写"接口形状 + 换算指令"能证明的部分；算法（漂移补偿、平滑、PTP 状态机）无证据。

---

## 5.1 结论摘要

| 编号 | 结论 | 强度 |
|---|---|---|
| `A05.1` | 存在"零时间戳提供者"对象：`self+0x10` 是 **double** 更新间隔，`self+0x18` 起是 **64 字节记录**数组，`self+0x98` 是原子索引 | `CONFIRMED` |
| `A05.2` | `APAudioZeroTimeStampProviderGetZeroTimeStamp` 用 `ldsetal` 原子读索引，再整块拷 64 字节快照给调用者 | `CONFIRMED` |
| `A05.3` | `endpoint_getCurrentRTPTime` 输出 **24 字节**结构；只有 `ctx+0x98 == 2` 时才做"当前时间 → RTP 时间"换算 | `CONFIRMED` |
| `A05.4` | 换算结果为 0（首字段为 0）时会先调 `0x251b40994` 再重算一次，即**一次重试** | `CONFIRMED` |
| `A05.5` | 时间戳的输入形态是 **double**，在写入/读取路径各做一次 `fcvtzu`（double → 无符号整数） | `CONFIRMED` |
| `A05.6` | 64 字节记录的字段含义（哪个是 RTP 时间、哪个是主机时间） | `OPEN-CLK-4` |
| `A05.7` | double 时间戳的单位（秒 / tick / 采样帧） | `OPEN-CLK-5` |
| `A05.8` | 更新间隔的默认值与合法范围、NTP/PTP 参与方式 | `OPEN-RUN-2` |

## 5.2 零时间戳提供者（`A05.1`、`A05.2`）

`APAudioZeroTimeStampProviderGetUpdateInterval`（`0x2519bbf1c`，8 字节）：

```asm
0x2519bbf1c: ldr d0, [x0, #0x10]   ; 返回 double
0x2519bbf20: ret
```

`APAudioZeroTimeStampProviderGetZeroTimeStamp`（`0x2519c1b94`，36 字节）：

```asm
0x2519c1b94: add  x8, x0, #0x18        ; 记录数组基址
0x2519c1b98: add  x9, x0, #0x98        ; 索引字段
0x2519c1b9c: ldsetal wzr, w9, [x9]     ; 原子读（set 位图为空 = 纯读）
0x2519c1ba0: add  x10, x8, x9, lsl #6  ; 槽位 = 基址 + 索引*64
0x2519c1ba4: ldp  q0, q1, [x10]        ; 读 32 字节
0x2519c1ba8: ldp  q2, q3, [x10, #0x20] ; 再读 32 字节
0x2519c1bac: stp  q2, q3, [x1, #0x20]  ; 写出到调用者缓冲 [0x20..0x40)
0x2519c1bb0: stp  q0, q1, [x1]         ; 写出到调用者缓冲 [0..0x20)
0x2519c1bb4: ret
```

由此确定的几何：

| 项 | 值 |
|---|---|
| 单条记录大小 | **64 字节**（`lsl #6`） |
| 记录数组基址 | `对象 + 0x18` |
| 索引字段 | `对象 + 0x98`（4 字节，原子读） |
| 更新间隔 | `对象 + 0x10`（double） |
| 输出 | 64 字节快照（调用者提供 ≥64 字节缓冲） |

`ldsetal` 是"原子读 + 置位"指令，`wzr` 作为置位图等价于无副作用读取——说明写侧与读侧跨线程共享该索引（但没有取模运算，索引的合法性由写侧保证）。

## 5.3 端点当前 RTP 时间（`A05.3`、`A05.4`）

`_endpoint_getCurrentRTPTime`（`0x251bd0250`）：

```asm
0x251bd0264: mov  x20, x8              ; x8 = 返回结构指针（24 字节）
0x251bd0268: bl   #0x25810ac50         ; 取上下文
0x251bd0270: adrp x8, #<外部页>          ; 目标页不属本镜像段表（共享缓存/其他镜像）
0x251bd0274: ldr  x8, [x8, #0x6b8]     ; 导入槽所指默认对象，语义未解析
0x251bd0278: ldr  q0, [x8]
0x251bd027c: str  q0, [x20]            ; 拷贝 16 字节
0x251bd0280: ldr  x8, [x8, #0x10]
0x251bd0284: str  x8, [x20, #0x10]     ; 再拷 8 字节 → 共 24 字节
0x251bd0288: ldr  x0, [x19, #0x78]
0x251bd028c: bl   #0x25810b430         ; 加锁
0x251bd0290: ldr  w8, [x19, #0x98]
0x251bd0294: cmp  w8, #2
0x251bd0298: b.ne #0x251bd02dc         ; 状态 != 2 → 不换算，直接返回
...
0x251bd02b8: bl   #0x251b3cfac         ; 换算：把时间基 + 时钟对象 → RTP 时间
0x251bd02bc: ldr  x8, [x20]
0x251bd02c0: cbnz x8, #0x251bd02dc     ; 首字段非 0 → 成功，结束
0x251bd02c4: ldr  x0, [x19, #0xa8]
0x251bd02c8: bl   #0x251b40994         ; 失败 → 先做一次"重建/刷新"
0x251bd02cc: bl   #0x258102680
0x251bd02d0: add  x1, sp, #0xc
0x251bd02d4: mov  x8, x20
0x251bd02d8: bl   #0x251b3cfac         ; 再换算一次（仅一次）
```

可确认的行为：

1. 返回值缓冲 **24 字节**，通过 `x8` 传入（AAPCS64 的间接返回约定）；
2. 先无条件把导入槽指向对象的24B默认值拷进输出，未证明是主机时间基（`A10.3`）；
3. `ctx+0x98 != 2` 时不换算，保留默认值；state=2也不等于已经同步；
4. 第一次结果首64位为0时刷新重算一次，第二次后没有再检查或明确报错（`A10.3`）；
5. 全程持 `ctx+0x78` 锁，返回前解锁（`0x251bd02fc` 尾调用）。

`ctx+0x98 == 2` 与 `jitterBuffer` 的 `desc+0x88` 无关，是两套对象；不要混用（见 `analysis/06`）。

## 5.4 时间戳是 double（`A05.5`）

两处独立证据：

| 位置 | 指令 | 含义 |
|---|---|---|
| 提交路径 `0x2519c19fc`–`0x2519c1a04` | `ldr d0,[x21]` / `fcvtzu d0,d0` / `str s0,[x1,#4]` | 描述符首字段是 double，转成无符号整数后**只写低 32 位**到 `base+4` |
| 读取路径 `0x2519c1948`–`0x2519c194c` | `ldr d0,[x24,#0x50]` / `fcvtzu x1,d0` | 描述符 `+0x50` 是 double，转成 64 位作为时间参数 |

这些是内部接口：Commit先转u64再保存低32位，Read使用u64；不是直接转u32。
独立客户端可用整数/定点内部时钟，不必复制double或64B布局；接口单位与特殊值策略仍需核实（`A10.3`）。

## 5.5 未决

| 编号 | 未决点 | 关闭条件 |
|---|---|---|
| `OPEN-CLK-4` | 64 字节记录内部的字段布局（RTP 时间 / 主机时间 / 速率 / 标志各在哪） | 找到写该记录的 `stp` 序列，或用抓包比对 64 字节内容 |
| `OPEN-CLK-5` | double 时间戳的单位 | 找到 `fcvtzu` 之前该 double 的来源（`mach_absolute_time` 换算 / 秒 / 帧） |
| `OPEN-CLK-3` | 14 位差值 `D14` 的时间单位（与 RTP 时间戳同单位） | 同 `OPEN-CLK-5` |
| `OPEN-RUN-2` | 更新间隔默认值、`ctx+0x98` 状态机取值集合、NTP/PTP 参与方式 | 运行期日志或控制面证据 |
