# 06 — 发送缓冲（jitterBuffer_* 族）

> 覆盖要求第 8 项。注意：这族函数在 `AirPlaySender` 里服务的是"把音频块装进 RTP 包"这一侧，**不是**接收端抗抖动算法；名字里的 jitter 不代表重排/去抖逻辑。

---

## 6.1 结论摘要

| 编号 | 结论 | 强度 |
|---|---|---|
| `A06.1` | `jitterBuffer_AcquireBuffer` 返回的负载指针 = 缓冲基址 **+ 12**，报告的单块容量 = **1460**（`0x5b4`）；即头部预留 12 字节 | `CONFIRMED` |
| `A06.2` | `jitterBuffer_CommitBuffer` 把描述符 `+0` 的 double 转成整数后写 **`base+4`（RTP 时间戳位）**，把负载长度写 **`base+0x5c0`** | `CONFIRMED` |
| `A06.3` | 提交长度 0 = 丢弃该槽（不发送）；长度非 0 时要求描述符 `+0x38` 的 bit0 置位，否则返回 `-0x4198` | `CONFIRMED` |
| `A06.4` | 双重获取 / 指针不属于本缓冲 / 未获取就提交，均返回 `-0x4199` | `CONFIRMED` |
| `A06.5` | `jitterBuffer_ReadPackets` 要求描述符 `+0x88` bit0 置位，按"每帧字节数（对象 `+0x50`）× 请求帧数"计算字节数并校验目的缓冲容量 | `CONFIRMED` |
| `A06.6` | 12+1460=1472仅局部几何；与接收拷贝门1481不是同一长度坐标，不能证明线上上限 | `限定` |
| `A06.7` | `1460` 是否已扣掉扩展元素区（元素区是否从这 1460 里出） | `OPEN-JIT-1` |
| `A06.8` | 对象 `+0x50`（每帧字节数）与 `+0x98`（状态）的赋值者 | `OPEN-JIT-2` |
| `A06.9` | 描述符 `+0x88`/`+0x38` 两个标志位的完整语义集合 | `OPEN-JIT-3` |

## 6.2 获取：预留 12 字节头（`A06.1`、`A06.6`）

`_jitterBuffer_AcquireBuffer(buf, ptrOut, sizeOut)`（`0x2519c0aec`）：

```asm
0x2519c0b10: bl   #0x25810ac50        ; 上下文
0x2519c0b14: ldr  x8, [x0, #0x68]
0x2519c0b18: cbnz x8, #0x2519c0b60    ; 已持有缓冲 → 错误 -0x4199
0x2519c0b20: ldr  x0, [x0, #8]        ; 池
0x2519c0b28: bl   #0x25810dab0        ; 取一块
0x2519c0b30: str  x0, [x21, #0x68]    ; 记在上下文里（"已持有"）
0x2519c0b3c: add  x8, x8, #0xc        ; ← 返回基址 + 12
0x2519c0b40: str  x8, [x20]           ; 出参：负载指针
0x2519c0b44: mov  w8, #0x5b4          ; 1460
0x2519c0b48: str  x8, [x19]           ; 出参：容量
```

要点：

1. 出参指针是 **基址 + 12**，即调用者拿到的就是"RTP 头之后"的载荷区，头 12 字节由框架保留（`A06.1`）；
2. 单块容量1460字节，与预留12字节合计1472；不据此推出线上MTU或满足接收侧拷贝门（`A06.6`、`A10.1`）；
3. 上下文 `+0x68` 是"当前持有块"的独占标记，二次获取直接报错（`A06.4`）。

## 6.3 提交：写时间戳与长度（`A06.2`、`A06.3`）

`_jitterBuffer_CommitBuffer(buf, payloadPtr, len, x3, x4, metaDesc)`（`0x2519c19b4`）：

```asm
0x2519c19d8: ldr  x1, [x0, #0x68]     ; 当前持有块
0x2519c19e0: add  x8, x1, #0xc
0x2519c19e4: cmp  x22, x8             ; 指针必须等于 基址+12
0x2519c19e8: b.ne #0x2519c1a4c        ; 否则 -0x4199
0x2519c19f0: cbz  x20, #0x2519c1a28   ; 长度为 0 → 丢弃路径
0x2519c19f4: ldrb w8, [x21, #0x38]
0x2519c19f8: tbz  w8, #0, #0x2519c1a58 ; bit0 未置位 → -0x4198
0x2519c19fc: ldr  d0, [x21]           ; 描述符 +0：double
0x2519c1a00: fcvtzu d0, d0            ; double → 无符号整数
0x2519c1a04: str  s0, [x1, #4]        ; 写 base+4 = RTP 时间戳（低 32 位）
0x2519c1a08: mov  w8, w20             ; 负载长度
0x2519c1a10: str  x8, [x1, #0x5c0]    ; 写 base+0x5c0
0x2519c1a14: ldr  x0, [x19, #8]
0x2519c1a18: bl   #0x25810daa0        ; 入队
0x2519c1a20: str  xzr, [x19, #0x68]   ; 释放"当前持有块"
```

由此确定的写入点：**只有 `base+4`（时间戳）与 `base+0x5c0`（长度）被写**；`base+1`（PT）、`base+2`（序列号）、`base+8..11` 都不在这条路径上写。这与 `A01.7` 的"装配点未闭合"一致：序列号/PT 由后续装配步骤补（`analysis/01` §1.6）。

长度0走 `0x2519c1a28..1a30` 调池取消接口后返回0，但**不经过清除持有字段的1a20**。
它不走此处的非零提交路径；完整释放/调用者可否再Acquire仍为 `OPEN-JIT-4`，不能宣称必然回到空闲（`A10.1`）。

这里与ReadNewMessage都用块内+0x5c0，但相同偏移本身不能证明是同一个对象或同一长度语义。接收端存T+2内部结束坐标，Commit存调用者长度低32位；应分别追对象生命周期（A10.1、A11.5）。

## 6.4 读取：按帧取（`A06.5`）

`_jitterBuffer_ReadPackets(object, desc, dst, cap, mustZero, frames, bytesOut, framesOut)`（`0x2519c18f0`，8参数，见`A10.2`）：

```asm
0x2519c192c: ldrb w8, [x24, #0x88]
0x2519c1930: tbz  w8, #0, #0x2519c198c   ; bit0 未置位 → -0x4198（未就绪）
0x2519c1934: cbnz x23, #0x2519c1994      ; 第 5 参数必须为 0（x4保存到x23）
0x2519c1938: ldr  w8, [x0, #0x50]        ; 每帧字节数
0x2519c193c: mul  w23, w8, w20           ; 字节数 = 乘积低32位，非溢出检查
0x2519c1940: cmp  x25, x23               ; 目的缓冲容量
0x2519c1944: b.lo #0x2519c199c           ; 容量不足 → -0x4198
0x2519c1948: ldr  d0, [x24, #0x50]       ; 描述符 +0x50：double 时间戳
0x2519c194c: fcvtzu x1, d0
0x2519c195c: bl   #0x25810dac0           ; 从池里取 bytes 字节
0x2519c1968: str  x23, [x21]             ; 出参：字节数
0x2519c196c: str  w20, [x19]             ; 出参：帧数
```

三个可实现的约束：

1. 描述符"未就绪"（`+0x88` bit0 = 0）时不得读取，报 `-0x4198`；
2. 固件以乘积低32位比较容量；独立客户端须额外checked multiply，不能依赖它检测溢出（`A10.2`）；
3. 时间戳来自描述符 `+0x50` 的 double，同样走 `fcvtzu`。

## 6.5 错误码

| 值 | 出现位置 | 触发条件 |
|---|---|---|
| `-0x4198` | `0x2519c19f8`、`0x2519c1930`、`0x2519c1944`、`0x2519c1934` | 标志位未就绪 / 容量不足 / 参数非 0 |
| `-0x4199` | `0x2519c0b64`、`0x2519c1a50` | 缓冲已被占用 / 指针不匹配 |

数值本身不做语义外推（没有证据表明它们是某个枚举成员）；实现按"非 0 即失败"处理即可。

## 6.6 未决

| 编号 | 未决点 | 关闭条件 |
|---|---|---|
| `OPEN-JIT-1` | 1460 是否包含扩展元素区：装配若把 `4n` 字节元素写在负载之前，可用负载会变成 1460−4n | 读装配函数对"负载起点"的使用，或用抓包统计 `12 + 4n + payload` 与 1472 的关系 |
| `OPEN-JIT-2` | 对象 `+0x50`（每帧字节数）与 `+0x98`（状态=2）的赋值者 | 找 `str` 到这两个偏移的函数 |
| `OPEN-JIT-3` | `desc+0x88` bit0、`desc+0x38` bit0 之外的标志位语义 | 找标志位的写入者（`orr`/`bfi` 到这两个字节） |
| `OPEN-RUN-2` | 池大小、块数、丢块策略、水位 | 运行期日志 |
