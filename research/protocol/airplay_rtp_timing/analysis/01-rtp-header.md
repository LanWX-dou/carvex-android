# 01 — RTP 固定头与装配路径

> 覆盖要求第 1、4、6 项的一部分。所有地址属于 `AirPlaySender`（SHA256 `304b8a4a…cd63f`）。
> 记号：`obj+N` 指 `APSRTPPacketHandler` 对象内的字节偏移；`pkt+N` 指一个媒体包缓冲区内的字节偏移。

## 1.1 结论摘要

| 编号 | 结论 | 强度 |
|---|---|---|
| `A01.1` | 媒体包固定头 **12 字节**；扩展元素从 `pkt+0xc` 开始 | `CONFIRMED` |
| `A01.2` | 序列号在 `pkt+2..3`，**大端 16 位** | `CONFIRMED` |
| `A01.3` | 内部包`pkt+1`低7位参与PT判定；Compose清高位的目标是终止元素，不能据此证明网络marker清零 | `CONFIRMED（坐标分离）` |
| `A01.4` | **接收路径**对输入长度执行 `len >= 0x5c9` 的拒绝分支（`0x5c9 = 1481`）；这不是已闭合的发送侧或跨版本“单个媒体包上限” | `CONFIRMED（接收路径）` |
| `A01.5` | 装配函数的内部长度出参=`4n+11`（n为4B元素数）；不是整包长 | `CONFIRMED` |
| `A01.6` | 多包合并（buffered）模式下 payload type 被改写成"带扩展变体"（见 `02`） | `CONFIRMED` |
| `A01.7` | B=M+10与内部I+12已对应；实际网络外层映射未闭合，无“11字节尾部” | `OPEN-RTP-1` |
| `A01.8` | 时间戳在 `pkt+4..7`，**大端 32 位**；每个子包的时间戳 = 包头时间戳 − 该元素的 14 位差值 | `CONFIRMED` |
| `A01.9` | 固定头前 12 字节在取包路径上被**整段复制**（`ldr x8 / str x8` + `ldr w9 / str w9`），再按子包改写 `+2`、`+4` | `CONFIRMED` |

## 1.2 固定头 12 字节：证据

`APSRTPPacketHandlerGetExtendedHeaderOfPacket`（符号自带，`0x251ace4e4`）：

```asm
0x251ace4e4: ldr  x8, [x0, #0xa8]      ; x8 = 当前包基址
0x251ace4ec: add  x9, x8, #0xc         ; x9 = 包基址 + 12 → 扩展元素区起点
```

同函数后续 `ldrsb w10,[x9+x8]` 以 `index*4` 为步进取第 `index` 个元素的**首字节**（`0x251ace4f0`–`0x251ace4f4`），说明扩展元素区紧接在 12 字节固定头之后。

固定头内部字段的定位由 `APSRTPPacketHandlerGetSeqNumOfPacket`（`0x251ace49c`）给出：

```asm
0x251ace49c: ldr  x8, [x0, #0xa8]      ; 当前包基址
0x251ace4a4: ldrh w8, [x8, #2]         ; 读 pkt+2 的 16 位
0x251ace4a8: rev  w8, w8               ; 字节序翻转
0x251ace4b0: sub  w9, w1, w9           ; w1 = 请求的包序号，w9 = obj+0x678（基序号）
0x251ace4b4: add  w8, w9, w8, lsr #16  ; 基包序列号 + (请求序号 − 基序号)
0x251ace4b8: add  w8, w8, #1
0x251ace4bc: and  w0, w8, #0xffff      ; 结果截到 16 位
```

由此三条同时成立：

1. 序列号占 `pkt+2..pkt+3`（两字节）；
2. 是大端存放（`ldrh` 之后必须 `rev` + `lsr #16` 才得到数值）；
3. 序列空间 16 位，回绕由 `and 0xffff` 显式处理（`A01.2`）。

按 `[RFC3550]` 可对照固定头布局；本构建已直接确认 `+1` PT、`+2` 序列号、`+4` 时间戳、`+12` 元素区。`+8..11` 有整块复制证据，但是否作为 SSRC 生成/验证尚未确认；第 0 字节的位语义也不能只由 RFC 布局断言（`OPEN-RTP-2`）。

## 1.3 payload type 字节（`pkt+1`）

接收侧 `APSRTPPacketHandlerReadNewMessage`（`0x2519c0c90`）把收到的包搬进内部缓冲后，显式写入 `buf+1`：

```asm
; 反编译对照（DECOMPILED_UNREVIEWED）＋指令核对
*(undefined1 *)(*(long *)(param_1 + 0xa8) + 1) = param_3;   ; buf+1 ← 调用方给的 PT 字节
```

随后立即用该字节决定要不要解析扩展元素：

```
uVar2 = (buf[1] & 0x7f) - 0x60
if (uVar2 < 14 && (bit(uVar2) in 0x3302 || (uVar2 == 0 && obj[0x1c] > 1)))  → 解析扩展元素
```

`0x3302` 的置位是 bit 1、8、9、12、13，即 payload type `0x61`、`0x68`、`0x69`、`0x6c`、`0x6d`（见 `02`）。

装配侧（`APSRTPPacketHandlerComposeRTPPacketWithBBuf`，`0x2519c348c`）写的是另一坐标的终止元素，不是已证的同一个`pkt+1`字节：

```asm
0x2519c37e4: ldrb w8, [x22]        ; x22 = 包描述结构
0x2519c37e8: and  w8, w8, #0x7f    ; 清掉最高位
0x2519c37ec: strb w8, [x28]        ; 写到元素游标E，见analysis/07
```

`and #0x7f`保证终止元素高位为0，不能证明网络marker被清零。接收侧`&0x7f`只证明内部PT判定忽略高位；marker的写入及含义仍为`OPEN-RTP-3`。

## 1.4 接收路径长度门（`0x5c9`）

`APSRTPPacketHandlerReadNewMessage` 收到数据后先比长度：

```asm
; if (len < 0x5c9) { 接受 } else { cold_3（丢弃并记录） }
```

`0x5c9 = 1481`。比较的是块缓冲 API 输出到 `[sp+0x10]` 的长度（`0x2519c0d10..34`），随后该长度的字节被拷到内部 `buf+2`（`0x2519c0d38..44`）；PT 另写到 `buf+1`。`+0x5c0` 又保存另一次块缓冲查询结果加 2（`0x2519c0d50..60`）。因此该门不能直接称为完整线上 RTP/UDP 包长，具体坐标与最终拼接仍见 `OPEN-RTP-8`。

在此内部拷贝路径，所比较长度须小于 1481；缓冲容量还须计入目标偏移与内部元数据，不能简单分配 1480 字节后从 `buf+2` 拷入。完整线上最大包长和发送侧门限未由此闭合。

## 1.5 装配长度公式 `4n + 11`

`APSRTPPacketHandlerComposeRTPPacketWithBBuf` 的收尾：

```asm
0x2519c37d8: lsl  w8, w22, #2       ; w22 = 本次写入的元素个数 n
0x2519c37dc: add  w20, w8, #0xb     ; w20 = 4n + 11
...
0x2519c3854: str  w20, [x27]        ; *出参 = 4n + 11
```

单包模式（`obj+0x1c < 2`，`0x2519c3550`）令`w20=10`并跳过元素写入，但仍复制音频头和当前音频数据。

这是内部长度出参，不是整包长度。其相对单包10多出的`4n+1`正是元素区长度；不能把11分解成PT/seq/ts/SSRC或推导第0字节写入者。主调用者用此值推进后处理指针，见`analysis/07` §7.4。

## 1.6 未决：临时缓冲的先后与最终线序（`OPEN-RTP-1`）

Compose的x3是包装对象，取API数据地址B后使用两个游标：元素在B起连续排列，载荷从`B+4n+1`起连续排列，末尾追加当前音频数据。接收侧从内部包基址+12扫描元素，两者并不矛盾。analysis/11已核B=M+10、M复制到I+2；尚缺实际网络适配到消息M的映射。旧H1“11字节尾部重排”没有证据，已撤回；不得用猜测的重排实现发送端。

## 1.7 未决：时间戳与 SSRC 的字段位置（`OPEN-RTP-2`）

本项部分关闭：§1.9 已给出 `pkt+4` 时间戳读取、差值处理和写回；`pkt+8..11` 也确有整体复制。仍缺的是 SSRC/流标识的生成、验证及会话绑定语义，不再是“没有读写指令”。关闭剩余问题需要字段使用链或真实流对照。

## 1.9 取包路径（`APSRTPPacketHandlerGetNextPacket`，`0x2519c14ec`）

该函数把内部缓冲里的一个包变成"头 + 负载指针/长度"的三元组，是固定头字段最直接的证据。

**整段复制固定头**（`0x2519c16d0`–`0x2519c16dc`）：

```asm
0x2519c16d0: ldr  w9, [x8, #8]     ; x8 = 内部包缓冲基址
0x2519c16d4: ldr  x8, [x8]         ; 取前 8 字节
0x2519c16d8: str  x8, [x19]        ; 出参 [0..7]  ← 缓冲 [0..7]
0x2519c16dc: str  w9, [x19, #8]    ; 出参 [8..11] ← 缓冲 [8..11]
```

`8 + 4 = 12`，这就是"固定头 12 字节"的第二次独立确认：**前 12 字节被原样搬走**，其中包括 `+1` 的 PT 字节与 `+4` 的时间戳。

**时间戳按子包改写**（`0x2519c1704`–`0x2519c1750`）：

```asm
0x2519c1728: ldr  w8, [x8, #4]        ; w8 = 缓冲 +4 的 32 位时间戳
0x2519c172c: rev  w8, w8              ; 大端 → 主机序
0x2519c1734: ldr  w9, [sp, #0xc]      ; w9 = GetExtendedHeaderOfPacket 解出的元素值
0x2519c1738: ubfx w9, w9, #8, #0xe    ; 取 bits 21..8 = 14 位差值 D
0x2519c173c: sub  w8, w8, w9          ; ts = 包头时间戳 − D
0x2519c174c: rev  w8, w8              ; 主机序 → 大端
0x2519c1750: str  w8, [x19, #4]       ; 写出子包时间戳
```

于是得到一条可直接实现的等式（`A01.8`）：

```text
sub_packet_ts = packet_ts − delta        （delta 为该子包扩展元素的 14 位字段）
最后一个子包不参与该减法（`0x2519c1744` 分支直接原样写出）；这条分支本身不证明最后元素的 D14 必为 0。
```

**序列号按子包改写**（`0x2519c1754`–`0x2519c1764`）：

```asm
0x2519c1754: mov  x0, x20
0x2519c1758: mov  x1, x21              ; 子包序号
0x2519c175c: bl   #0x251ace49c         ; APSRTPPacketHandlerGetSeqNumOfPacket
0x2519c1760: rev16 w8, w0              ; 转大端 16 位
0x2519c1764: strh w8, [x19, #2]
```

**负载位置与长度**（`0x2519c1618` / `0x2519c1654` / `0x2519c1690`）：

```asm
0x2519c1618: add  x26, x9, #0xc        ; 负载起点 = 包基址 + 12（再按元素个数前移）
0x2519c1654: str  x26, [x19, #0x10]    ; 出参 +0x10 = 负载指针
0x2519c1690: str  x8,  [x19, #0x18]    ; 出参 +0x18 = 负载长度
```

`0x2519c1688` 另有 `ldr x8,[x8,#0x5c0]`，即内部缓冲在 `+0x5c0` 处读取负载相关指针。它与接收路径的 `0x5c9` 长度门同属一条观察链，但不能据此证明发送侧存在独立同值拒绝指令，也不能关闭 `OPEN-RTP-8`。

据此，`OPEN-RTP-2` **部分关闭**：时间戳位置已确认；`+8..11` 的复制已证，SSRC 语义未闭合。
