# 抓包配方 —— 本阶段缺的那份证据（`OPEN-RUN-1`）

> 现状：本仓库**没有**任何 RTP/RTCP 媒体抓包（`analysis/00` §0.7、`analysis/A-conclusions.md` 的 `A00.3`）。
> 因此 `spec/01` 的全部字节结论目前只有**固件指令**证据，没有"线上实测"比对。
> 本文件把这件事写成可执行步骤：做什么、抓什么、怎么判定成功、成功了要放哪。

---

## 1. 要抓什么

| 目标 | 说明 |
|---|---|
| 一个完整会话的媒体流 | 至少 1 路音频 + 1 路视频（或两路音频） |
| RTP 头 | 12 字节固定头 + 元素区 + 载荷 |
| RTCP（若有） | SR/RR/SDES/BYE/XR 任一，用于时钟与统计比对 |
| 时间跨度 | ≥ 60 秒，覆盖合并模式与非合并模式（如同时出现） |

成功判据（缺一不可）：

1. 能按 `spec/01` 解出 PT、序列号、时间戳，且序列号在 60 秒内**连续无跳变**（除回绕）；
2. 包长全部 < 1481（`spec/01 R-1.5`）；
3. `PT ∈ {0x61,0x68,0x69,0x6c,0x6d}` 的包，其元素区能被 `reference-impl/rtp_parser.py` 解析且**不抛异常**；
4. 若抓到 RTCP SR，能把 SR 的 NTP/RTP 对应关系与 `spec/02`（待产出）对齐。

## 2. 抓法（按可得性排序）

### 2.1 无线 CarPlay（推荐）

手机与车机都接入同一个**可控 AP**：

```bash
# 在 AP 上（Linux / OpenWrt）：
tcpdump -i br-lan -s 0 -w airplay-$(date +%F-%H%M).pcap 'udp and not port 53'
```

要点：

- 必须让手机与车机**都**走这个 AP（车机连手机热点不行，那样流量不过 AP）；
- 抓 `udp` 全量而不是只抓已知端口——媒体端口在 SETUP 里动态分配，本阶段还没有控制面结论；
- 抓完先按 `spec/01` 过滤：找 `PT & 0x7f` 命中 `{0x60,0x61,0x64,0x65,0x68,0x69,0x6a,0x6c,0x6d}` 的 UDP 负载。

### 2.2 有线 / USB 以太网

若链路走 USB 网卡或 Ethernet 适配器，在中间设备上抓同一过滤条件。

### 2.3 macOS 侧

若用 Mac 作为对端（AirPlay 到 Mac），可在 `utun`/`bridge0` 上抓；注意此时对端是 Mac 而不是车机，**只能用于验证格式，不能用于验证车机行为**。

## 3. 入库要求

抓到的文件放到 `runtime/captures/`，并在 `runtime/captures/INDEX.md` 登记：

| 字段 | 要求 |
|---|---|
| 文件名 | `airplay-<设备>-<日期>-<时分>.pcap` |
| 大小 / SHA256 | 必填 |
| 抓取拓扑 | 手机 ↔ AP ↔ 车机（写清型号与固件版本） |
| 会话类型 | 无线 CarPlay / 有线 / AirPlay 到 Mac |
| 覆盖 | 音频/视频/双路 |
| 解析结果 | 用 `reference-impl/rtp_parser.py` 跑一遍的统计（包数、PT 分布、元素个数分布） |

## 4. 抓到之后要关闭的 `OPEN`

| `OPEN` | 关闭所需的观测 |
|---|---|
| `OPEN-RUN-1` | 上述任一抓包成功入库并通过 §1 判据 |
| `OPEN-RTP-1` | 线上包中元素区相对 12 字节头的实际位置（是否与装配函数的写序一致） |
| `OPEN-RTP-2` | `pkt+8..11` 是否随流变化（SSRC） |
| `OPEN-RTP-3` | `pkt+1` 最高位是否出现过 1（marker） |
| `OPEN-RTP-4` | 同一 PT 下元素数与元素长度的实际组合 |
| `OPEN-RTP-5` | 跨profile的B7/L10语义、长度≤1023保证；已核Compose中L10为音频数据长低10位，不含元素 |
| `OPEN-RTP-9` | 一次会话里实际出现的 PT 组合 |

## 5. 禁止事项

1. 不得用其他构建（尤其 23G90 / 22H374 / 21G93）的抓包去"确认" 24A446 的常量，只能作差异记录；
2. 不得把"能解析"写成"能播放"；
3. 不得把外部开源实现的抓包结论直接搬进来，除非同时给出抓包文件与解析脚本输出。
