# 04 RFCOMM 链路建立

## 4.1 帧格式

所有 RFCOMM 帧**必须**为下列结构：

```
+---------+---------+--------+==============+-----+
| Address | Control | Length | Information  | FCS |
+---------+---------+--------+==============+-----+
   1 字节   1 字节   1/2 字节  0..N 字节      1 字节
```

**R-4.1** `Address` 字段：

```
bit 0     EA    必须为 1
bit 1     C/R   由会话方向位 D 与控制帧角色共同决定（不是全局固定的命令=0/响应=1）
bit 2-7   DLCI  0..63
```

**R-4.2** `Control` 字段：

```
bit 4     P/F   命令轮询位 / 响应终止位
bit 0-3,5-7  控制码
```

本规范用到的控制码：

| 控制码（含 P/F=0） | 名称 | 含义 | C/R |
|---|---|---|---|
| `0x2F` | SABM | 建立数据链路 | 由 D 决定 |
| `0x43` | DISC | 断开数据链路 | 由 D 决定 |
| `0x63` | UA | 确认建立/断开 | 由 D 决定 |
| `0x0F` | DM | 拒绝/异常断开 | 由 D 决定 |
| `0xEF` | UIH | 携带用户数据 | 按方向 |

> 注：`DM` 的完整控制码为 `0x0F`；发送时 bit4（P/F）由实现按场景置位，接收方**必须**先屏蔽 bit4 再比较。

**R-4.3** `Length` 字段为变长编码：

- 首字节 bit0 = 1 → 单字节长度，值 = `该字节 >> 1`。
- 首字节 bit0 = 0 → 双字节长度，值 = `(b0 | (b1 << 8)) >> 1`。

因此长度 0 编码为 `0x01`，长度 1 编码为 `0x03`，长度 127 编码为 `0xFF`，长度 128 需要双字节 `0x00 0x01`（值 0x0100 >> 1 = 128）。

**R-4.4** `FCS` 的输入范围取决于帧类别：

- UIH：只覆盖 `Address`、`Control` 两个字节；长度、信用字节和信息字段不进入 FCS。
- SABM、DISC、UA、DM：覆盖 `Address`、`Control`、`Length`（无信息字段）。

算法固定为：

```
fcs = 0xFF
for each byte b:  fcs = table[(b XOR fcs) & 0xFF]
fcs = fcs XOR 0xFF
```

`table` 为 256 字节 CRC-8 表（多项式 0x07 的反射实现）。设备**必须**使用与对端相同的表；若表不同，则所有帧都会被丢弃。

**R-4.5** 接收方**必须**校验 FCS；校验失败**必须**丢弃整帧且**不得**返回任何响应。

## 4.2 DLCI 与通道号

**R-4.6** DLCI 与通道号的关系固定为：

```
通道号 = DLCI >> 1
DLCI   = (方向位 | (通道号 << 1)) ^ 1
```

`方向位` 为会话的方向标志（0 或 1），由会话建立时确定，之后不变。

- `D=0` → `DLCI = 2 × 通道号 + 1`（奇数）
- `D=1` → `DLCI = 2 × 通道号`（偶数）

这里的 D 是 `session+0x0c` 的固件方向位。新建出向复用器在 `0x1003c1dd4`–`0x1003c1dd8` 写 D=1，因此本地作为复用器发起方连接远端服务时得到偶数 DLCI。复用既有复用器时必须沿用其角色，不能按每次业务 connect 重新设置 D。

**R-4.7** 同一会话内，数据 DLCI **不得**重复；重复分配**必须**返回"已存在"错误。

**R-4.8** DLCI 0 保留给复用器控制；DLCI 1 **必须**拒绝用于数据通道（收到 DLCI 1 的 SABM 时按 4.6 的拒收规则处理）。

**R-4.9** DLCI ≥ 62 不可用于数据通道。对合法 EA/P/F/C/R 的 SABM，24A446 的地址越界分支经 `0x1003c5d74` 到 `0x1003c5e50` 回 DM；不能把所有地址非法情况概括为静默丢弃。

## 4.3 复用器建立（DLCI 0）

**R-4.10** 复用器由一条 DLCI 0 的 SABM 建立。发起方（D=1）发送 SABM（C/R=1，EA=1，P/F=1），接受方（D=0）回 UA（C/R=1，P/F=1）。

**R-4.11** 接受方在收到 SABM 前，会话状态**必须**为"未建立"；收到合法 SABM 并成功回应 UA 后，会话状态**必须**转入"已就绪"。

**R-4.12** 会话状态为"已就绪"后，再收到 DLCI 0 的 SABM 时，**必须**视为异常/重复，按实现策略回 DM 或忽略；**不得**重复初始化复用器。

**R-4.13** SABM 依次校验以下条件：EA/P/F/C/R 失败静默丢弃；状态或 DLCI 拒绝分支可能回 DM，见 R-4.9 与 R-4.16。

| 序 | 校验 |
|---|---|
| 1 | `Address` bit0（EA）= 1 |
| 2 | `Control` bit4（P/F）= 1 |
| 3 | `Address` 的 C/R 位与会话方向标志**互补**（见 R-4.14） |
| 4 | 会话处于允许的状态 |
| 5 | `Address` < `0xF8`（DLCI ≤ 61） |

**R-4.14** C/R 校验规则：设会话方向标志为 `D`，则要求 `(C/R == 0) == D`。即 `D=0` 时只接受 C/R=1 的入向 SABM，`D=1` 时只接受 C/R=0 的入向 SABM。组帧器的完整真值表是：

| D | SABM/DISC（命令）C/R | UA/DM（响应）C/R |
|---|---:|---:|
| 0 | 0 | 1 |
| 1 | 1 | 0 |

依据是 `0x1003c5334` 对 `session+0x0c` 的两组 `csel`。出向复用器建连置 D=1（R-4.6）；实现必须在会话建立时保存同一 D，并按表编码整条会话的控制帧。

> 实现提示：区分复用器角色和某条数据 DLCI 的打开者；C/R 不是实现方可任意选择的常量。

## 4.4 数据链路建立（DLCI ≠ 0）

**R-4.15** 建立数据链路**必须**按下列顺序：

```
发起方                                接受方
  |--- SABM (DLCI=n) ---------------->|
  |                                    | 查服务注册（通道号 = DLCI>>1）
  |                                    | 找到 → 回 UA；找不到 → 回 DM
  |<-- UA (DLCI=n) -------------------|
  |  DLCI 进入"已连接"                  |  DLCI 进入"已连接"
```

**R-4.16** 接受方在收到 SABM 时**必须**用 `通道号 = DLCI >> 1` 查本地服务注册表：

- 命中：**必须**在会话内创建 DLCI 记录，并从注册项继承：最大帧长上限、初始信用、上行/下行回调。
- 未命中：**必须**回 DM，并记录错误"该 DLCI 无注册服务端"。

**R-4.17** 新建 DLCI 记录的默认值：

| 项 | 默认值 |
|---|---|
| 状态 | "待接受" |
| 最大帧长 N1 | 127 |
| 入向标志 | 1（入向）/ 0（出向） |
| 信用计数 | 0（等待协商） |

**R-4.18** 若 DLCI 已存在且状态为"已连接"，再次收到 SABM 时**必须**回 DM（幂等拒绝），不得改变既有链路。

**R-4.19** 发起方发送 SABM 后**必须**把 DLCI 置为"连接中"，并在收到 UA 后置为"已连接"，收到 DM 后置为"已断开"。

## 4.5 连接参数

**R-4.20** 建立数据链路时**必须**协商（或至少设定）两项参数：

| 参数 | 含义 | 约束 |
|---|---|---|
| N1 | 最大信息字段长度 | > 0，且 ≤ 信用窗口字节数 |
| 信用窗口 | 初始信用 = 窗口字节数 / N1 | 结果必须 ≥ 1 |

**R-4.21** 参数校验失败**必须**返回"参数非法"错误且**不得**发送 SABM。

**R-4.22** 无线 iAP 场景的取值**应当**为：`N1 = 1007`、`信用窗口 = 15105`，即内部信用窗口容量 = `15105 / 1007 = 15`，不是直接写入 PN 的线上信用值。

> 这两个数值是固件实测值，非规范强制值；其他场景可不同，但 `N1 ≤ 信用窗口` 恒成立。

**R-4.23** N1 的协商结果**必须**上报给上层（上层可见名为"最大帧长"，若接口沿用 "MTU" 命名，语义仍是 N1，见 05.5）。

## 4.6 复用器控制命令帧

复用器控制命令走 DLCI 0 的 UIH，信息字段为：

```
+---------+---------+============+
| command | length  | data       |
+---------+---------+============+
   1 字节   1 字节    0..N 字节
```

**R-4.24** `length` 字段同样带 EA 位，值 = `该字节 >> 1`；**必须**表示 `data` 的字节数。

**R-4.25** 接收方**必须**校验 `信息字段总长 == length + 2`。不满足时**必须**销毁底层 L2CAP 通道（整条链路），而不是仅拒绝该命令。

> 这是本规范中唯一"一错即全断"的规则，实现必须严格。

**R-4.26** 未识别的 `command`，设备**必须**回一帧 **NSC（`0x11`）**，其信息字段为：

```
11 03 <原命令字节 & 0xFE>
```

（`0x03` 是长度字节，`>>1` = 1 字节数据。）**不得**用 DM 代替，也**不得**静默忽略。

### 4.6.1 命令分派表

设备**必须**按 `command & 0xFC` 分派，**必须**把下表之外的值（`0x30`/`0x40`/`0x70`/`0xB0`/`0xC0`/`0xD0`/`0xF0` 及任何非上表命令）都当作"未识别"处理（R-4.26）。

| 命令基值 | 命令 | 数据区长度要求 |
|---|---|---|
| `0x10` | NSC（非支持命令） | **恰好 1 字节** |
| `0x20` | TEST | 未展开（`OPEN-RF-5b`） |
| `0x50` | RLS（远程线路状态） | 未展开（`OPEN-RF-5b`） |
| `0x60` | FCOFF | 未展开（`OPEN-RF-5b`） |
| `0x80` | **PN（参数协商）** | **恰好 8 字节** |
| `0x90` | **RPN（远程端口协商）** | **≥ 1 字节**；完整形态 8 字节 |
| `0xA0` | FCON | 未展开（`OPEN-RF-5b`） |
| `0xE0` | **MSC（调制解调器状态）** | **≥ 2 字节**（2 或 3） |

### 4.6.2 PN（`0x83`/`0x81`）数据区布局

数据区长度**必须恰好 8 字节**；不是 8 字节时**不得**按 PN 处理。

| 偏移 | 字段 | 语义与约束 |
|---|---|---|
| 0 | DLCI | 低 6 位有效；值 `0`–`61`（`0x3D`）；**`1` 与 `≥62` 为非法值，必须拒收** |
| 1 | 帧类型 / 会聚层 | 与 `0xF0` 比较决定是否走信用流控路径 |
| 2 | 优先级 | 低 6 位有效（`& 0x3F`） |
| 3 | ack 计时器 | 参考实现**忽略**该字段 |
| 4–5 | 最大帧长 N1 | 16 位小端；生效值取"本地 N1"与"对端 N1"的**较小者** |
| 6 | 最大重传 | 参考实现**忽略**该字段 |
| 7 | 初始信用 | 参考实现**只取低 3 位**（`& 0x07`） |

**R-4.28** 收到 PN 后，设备**必须**把生效 N1 取双方较小值，并把信用计数设为对端给出的初始信用（参考接收器取 `value & 7`，不是 `min(value,7)`；如 20 得到 4）。

**R-4.29** 设备**可以**忽略 PN 的 ack 计时器与最大重传字段（参考实现即如此），但**不得**因这两个字段取值异常而断链。

> **运行时边界**：旧报告把 PN 请求/响应标签颠倒，因而“请求 1007、响应 2027，响应不回填 min”的推论作废。接收路径取 min 有静态证据；响应端如何生成 N1 仍列 `OPEN-RF-17`。

**R-4.29a（CONFIRMED）** PN、MSC、RPN 的载荷地址不是同一种布局：固件 PN 解析按 `payload[0] & 0x3F` 取 DLCI；MSC/RPN 解析按 `payload[0] >> 2` 取地址字段。两者是已确认的不同字段布局，不能用启发式把一个合法的裸 PN DLCI 重映射成另一条 DLCI。

发送 PN 时使用裸 DLCI（`DLCI & 0x3F`）；发送 MSC/RPN 时使用地址字段（`(DLCI << 2) | 0x03`）。收到 PN 后只按 PN 布局校验 DLCI 范围（0–61，排除 1）；收到 MSC/RPN 后只按各自地址布局解码。未知或不匹配的 DLCI 应拒绝该命令并记录诊断，不得把它“猜测”成另一条通道。

### 4.6.3 MSC（`0xE1`/`0xE3`）数据区布局

数据区**至少 2 字节**：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | DLCI | **按地址字节编码**：`DLCI = 字节 >> 2` |
| 1 | 调制解调器信号 | bit 语义随实现；参考实现只用其中若干位 |
| 2 | 附加信号（可选） | 仅当数据区长 3 字节时存在 |

**R-4.30** 参考固件发送 MSC 时，数据区第 0 字节写为地址字段
`(DLCI << 2) | 0x03`（见 `0x1003c7248`–`0x1003c7250`），第 1 字节为信号值；无附加信号时该信号值在组帧前置 bit0（`signal | 1`），有附加信号时再写第 2 字节（`(extra << 4) | 3`）。控制命令为 `0xE1`/`0xE3`，对应信息长度为 2 或 3 字节（外层长度字节 `0x05`/`0x07`）。因此不能把 MSC 第 0 字节写成 `DLCI | 1`；那是错误的 PN/MSC 混淆。

### 4.6.4 RPN（`0x93`/`0x91`）数据区布局

数据区**至少 1 字节**；完整形态为 8 字节：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | DLCI | **按地址字节编码**：`DLCI = 字节 >> 2`；`> 0xF7` 为非法 |
| 1 | 帧类型 | 原样保存 |
| 2 | 优先级 / 会聚层 | 参考实现按常量表展开成 4 字节掩码 |
| 3 | 波特率相关 | 低 6 位有效 |
| 4–5 | 最大帧长 N1 | 16 位小端 |
| 6–7 | 重传/信用相关 | 16 位整体读取，字段拆分未取证（`OPEN-RF-5c`） |

### 4.6.5 长度异常的处理

**R-4.31** 当 MSC 数据区 < 2 字节或 RPN 数据区 < 1 字节时，24A446 的内部诊断构建会走终止进程路径；客户端实现**不得**照搬该崩溃行为，必须丢弃该命令并记录诊断计数。

**R-4.32（会话超时）** 设备**必须**为"已发 SABM 等待 UA"与"已发 DISC 等待 UA/DM"配置一个会话级超时，且该值**必须可配置**、**不得**硬编码。

- 参考实现的默认值为 **30 个单位**，单位为 **100 ms**，即 **默认超时 = 3.000 s**（证据：先 `×100`，再按毫秒拆成 `timespec` 交给 `pthread_cond_timedwait_relative_np`，见 `04` C9.3）。
- 覆盖点是配置项 ID `50` 的 16 位字段（偏移 `+0xA`）；该值为 0 时回落到 30；单位同为 100 ms。
- 实现方**应当**在配置层暴露"秒"或"毫秒"并在内部换算，避免把 30 误当秒或误当毫秒。

**R-4.33** 超时值**必须**小于 `0x8000` 个单位（即 **< 54.6 分钟**）；参考实现以 16 位到期时刻记录，bit15 置位即视为非法并拒绝登记。

**R-4.34** 实现**不得**把"16 位到期时刻"当作唯一计时依据：参考实现里该字段（10 µs 粒度，回绕 ≈ 0.655 s）只用于槽位排序与陈旧标记，真正的等待由平台定时器承担（`04` C9.3）。≥ 1 s 量级的等待**必须**由平台定时器或更宽的计数器承担。

## 4.7 拒收与错误响应

| 场景 | 响应 |
|---|---|
| SABM 的 EA/P/F/C/R 失败 | 无响应（静默丢弃） |
| SABM 通道号无注册服务 | DM |
| SABM 指向已连接 DLCI | DM |
| 地址 ≥ 0xF8 | 无响应 |
| DLCI = 1 的 SABM | DM（按 `04` 的拒收规则） |
| FCS 错 | 无响应 |
| 命令帧长度不符 | 销毁链路 |

**R-4.27** 所有"无响应"情形**必须**记录诊断计数（便于定位互通问题），但**不得**向上层报错——静默丢弃是规范行为。

## 4.8 一致性判据

1. 帧编码：`EA=1`、C/R 按 R-4.2、长度按 R-4.3、FCS 按 R-4.4；用固定向量验证（如 SABM(DLCI 0, P=1) = `03 3F 01 FCS`）。
2. DLCI 与通道号按 R-4.6 双向换算一致。
3. 五道 SABM 校验逐条可触发（分别验证静默丢弃与 DM 分支）。
4. 无注册服务的 DLCI 收到 SABM 时回 DM。
5. 命令帧 `length` 与实际数据长度不符时链路被销毁。
6. 协商后 `N1 ≤ 信用窗口` 且初始信用 ≥ 1。
7. 未识别命令（如 `0x40`）时**回 NSC**，其数据字节等于原命令码 `& 0xFE`（可用单帧验证）。
8. 收到 PN 时按 R-4.28 取 `min(N1_本地, N1_对端)`；DLCI 字节按 R-4.29a 的裸 DLCI 布局解析，不做地址字段猜测。
9. 收到 PN 后信用上限为 7（本实现只认低 3 位）；接收端取 `value & 7`，不是饱和到 7；发送端只写合法的 0–7。
10. MSC 数据区 < 2 字节、RPN 数据区 < 1 字节时**不得崩溃**（R-4.31）。
