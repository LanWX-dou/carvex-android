# 01 可发现性与设备识别

## 1.1 可发现性（connectability）

**R-1.1** 设备**必须**在需要被连接期间进入可发现/可连接状态（page scan 与 inquiry scan 均可响应）。

**R-1.2** 设备**应当**把可发现性实现为带参数的占空比控制，而不是二元开关：

| 参数 | 作用 |
|---|---|
| 扫描间隔（interval） | 两次扫描窗口之间的周期 |
| 扫描窗口（window） | 每次扫描持续时间 |
| 隔行扫描（interlaced） | 是否交替使用两套扫描参数 |
| 辅路扫描（aux scan）参数、使能、抢占、时长 | 与主扫描并行的第二套扫描策略 |

**R-1.3** 设备**可以**在"仅需被已知对端连接"时缩短窗口，但**不得**在无线 CarPlay 会话期间关闭可连接性，否则断线后无法重连。

> 依据：附录 A 的 D-01–D-04。

## 1.2 EIR 数据结构

EIR 由一串 AD 结构组成，每个结构为：

```
+--------+--------+------------------+
| length | type   | data (length-1)  |
+--------+--------+------------------+
   1 字节   1 字节   length-1 字节
```

**R-1.4** `length` **必须**等于 `1 + data 长度`（即包含 type 字节本身，不含 length 字节）。

**R-1.5** 整个 EIR 的累计长度**不得**超过 **240 字节**。超过时设备**必须**丢弃优先级最低的结构，而不是截断某个结构。

**R-1.6** 设备**必须**包含一个 **Complete Local Name** 结构：

```
[len][0x09][本地名 UTF-8 字节]
```

`len = 本地名长度 + 1`。本地名**必须**来自运行时可配置值，不得硬编码为设备型号。

## 1.3 服务类 UUID 列表

设备**必须**广播其支持的服务类，且区分 16-bit 与 128-bit 两类。

### 1.3.1 128-bit 服务类 UUID（规范性常量）

设备**必须**在支持对应能力时广播下列 UUID（EIR 内为小端字节序）：

| 能力 | UUID（文本顺序） | 大端字节 |
|---|---|---|
| 无线 iAP（网关角色） | `00000000-deca-fade-deca-deafdecacafe` | `00 00 00 00 de ca fa de de ca de af de ca ca fe` |
| 无线 iAP 伴随标识 | `02030302-1d19-415f-86f2-22a2106a0a77` | `02 03 03 02 1d 19 41 5f 86 f2 22 a2 10 6a 0a 77` |
| 无线 iAP 接收端角色 | `00000000-deca-fade-deca-deafdecacaff` | `00 00 00 00 de ca fa de de ca de af de ca ca ff` |
| CarPlay（经典） | `ec884348-cd41-40a2-9727-575d50bf1fd3` | `ec 88 43 48 cd 41 40 a2 97 27 57 5d 50 bf 1f d3` |
| CarPlay 网关 | `2d8d2466-e14d-451c-88bc-7301abea291a` | `2d 8d 24 66 e1 4d 45 1c 88 bc 73 01 ab ea 29 1a` |

**R-1.7** 上述 UUID **必须**逐字节一致。其中前三个含 `deca-fade` 字样，属人工构造标识，**不得**按 UUID v4 规则校验版本位或变体位。

**R-1.8** UUID 在 EIR 中**必须**按小端（逐字节逆序）写入；例如第一行上线为：

```
fe ca ca de af de ca de de fa ca de 00 00 00 00
```

### 1.3.3 同一 UUID 在 SDP 中的字节序（重要，实测）

**R-1.8a** 设备**必须**区分两类 UUID 族在 SDP 报文中的字节序：

| UUID 族 | SDP 报文中的字节序（实测） | 线上字节 |
|---|---|---|
| WiAP 族（`…deca-fade-deca-deafdecacafe` / `…ccaff`） | **文本顺序**（大端） | `00 00 00 00 de ca fa de de ca de af de ca ca fe` |
| CarPlay 族（`ec884348-…`、`2d8d2466-…`） | **逆序**（小端，与 EIR 相同） | `d3 1f bf 50 5d 57 27 97 a2 40 41 cd 48 43 88 ec` |

即：

- `ec884348-cd41-40a2-9727-575d50bf1fd3` 在 SDP 中**以** `d31fbf50-5d57-2797-a240-41cd484388ec` 的形式出现；
- `2d8d2466-e14d-451c-88bc-7301abea291a` 在 SDP 中**以** `1a29eaab-0173-bc88-1c45-4de166248d2d` 的形式出现。

**R-1.8b** 设备在 SDP 中匹配 CarPlay 服务时，**必须**同时接受上述逆序字节；只匹配文本顺序将**永远**匹配不到真实的 iPhone 设备。

**R-1.8c** 若设备自身发布 CarPlay 服务记录，**应当**采用与实测一致的形式（逆序），并在文档中记录该选择。

> 说明：本节依据是**运行时抓包**（三个构建、多条独立报文一致），属跨构建佐证；固件侧可确认的只有"EIR 走逆序复制"与"名称比较用文本序立即数"两点。二者为何不同见 `OPEN-RUN-1`。


### 1.3.2 分组广播

**R-1.9** 设备**应当**按能力把 128-bit UUID 成组广播，每组占 `2 + 16×N` 字节：

| 组 | 内容 | 数据长度 |
|---|---|---|
| A | 两个 iAP UUID（网关 + 伴随标识） | 32 字节 |
| B | 两个 UUID（接收端角色 + CarPlay） | 32 字节 |
| C | 一个 UUID（CarPlay 网关） | 16 字节 |

A 组与 B 组互斥于"角色"维度：同时支持两种角色时两组都发。

**R-1.10** 16-bit 服务类 UUID 列表与 128-bit 列表**应当**作为独立的 AD 结构分别广播，不得混在同一个结构里。

## 1.4 设备识别

**R-1.11** 判定"对端是否为无线 CarPlay / 无线 iAP 设备"**必须**基于 1.3.1 的 UUID 字节匹配，**不得**基于本地名、厂商名或类别（CoD）字符串。

**R-1.12** 设备**应当**维护 UUID → 能力名 的映射，用于日志与诊断。映射**必须**覆盖：

| 能力名 | UUID |
|---|---|
| `WiapGateWay` | `00000000-deca-fade-deca-deafdecacafe` |
| `WiapSink` | `00000000-deca-fade-deca-deafdecacaff` |
| `WiapGateWay_v2` | `08ed27c3-1d19-415f-86f2-22a2106a0a77` |
| `WiapSink_v2` | `08ed27c3-1d19-415f-86f2-22a2106a0a78` |
| `Carplay` | `ec884348-cd41-40a2-9727-575d50bf1fd3` |
| `CarplayGateway` | `2d8d2466-e14d-451c-88bc-7301abea291a` |
| `AapServer` | `7221ec74-0bad-4d01-8f77-997b2be0722a` |
| `AapService` | `4b6f7c4b-07f4-49de-b0b9-ab4304728f29` |
| `AapClient` | `1ff31936-572e-4b36-a2bf-b2409b1aa6f4` |
| `D2D` | `00000000-deca-cafe-deca-cafedecacafe` |
| `Magnet` | `04e10d1e-00b1-432a-b764-ddba983af941` |
| `SyncMLServer` | `01000000-0000-1000-8000-0002ee000002` |
| `SyncMLClient` | `02000000-0000-1000-8000-0002ee000002` |

**R-1.13** 对以 `…-0000-1000-8000-00805F9B34FB` 结尾的 UUID，设备**应当**按 16-bit 短 UUID 处理（取 `0000xxxx` 段的 `xxxx`），映射到标准服务名。

## 1.5 与 LE 通道的区分

**R-1.14** 设备**必须**把经典 EIR 与 LE 广播视为两条独立通道：在经典 EIR 中发现"LE CarPlay"标识时**必须忽略**该标识，不得据此判定对端支持 LE CarPlay。

**R-1.15** 设备**应当**为两条通道分别维护能力状态（支持 / 不支持 / 未知），不因一条通道的结论覆盖另一条。

## 1.6 一致性判据

设备通过本章的条件：

1. EIR 总长 ≤ 240，所有 AD 结构 `length` 字段正确。
2. 每个 128-bit UUID 逐字节与 1.3.1 表格一致，且为小端写入。
3. 本地名结构存在且类型为 `0x09`。
4. 关闭某能力后，其 UUID **不再出现**在 EIR 中（而非出现但为空）。
5. 同时开启经典与 LE 能力时，EIR 仍 ≤ 240 且不发生截断。
