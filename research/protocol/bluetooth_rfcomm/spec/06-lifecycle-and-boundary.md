# 06 生命周期与上层边界

## 6.1 主动断开

**R-6.1** 主动断开数据链路**必须**发送 DISC（基值 `0x43`，线上 `0x53`，C/R 按会话角色，EA=1，P/F=1），并把该 DLCI 置为"等待确认"。

**R-6.2** 等待确认期间**必须**启动超时定时器；超时后**必须**直接销毁 DLCI 记录并上报"断开超时"。

**R-6.3** 收到 UA 后**必须**把 DLCI 置为"已断开"并释放记录。

**R-6.4** 收到 DM 时**必须**把 DLCI 置为"已断开"（对端拒绝或已不存在），**不得**重试 DISC 无限次。

**R-6.5** 同一 DLCI 上重复发起 DISC **必须**被抑制（幂等），不得产生多个定时器。

## 6.2 被动断开

**R-6.6** 收到 DISC 时**必须**：

1. 对通过校验且仍存在的数据 DLCI 回 **UA**（基值 `0x63`，线上 `0x73`，C/R 按角色）作为确认；
2. 按 DLCI 当前状态分派收尾；
3. 释放该 DLCI 的全部资源。

> `0x1003c6330`/`0x1003c62ac` 传入十进制 99，即 `0x63`（UA），不是 DM。DM 仍可表示远端拒绝/已不存在，不能把它写成正常 DISC 应答。

**R-6.7** 对同一 DLCI 重复收到 DISC 时，**必须**幂等处理：不得重复回调上层；若 DLCI 记录仍在，可回 UA；若记录已删除，24A446 的查表失败路径记录后返回，不保证再次应答。

**R-6.8** DISC 先校验 EA=1、P/F=1、C/R 匹配、地址 < 0xF8、DLCI ≠ 1；失败静默返回。会话为 7 时分 DLCI 0/数据 DLCI 处理；非 7 状态可直接回 UA（`0x1003c6274`–`0x1003c62ac`），不能概括成“非就绪一律丢弃”。

**R-6.9** 复用器级 DISC（DLCI 0）**必须**：

1. 把会话置为"断开中"；
2. 启动会话级超时（缺省值 30，参考换算 100 ms/单位，见 R-4.32）；
3. 回 UA；
4. 超时或收到确认后销毁整条会话及其全部 DLCI。

**R-6.10** 会话级超时值**必须**可配置；配置为 0 时使用实现缺省值。

## 6.3 资源清理顺序

**R-6.11** 销毁一个 DLCI **必须**按下列顺序，不得颠倒：

```
1. 取消该 DLCI 的定时器
2. 从会话的 DLCI 链表摘除
3. 释放挂起的发送/接收缓冲与未完成回调
4. 执行协议层收尾（信用、队列、统计归并）
5. 若这是该会话最后一个 DLCI 且需要上报 → 用"最后一次错误码"通知上层
6. 释放 DLCI 记录内存
```

**R-6.12** 第 5 步的错误码**必须**是"导致该 DLCI 关闭的原因"而非"最后一个操作的结果"，否则上层无法区分正常关闭与异常断开。

**R-6.13** 销毁会话前**必须**先销毁其全部 DLCI；**不得**留下指向已释放会话的 DLCI 记录。

**R-6.14** 清理过程**必须**可重入：清理中触发的回调**不得**再访问正在释放的记录。

## 6.4 协议违规的惩罚

**R-6.15** 复用器控制命令帧的信息长度与子长度不符时，**必须**销毁底层链路（整条会话），而不是只断开该 DLCI。

**R-6.16** 销毁链路**必须**：

1. 停止所有定时器；
2. 对所有 DLCI 上报"链路异常断开"；
3. 释放全部缓冲；
4. 允许上层立即重连（不得进入长时间禁止态）。

**R-6.17** 未识别的复用器命令**必须**按 R-4.26 回 **NSC** 响应（`0x11` + 命令字节），**不得**销毁链路，**不得**静默忽略。（此处原先写作"回 UA 或忽略"，与 `spec/04` R-4.26 冲突；以 R-4.26 的汇编依据为准。）

## 6.5 重连

**R-6.18** 重连时**必须**优先复用状态为"已就绪"的会话：若会话存在，直接对新 DLCI 发 SABM，**不得**重建复用器。

**R-6.19** 会话已被销毁时，**必须**从 L2CAP 通道建立重新开始（新会话需要新的 DLCI 0 SABM/UA）。

**R-6.20** 重连**必须**使用新的 SDP 结果（或经缓存验证的结果）确定通道号；**不得**沿用旧的通道号假设。

**R-6.21** RFCOMM 层**不得**自行重连：出向连接只执行一次，失败即向上层报错；断链后只做清理（`R-6.11`），**不得**在该层内置重试计数或重连定时器。

**R-6.22** 重连节奏（由基带/连接管理层负责）**必须**是"固定等待 + 硬上限"，参考实现的参数为：

| 参数 | 参考值 | 依据（`analysis/06` C8） |
|---|---|---|
| 重试上限 | **5 次**（计数 0…4） | `cmp w0,#4` + "Reached max … retries" |
| 页扫描定时器重设 | **60 s** | `0x139d70(dev, 0x3c)` |
| 页扫描退避定时器 | **300 s**（固定） | `0x45D964B800` ns |
| 连接请求看门狗 | **8 s** 或 **16 s** | `csel 8,16` + "watchdog stall timeout" |

**R-6.23** 达到重试上限后**必须**放弃本次重连并把设备移出待重连集合，**不得**无限重试。

**R-6.24** 实现**不得**假定存在指数退避：参考实现没有按次数增长的等待。若实现方采用指数退避，**必须**同时保留硬上限，且上限不得大于参考实现的 5 次（否则对端行为会被"更晚才发现放弃"拖长）。

**R-6.25** 重连尝试**应当**有上限与退避；达到上限后**必须**上报失败并停止重试，等待上层显式触发。

**R-6.26** 旧链路句柄在会话销毁后**必须**失效；用旧句柄发起的接受/断开操作**必须**返回"句柄无效"错误（日志 `OI_RFCOMM_Accept - linkhandle %d not found`）。

## 6.6 上层边界定义

> 交接契约的**完整定义**（交付形态、数据单位、缓冲有效期、上限与分块、关闭与错误通知、本层不提供什么）
> 见 `spec/08-handoff-contract.md`；本节只给分层与边界原则。

**R-6.27** 本规范把系统分为四层，边界固定：

| 层 | 职责 | 不该做的事 |
|---|---|---|
| RFCOMM 帧层 | 地址/控制/长度/FCS、DLCI、信用、SABM/UA/DISC/DM、流控 | 不解析 payload、不做报文重组、不做重传 |
| 传输桥层 | 在帧层与上层之间搬运字节（缓冲、分块、fd/队列） | 不改写数据、不做协议判断 |
| iAP2 Link 层 | 报文头、长度、序号、校验 | 不关心 DLCI/信用；**不在此层定义会话语义** |
| 应用层 | CarPlay / 配件业务 | — |

> **后续阶段修订（2026-10，分层越界修正）**：本表原先在 iAP2 Link 层写有"会话状态"，属越界——
> 会话表的**存储位置**在 link 对象内（`link[0xc0]` 一类字段），但**语义归属**在会话层，
> 不由本规范也不由 link 帧格式定义。本规范只约束 RFCOMM 帧层与传输桥层。


**R-6.28**（**后续阶段修订（2026-10）**，替代本条原"传输桥层必须不丢失帧边界"的表述）

帧层向**同进程回调**交付的单位**必须**是"一个信息字段"；向**fd 客户端**交付的是**字节流**，
**帧边界不可见**，实现**不得**声称在 fd 上保留了帧边界。

- 原表述与固件证据冲突：主数据通路是 `socketpair` 字节流（`analysis/07` C2；串表
  `Failed to send data to socket on pipe` `0x100acc42f`、`Failed to transmit data from socket on pipe`
  `0x100acc74f`），套接字上不存在"带长度的消息队列"。
- iAP2 消费者是否**需要**帧边界：**不需要**（iAP2 报文自带长度字段，见交接事实清单 F-11）；
  但该结论属 iAP2 side 的自证，本规范只保证"我们这边不提供、也不假装提供"。
- 完整的形态、缓冲与关闭语义见 `spec/08-handoff-contract.md`。

**R-6.29** 帧层**必须**向上层上报：设备标识、通道号、方向（入向/出向）、可用的数据通道句柄或回调、服务 UUID、N1。

**R-6.30** 上层**必须**自带报文完整性机制（长度 + 校验或重传）。帧层丢弃的帧不会重发，也不会通知是哪一帧。

**R-6.31** 安全（配对/加密）**不**属于 RFCOMM 层职责：RFCOMM 层**不得**以"未加密"为由拒绝 SABM，策略由上层在连接建立前或建立后施加。

## 6.7 一致性判据

1. 主动 DISC → 对端 UA → DLCI 释放；对端不回 → 超时后释放。
2. 被动 DISC → 本端回 UA → 资源释放；重复 DISC 幂等。
3. 复用器级 DISC → 会话断开中 + 定时器 + UA。
4. 命令帧长度不符 → 整条链路销毁且所有 DLCI 上报异常。
5. 清理顺序可观测：定时器先取消（无残留回调触发）。
6. 重连复用会话时**不**出现新的 DLCI 0 SABM。
7. 旧句柄操作返回明确错误。
8. 边界测试（回调通路）：一次回调 = 一个信息字段；**fd 通路不做此断言**——只要求上层能按报文自身长度切分
   （见 `spec/08` R-8.9/R-8.10 与一致性判据 1）。
