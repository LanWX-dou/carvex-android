# 00 范围、术语与约定

## 1. 本规范的范围

本规范定义**一台"被连接方设备"（以下称"设备"）**如何在经典蓝牙上：

1. 使自己可被发现、可被识别为支持无线 CarPlay / 无线 iAP 的设备；
2. 注册服务并在 SDP 中暴露服务记录（含 RFCOMM 通道号）；
3. 作为客户端查询对端 SDP、取得 RFCOMM 通道号；
4. 建立 RFCOMM 复用器与数据链路（DLCI）；
5. 收发 RFCOMM 数据、执行信用流控；
6. 断链、超时、重连与资源清理；
7. 把 RFCOMM 之上交付给 iAP2 层。

**不在范围内**：iAP2 报文格式、CarPlay 会话协议、蓝牙配对算法与密钥派生、L2CAP 层细节、HCI 层细节。

## 2. 平台无关性声明

本规范只描述**线上行为**（字节、时序、状态迁移、错误处理），不指定：

- 编程语言、运行时、线程模型；
- 蓝牙协议栈实现（自研或第三方）；
- 操作系统 API；
- 内存管理方式。

文中出现的"设备"“对端”“上层”均为角色名，不对应任何具体产品或进程。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 设备 | 实现本规范的一方（被连接方） |
| 对端 | 与本设备建立蓝牙连接的手机/主机 |
| 会话 | 一对设备之间的一条 RFCOMM 复用器实例（对应一条 L2CAP 通道） |
| DLCI | 数据链路连接标识，0 表示复用器控制通道，1–61 为数据通道 |
| 通道号 | 服务层使用的 RFCOMM 通道编号（0–30），SDP 记录中出现 |
| N1 | 单个 RFCOMM 信息字段的最大字节数（最大帧长） |
| 信用 | 基于信用的流控中，接收方授予发送方的"可发送帧"额度 |
| 信息字段 | RFCOMM 帧中地址/控制/长度之后、FCS 之前的部分 |
| 帧 | 一个完整的 RFCOMM 传输单元（地址+控制+长度+信息+FCS） |

术语沿用 TS 07.10 与蓝牙核心规范的命名，**仅作命名用途**；本规范的每个数值结论都以固件证据为准（见附录 A）。

## 4. 规范性用词

- **必须（MUST）**：不满足即判定为不符合本规范。
- **应当（SHOULD）**：除非有明确理由，否则必须满足；偏离时必须在实现文档中记录理由。
- **可以（MAY）**：可选。

## 5. 字节序约定（最容易出错，单列）

| 位置 | 字节序 | 说明 |
|---|---|---|
| EIR 中的 128-bit UUID 列表 | **小端**（LSB 在前） | 与 UUID 文本顺序相反 |
| EIR 中的 16-bit UUID 列表 | **小端** | 同上 |
| SDP 的 PDU 头、属性 ID、记录句柄、属性值中的整数 | **大端** | 网络序 |
| SDP 中的 128-bit UUID | **大端** | 与 UUID 文本顺序一致 |
| RFCOMM 地址字节 | 单字节位域 | bit0=EA, bit1=C/R, bit2–7=DLCI |
| RFCOMM 长度字段 | 单/双字节，bit0 为 EA 扩展位 | 值 = 原始值 >> 1 |
| RFCOMM FCS | 单字节 | 覆盖地址至信息字段 |

> 简记：**EIR 小端、SDP 大端**；同一 UUID 在两处的字节序列互为逆序。

## 7. 与实现无关的"必须同时成立"约束

以下四条是跨章节的硬约束，单独列出以免遗漏：

1. **字节序双轨**：同一 UUID 在 EIR 与 SDP 中字节序相反（第 5 节）。
2. **帧边界即交付边界**：RFCOMM 交付上层的单位是一个信息字段，不得假设报文与帧一一对应（06.4）。
3. **长度精确匹配**：接收帧的信息长度必须精确等于 `总长 - 头长 - 1`，否则整帧丢弃；复用器命令信息长度必须精确等于 `子长度 + 2`，否则整条链路拆除（05.4、05.7）。
4. **信用溢出即错误**：发送信用累加超过 16 位上限必须报错并中止（05.3）。
