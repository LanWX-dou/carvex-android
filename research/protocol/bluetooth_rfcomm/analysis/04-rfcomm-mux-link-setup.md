# 04 RFCOMM 复用器建立、DLCI 与信道协商

覆盖需求项：**（4）RFCOMM 服务端监听路径**、**（5）RFCOMM 客户端连接路径**、**（6）连接后状态变化**（连接阶段部分）。

## 1. 目标

1. DLCI 与"服务通道号（channel）"的换算公式。
2. 出向（客户端）连接做了哪些校验、参数从哪来。
3. 入向（服务端）SABM 的处理与拒收条件。
4. 帧格式与状态字节（SABM/UA/DISC/DM）的确切编码。
5. 复用器（DLCI 0）命令帧的长度校验与失败后果。

## 2. 结论

### C1 帧格式与 FCS 算法 `CONFIRMED`

组帧函数 `FUN_1003c5334(control, session, dlci)`（`0x1003c5334`）：

| 依据 | 内容 |
|---|---|
| C 行 42 | `uStack_44 = CONCAT22(1, CONCAT11(control, bVar6 | (dlci << 2))) | 0x1000` |
| 语义 | 字节 0 = 地址；字节 1 = 控制（`\| 0x1000` 置 bit4 = P/F）；字节 2 = `0x01`；字节 3 预留给 FCS |
| C 行 44 | `FUN_1003c6b60(&buf, 3)` → **CRC-8 表驱动 FCS**（见下） |
| C 行 45 | `uStack_44 = CONCAT13(fcs, uStack_44)` → 把 FCS 写入字节 3 |
| C 行 47 | `FUN_1003d8668(&buf, 4, 0)` → **OI_MBUF_Wrap**：把 4 字节栈缓冲包装成 MBUF 并发送 |
| C 行 50 | `FUN_1003c54f8(session, dlci, mbuf, 0)` 投递到会话发送队列 |

FCS 函数 `0x1003c6b60`（`PARTIAL`→算法已确认，用途由调用点确认）：

```
fcs = 0xFF
for each byte b: fcs = table[b XOR fcs]
fcs = ~fcs
```

其中 `table` 位于 `0x1009349a0`（256 字节 CRC-8 表）。这与 TS 07.10 的 FCS（CRC-8，多项式 0x07 的反向实现、初值 0xFF、末尾取反）一致。

FCS 范围：控制帧传长度 3（`0x1003c53d8`）；UIH 发送器传长度 2（`0x1003c592c`），接收端 `0x1003c6be4` 只用地址、控制与尾字节校验。因此 UIH 的长度、信用和载荷不进入 FCS。

**地址字节构成**：

```
bit0    EA     = 1（本实现恒为 1，即单字节地址）
bit1    C/R    = bVar6 & 2
bit2-7  DLCI   = dlci
```

`bVar6` 在 D=0 时的取值（必须保留 C 行 29–41 的外层角色条件）：

```
bVar6 = 3（EA=1, C/R=1）  若 control ∈ {0x63(UA), 0x0F(DM)}
bVar6 = 1（EA=1, C/R=0）  若 control ∈ {0x2F(SABM), 0x43(DISC)}
```

以上伪代码仅是 D=0 分支，不能丢掉 `session+0xc` 的条件。完整真值表：D=0 时命令 C/R=0、响应 C/R=1；D=1 时命令 C/R=1、响应 C/R=0（`0x1003c538c`–`0x1003c53bc`）。

**长度字段**：字节 2 的值为 `0x01`。按 TS 07.10，长度字段每个字节的 bit0 是 EA 扩展位，值需右移 1 位，因此 `0x01` = **长度 0**（无误）。这解释了"连接类帧信息字段为空"。

### C2 控制码取值集合由断言白名单强制 `CONFIRMED`

C 行 25–28：

```c
if (((0x34 < param_1 - 0x2fU) ||
    ((1L << ((param_1 - 0x2fU) & 0x3f) & 0x10000000100001U) == 0)) && (param_1 != 0xf)) {
  FUN_1000f9438();   // 断言失败
}
```

`0x1000000_0100001` 的置位位是 bit0、bit20、bit52：

| 偏移 | 控制码 | TS 07.10 含义 |
|---|---|---|
| 0 | `0x2F` | SABM |
| 20 | `0x43` | DISC |
| 52 | `0x63` | UA |
| 显式 | `0x0F` | DM |

因此本函数**只能**发送 SABM/UA/DISC/DM 四种连接控制帧；PN/RPN/MSC/TEST 等复用器命令走另一条路径（见 C6）。

### C3 DLCI 换算公式 `CONFIRMED`

出向连接（`0x1003c2b00`，C 行 64）：

```c
FUN_1003c14dc(session, (session[0xc] | (channel << 1)) ^ 1, &dlci_rec);
```

即：

```
DLCI = (session_flag | (channel << 1)) ^ 1
```

| `session_flag` | 结果 |
|---|---|
| 0 | `DLCI = 2*channel + 1` |
| 1 | `DLCI = 2*channel` |

入向连接用反向关系（`0x1003c1404` C 行 29）：

```c
if (*(byte*)(server_table + i*0x38 + 0x1a) == (dlci >> 1))   // channel = dlci >> 1
```

因此 **DLCI 的低位 bit0 与 `session_flag` 互斥**，服务通道号恒为 `DLCI >> 1`。`session_flag` 为 0 时占奇数 DLCI，为 1 时占偶数 DLCI。

出向复用器初始化 `0x1003c1dd4`–`0x1003c1dd8` 明确写 D=1，因此新复用器发起方连接远端服务使用偶数 DLCI；既有复用器须沿用 D。

### C4 出向连接 `OI_RFCOMM_Connect` 的校验与参数 `CONFIRMED`

函数 `0x1003c2b00`，日志 `OI_RFCOMM_Connect failed`。

| 依据 | 内容 |
|---|---|
| C 行 40–44 | `uVar10 = param_5`；若 `uVar10 != 0 && (uVar10 <= param_6 \|\| param_6 == 0)` 通过，否则返回 `0x38e` |
| C 行 60 | `FUN_1003c1d40(session, param_5)` 设置会话级最大帧长 |
| C 行 64 | 分配/查找 DLCI 记录 |
| C 行 67 | `dlci[0x48] = param_1`（响应回调） |
| C 行 68 | `dlci[0x28] = param_2`（控制回调块，含两个函数指针） |
| C 行 69 | `dlci[0x10] = (uint16)param_5` → **N1 = 最大帧长** |
| C 行 71 | `*param_7 = *(uint16*)(dlci + 8)` → 返回 DLCI 给调用者 |
| C 行 75–77 | `dlci[0xa0] = param_6 / param_5` → **初始信用额度 = 信用窗口字节数 / 帧长** |
| C 行 78 | `dlci[0x30] = param_8`（上下文） |
| C 行 80 | `FUN_1003c20b8(...)` 在会话已打开（状态 7）时立即发 SABM |

`param_5 <= param_6` 的校验等价于"N1 不能大于信用窗口"，这是防溢出的边界检查。

实际参数（WiAP 出向，来自 `0x1007a3ba4` C 行 134–135）：

```
FUN_1003c2b00(cb, &cfg, device+0x80, channel, 0x3EF, 0x3B01, &out, &ctx)
                                     param_4  param_5 param_6
```

因此 **WiAP 出向连接：N1 = 0x3EF = 1007 字节，内部信用窗口容量 = 0x3B01 / 0x3EF = 15（不能直接当作 PN 的 3 位线上信用）**。

### C5 入向 SABM 的处理与五道拒收条件 `CONFIRMED`

函数 `0x1003c5c70`（C 中与 `0x1003c59a0` 同族，逐条对照 `.s` 已复核）。

处理顺序（每步失败即静默返回或发 DM）：

| 序 | 条件 | 依据（汇编） |
|---|---|---|
| 1 | `addr bit0 (EA) == 1` | `0x1003c5c8c: tbz w22,#0` |
| 2 | `control bit4 (P/F) == 1` | `0x1003c5c94: tbz w8,#4` |
| 3 | `(addr.C/R == 0) == session[0xc]` | `0x1003c5c9c–0x1003c5cac: tst w22,#2; cset eq; eor w8,w9,[x0,#0xc]; tbnz` |
| 4 | 会话状态必须为 7 才继续；否则按状态 4 / 其他分支处理 | `0x1003c5cbc: cmp w8,#7` |
| 5 | `addr < 0xF8` 且 `DLCI != 1` | `0x1003c5cf4: cmp w22,#0xf7; b.hi` + `cmp w20,#1; b.eq` |

通过后：

| 依据 | 动作 |
|---|---|
| `0x1003c5cd4` 起 | DLCI 状态为 4 且 `addr <= 3`（DLCI 0）→ 发 UA（`FUN_1003c5334(0x63, session, dlci)`）并把会话状态置 7（`*session = 7`）→ 复用器建立完成 |
| 其他 | 走 DLCI 分配：`FUN_1003c136c`（查找）→ 已存在且状态 6 则发 DM；否则 `FUN_1003c1404`（分配） |
| C 行 224（`0x1003c5d6c` 附近） | 新建 DLCI 记录：`state = 3`、`dlci[0xa] = dlci` |
| C 行 229 | `FUN_1003c2314(session+6, addr>>3, dlci[0x10], dlci[8])` 查注册的服务回调 |
| 失败 | 日志 `No registered server on DLCI %d, rejecting incoming link`，`dlci[0xa4] = 0x399`，`FUN_1003c16dc(dlci, 0)` 发 DM |
| 成功 | 直接返回（由注册回调负责后续 UA 与端口协商） |

注意 `0x399` = 921，结合日志文本可判为"该 DLCI 上没有注册的服务端"错误码（名称映射见 `OPEN-RF-2`）。

### C6 复用器命令帧的长度校验与失败后果 `CONFIRMED`

分发函数 `0x1003c73f0(session, info_ptr, info_len)`：

| 依据 | 内容 |
|---|---|
| C 行 93 | `bVar1 = info[0]` = 命令码；`uVar17 = bVar1 & 0xfc`（去掉 C/R 两位后的命令基值） |
| C 行 96–99 | `bVar4 = info[1] >> 1` = 子长度；`if (info_len != bVar4 + 2)` → **不匹配即强制断链** |
| C 行 105 | 日志 `Invalid RFCOMM packet received, command (%d), force disconnect the link` |
| C 行 114 | `FUN_100316bbc(session + 6)` 执行断链（不是发 DM，而是整条链路拆除） |

含义：复用器命令帧的信息字段为 `[command][len][data…]`，且 `len` 字段同样带 EA 位（`>>1` 才是值）；信息字段总长必须**精确**等于 `2 + 子长度`，多一字节或少一字节都会导致链路被拆。

### C7 DLCI 记录的初始化值 `CONFIRMED`

`FUN_1003c14dc`（`0x1003c14dc`，分配 0xA8 字节）：

| 字段 | 初值 | 依据 |
|---|---|---|
| `+0x08` | DLCI（uint16） | C 行 37 |
| `+0x0a` | DLCI（byte） | C 行 39 |
| `+0x0c` | `0x8C` | C 行 42 |
| `+0x10` | `0x7F`（127） | C 行 41 → **默认 N1 = 127** |
| `+0x14` | 0（出向）/ 1（入向，由 `0x1003c1404` 覆盖） | C 行 34 / `0x1003c1404` C 行 36 |
| `+0x16..` | `0x03033F7F`（8 字节） | C 行 45 |
| `+0x1e` | `0x01011311`（4 字节） | C 行 46 |
| `+0x58` | 0 | C 行 40 |
| `+0x68` | 0 | C 行 43 |
| `+0xa2` | 0 | C 行 44 |
| `+0x80` | 会话指针 | C 行 38 |
| 重复 DLCI | 返回 `0x38F`（911） | C 行 55 |

`+0x16`/`+0x1e` 这两组常量位于 RPN（Remote Port Negotiation）参数字段区，`0x01011311` 拆成 `11 13 01 01`，与 RPN 的"波特率/数据位/停止位/校验"编码位置吻合（`PARTIAL`，未与 RPN 命令的数据结构逐字段对照，见 `OPEN-RF-3`）。

**C8.2 未知命令的响应** `CONFIRMED`

`0x1003c7750`–`0x1003c7774`：`mov w8,#0x311`（内存里小端即 `11 03`）与 `and w8,w23,#0xfe`，然后 `0x1003c5884(mux, 0, buf, 3, 0)` 发送。即回一帧 **NSC（`0x11`）**，信息字段为 `11 03 <原命令码 & 0xFE>`（长度字节 `0x03` → 1 字节数据）。

注：`0x311` 不是状态码，而是"`0x11` 命令 + `0x03` 长度"这两个相邻字节被一次性以小端半字写入栈缓冲；早期把 `0x311` 当状态码的读法是错的。

**C8.3 PN（`0x83`/`0x81`）载荷字段** `CONFIRMED`

| 依据 | 内容 |
|---|---|
| `0x1003c7644` | `cmp w22, #8; b.ne` → **数据区必须正好 8 字节** |
| `0x1003c764c` | `ldrb w8, [x21, #2]`；`and w20, w8, #0x3f` → 载荷[0] = DLCI（掩码 6 位） |
| `0x1003c7654` | `cmp w20, #1; b.eq` → DLCI=1 非法 |
| `0x1003c765c` | `cmp w20, #0x3e; b.hs` → DLCI ≥ 0x3e 非法（有效 0…0x3d） |
| `0x1003c7668` | 载荷[1] → 帧类型字节，`0x1003c7ff4` 与 `0xf0` 比较 |
| `0x1003c766c` | 载荷[2] → 优先级，`0x1003c7ebc` 用 `and #0x3f` 后传出 |
| `0x1003c7670` | `ldrh w24, [x21, #6]` → 载荷[4..5] = **最大帧长 N1（16 位小端）** |

**载荷内未被读取的字节**：载荷[3]（`info[5]`，规范中的 ack timer）与载荷[6]（`info[8]`，规范中的 max retrans）在该函数内**没有读取点**（已对全函数做寄存器/偏移穷举）。因此本实现对这两个字段**忽略**，而不是校验。

**C8.6 非法长度导致崩溃（不是回错误）** `CONFIRMED`

`0x1003c7508`/`0x1003c75a8` 的错误路径会经 `0x10000d938`（内部诊断开关）判断后，调用 `0x10000e9d4` 分配缓冲、`0x10090b650` 格式化、`0x10018f150` 终止进程。即：**MSC/RPN 长度不足在带内部诊断的构建上直接崩溃**，而不是回 DM/错误帧。这是必须知道的移植影响。

| `0x100061474` | `0x1000615dc(slot, timeout)` 计算到期 |

**C9.2 到期时刻的算术** `CONFIRMED`

`0x1000615dc`（180 字节）逐条：

| 依据 | 内容 |
|---|---|
| `0x100061604` | `0x100035440(&ts)` 取当前时间 |
| `0x10006160c`–`0x10006162c` | `now = ts.us × 10 + (ts.ns_rem + 99) / 100`（除以 100 用魔数 `0x51EB851F … asr #37`，已验证精确） |
| `0x100061638` | `add w8, w19, w21` → `u16 expiry = now + timeout` |
| `0x10006163c` | `strh w8,[slot+2]` —— 到期值只有 **16 位**，按 65536 回绕 |
| `0x100061670`–`0x100061678` | `mul w0,w19,#0x64` → `blraaz [0x100c39fb8]` —— **平台钩子收到 timeout × 100** |

`0x100035440` 是时间源，其单位可判定：

| 依据 | 内容 |
|---|---|
| `0x1000354e4` | `bl 0x10090a9a0`；该桩经 GOT 槽 `0x100bfb058` 跳转，链式修正项的导入序号 873 = **`_mach_absolute_time`** |
| `0x1000354e8` | `ldp w8,w9,[x20]` = `mach_timebase_info` 的 numer/denom（`0x10090aa30` = 导入序号 882 = `_mach_timebase_info`） |
| `0x1000354ec` | `ticks × numer / denom` = **纳秒** |
| `0x1000354f4`–`0x10003550c` | `>>3` 后乘魔数 `0x20C49BA5E353F7CF` 再 `>>4`；Python 验证该序列精确等于 **÷125** ⇒ `ns/1000` = **微秒** |
| `0x100035510`–`0x100035518` | `msub w8, w9, #1000, w8` ⇒ 第二字段 = `ns % 1000` |
| `0x10003551c` | 输出结构 = `{u32 微秒, u16 纳秒余数}` |

**C9.3 单位结论：毫秒（已确认）** `CONFIRMED`

上一轮遗留的"三选一"已由钩子与其消费者的调用链排除。链路如下（每步都有汇编依据）：

| 依据 | 内容 |
|---|---|
| `0x100290ce4`–`0x100290d00` | `x16 = 0x100061690`（`paciza`）→ `mov x1,x16` → `bl 0x100312584`：**平台钩子 = `0x100061690`** |
| `0x1003125a8` | `mov x21, x1` → 钩子经参数下传 |
| `0x100312690` | `mov x0,#0; mov x1,x21; bl 0x1003d7f28` → 进入定时器模块 init |
| `0x1003d7f28` | init：按配置项分配 `count×24` 字节槽表存入 `0x100c39fb0`，`strh 0xFFFF` 初始化，最后 `0x1003d8044: str x19,[x8,#0xfb8]` → **把钩子写入 `0x100c39fb8`** |
| `0x1000616a0`–`0x1000616d8` | 钩子本体：`pthread_mutex_lock`（`0x10090b990`）→ `str w19(=timeout×100),[0x100c25cc8]` → `pthread_cond_signal`（`0x10090b8f0`）→ unlock |
| `0x100061070`–`0x1000610a0` | 定时器线程读该值：`ldr w8,[0x100c25cc8]` |
| `0x100061080` | `umull x9,w8,#0x10624DD3` + `lsr #0x26` = **÷1000** |
| `0x100061088` | `msub w8,w9,#1000,w8` = **%1000** |
| `0x10006108c` | `mul w8,w8,#0xF4240` = **×1,000,000**（毫秒 → 纳秒） |
| `0x100061090` | `stp x9,x8,[sp]` = `timespec{ tv_sec = v/1000, tv_nsec = (v%1000)×1e6 }` |
| `0x1000610a0` | `bl 0x10090b900`；该桩经 GOT 槽 `0x100bfb3c8` 解析为 **`_pthread_cond_timedwait_relative_np`**（相对超时版） |
| `0x1000610a4` | `cmp w0,#0x3c`（`ETIMEDOUT`）→ 超时后重新扫描槽表 |

**结论：钩子参数的单位是毫秒。** 因此

```
超时值 30（默认） → 钩子收到 30 × 100 = 3000 ms = 3.000 s
```

由此还可以反推两件事：

1. C9.2 里的 `u16 expiry = now(10 µs 单位) + timeout` **不是真正的计时依据**，只用于槽位排序/陈旧标记；真正的等待由 `pthread_cond_timedwait_relative_np` 承担。这也解释了 0.655 s 的 16 位回绕为何不致命。
2. 超时值每单位 = 100 ms，因此上限 `0x7FFF` 单位 ≈ **54.6 分钟**；`tbnz w22,#0xf` 的拒绝阈值由此得到含义。

**C9.4 配置覆盖** `CONFIRMED`

`0x1003c6284` 取配置项 `50`，`+0xA` 处 16 位值非 0 时即覆盖默认 30（`csel`）。也就是说超时对每次连接可调，单位同样是"100 ms/单位"（该值随后经同一条 `×100` 路径变成毫秒）。
