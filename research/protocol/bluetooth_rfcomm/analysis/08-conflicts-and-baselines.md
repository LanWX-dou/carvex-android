# 08 基线对照：旧文档与既有程序

覆盖需求项：**（11）与旧文档差异**、**（12）与既有程序差异**。

| 需求项 | 用户决策 | 本套文档状态 |
|---|---|---|
| （11）与旧文档的差异 | "不对照旧文档" | `N/A-BY-DECISION` |
| （12）与既有程序的差异 | "本轮不比程序""先把静态的做出来" | `N/A-BY-DECISION` |

因此本文件**不提供**逐条差异表。下面保留模板与"若将来对照时的操作规则"，并另设一节记录**本固件与常见公开描述不一致处**（这类内容不需要旧文档作为输入，属于固件自身证据）。

## 2. 若将来对照旧文档：强制规则

1. 逐条列出"旧文档结论 / 固件证据 / 是否一致 / 差异原因"。
2. 不一致时**并列陈述**，不得删除或改写旧文档原文，不得静默以其为准。
3. 旧文档若给出无固件依据的结论，标 `OPEN`，不得直接采信。
4. 差异条目必须带函数地址与汇编行，否则视为无证据。

模板：

```
| 编号 | 旧文档结论（引原文与位置） | 固件证据（函数地址 + 汇编/C 行） | 判定 | 差异说明 |
|---|---|---|---|---|
| D-001 | … | … | 一致 / 冲突 / 旧文档缺证据 | … |
```

## 3. 若将来对照既有程序：强制规则

1. 只**记录**，不修改对方代码。
2. 对照维度固定为六项：发现/广播、SDP 记录内容、通道号取得方式、RFCOMM 帧构造、信用流控、拆链策略。
3. 每项给出"对方实现位置（文件:行）/ 本固件行为 / 差异 / 互操作风险"。
4. 不得以"对方能连通"作为协议正确性的证据。

模板：

```
| 编号 | 项目 | 对方实现 | 本固件行为 | 差异 | 互操作风险 |
|---|---|---|---|---|---|
| P-001 | 通道号 | … | DLCI = (session_flag | ch<<1) ^ 1 | … | … |
```

## 4. 本固件与常见公开描述的不一致处（固件证据，非旧文档对照）

以下记录差异与勘误；不能把反编译的命名误读当作协议差异。

| 编号 | 常见预期 | 本固件实际行为 | 证据 |
|---|---|---|---|
| F-001（勘误） | 收到 DISC 应回 UA | 固件也是 UA：十进制 99 = `0x63`，置 P/F 后 `0x73`；旧版误标为 DM | `06` C2，`0x1003c6330` / `0x1003c62ac` |
| F-002 | 上层拿到的"MTU"是 L2CAP MTU | `kCBMsgArgMTU` 实际传的是 **RFCOMM 最大帧长 N1** | `05` C9，`0x10040c934` C 行 66 + 日志文案 `frameSize` |
| F-003 | 128-bit UUID 在各处字节序一致 | EIR 中为**小端**，SDP 记录中为**大端** | `01` C3、`02` C5 |
| F-004 | 复用器命令长度不符时回 DM 或丢弃 | 直接**销毁底层 L2CAP 通道**（整条链路） | `06` C4，`0x1003c73f0` C 行 114 |
