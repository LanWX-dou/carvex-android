# 06 断链、超时、重连与资源清理

覆盖需求项：**（9）断开 / 超时 / 重连 / 清理**。

## 1. 目标

1. 主动断链（发 DISC）与被动断链（收 DISC）的差异。
2. 拆链的两级：DLCI 级与复用器（会话）级。
3. 超时定时器的存在、默认值与未定单位。
4. 错误状态码的传播路径。
5. 重连时的会话复用条件。

## 2. 结论

### C1 主动断链：发 DISC 后 DLCI 进入状态 6 `CONFIRMED`

复用 `FUN_1003c5334`（`04` C2 的白名单只允许 4 种控制码），传 `control = 0x43`：

| 依据 | 内容 |
|---|---|
| C 行 80–89 | `if (control == 0x2F) dlci[0x0d] = 2;` 否则 `if (control == 0x43) dlci[0x0d] = 6;` |
| C 行 79 | `dlci[0x0b] = control`（记录最后一次发出的控制码） |
| C 行 91 | `FUN_1003c6c18(session)` 触发发送 |

即"已发 DISC、等对端 UA"由 DLCI 状态 6 表示。

### C2 被动断链：先回 UA，再按状态分派 `CONFIRMED`

收包侧（`0x1003c59a0`，DISC 分支 C 行 374 起）：

| 依据 | 内容 |
|---|---|
| C 行 382–383 | 要求 `addr bit0 = 1`、`ctrl bit4 = 1`、`(addr.C/R == 0) == session[0xc]` |
| C 行 385 | 要求 `addr < 0xF8` 且 `dlci != 1` |
| C 行 386 | 会话状态 7 时分数据/复用器路径；其他状态跳到 UA 发送分支 |
| C 行 407–408 | `addr > 3`（非 DLCI 0）：先查找 DLCI，查找失败返回；查到后 `FUN_1003c5334(99, …)` 回 **UA(0x63)** |
| C 行 411–413 | DLCI 状态已是 6 → 直接返回（对端点重复 DISC 幂等） |
| C 行 414–419 | DLCI 状态 5 → 置 7 并返回 |
| C 行 436–446 | 否则置 8，若发送失败 → `FUN_1003c16dc(0,0)` 并回调状态 `0x39F` |
| C 行 448–456 | `addr <= 3`（DLCI 0，复用器级 DISC）：超时值取 `*(short*)(cfg+10)`，缺省 `0x1E`；`*session = 8`；`FUN_1003c518c(session, ticks)` 启动定时器 |
| C 行 462 | 随后 `FUN_1003c5334(99, …)` 发 UA 回应 |

要点：99 十进制 = `0x63`（UA），不是 DM；发送器再置 P/F 后线上控制为 `0x73`。不存在这里所称的“用 DM 确认 DISC 的 Apple 特例”。

### C3 拆链的两级与顺序 `CONFIRMED`

DLCI 级释放 `FUN_1003c16dc(dlci, report)`（`0x1003c16dc`）：

| 顺序 | 动作 | 依据（C 行） |
|---|---|---|
| 1 | 断言 dlci 及其所属会话非空 | 17–24 |
| 2 | `FUN_1003d94a8(dlci[0x38])` 取消该 DLCI 的定时器 | 25 |
| 3 | `FUN_1003d84bc(dlci+0x90)` 从链表中摘除 | 26 |
| 4 | 若 `dlci[0x88] != 0` → `FUN_1000609fc()` 并清零（释放挂起的缓冲/回调） | 27–30 |
| 5 | `FUN_1003c15f0(dlci)`、`FUN_1003c4d8c(dlci)`（协议层收尾） | 31–32 |
| 6 | 若 DLCI 链表已空且 `report != 0` → `FUN_1003c1788(session, 0, dlci[0xa4])`：**用错误码 `dlci[0xa4]` 通知会话"最后一条通道关闭"** | 33–35 |
| 7 | `FUN_1000110b8(dlci)` 释放内存 | 41 |

错误码保存在 `dlci[0xa4]`：入向无服务端时写 `0x399`（`04` C5），其它路径写 `0x39F`/`0x3A5`/`0x3A6`/`0x3A1`（C2 与后续分支）。

### C4 复用器级强制拆链（协议违规的惩罚）`CONFIRMED`

| 触发 | 函数 | 依据 |
|---|---|---|
| 复用器命令帧信息长度与子长度不符 | `FUN_100316bbc(session + 6)` | `0x1003c73f0` C 行 105–114，日志 `Invalid RFCOMM packet received, command (%d), force disconnect the link` |
| 外部强制断开 | 日志 `forcing disconnect` | `0x100296714` 引用 `s_...`，见 `OPEN-RF-11` |

注意 `session + 6` 是会话内的 L2CAP 通道句柄区起点；即"强制拆链"是**销毁底层 L2CAP 通道**，不是发 RFCOMM 帧。后果是该会话上所有 DLCI 一起失效。

### C5 超时的存在与取值 `PARTIAL`

| 依据 | 内容 |
|---|---|
| C 行 450–453 | `sVar2 = 0x1E; if (*(short*)(cfg + 10) != 0) sVar2 = *(short*)(cfg + 10);` |
| C 行 455 | `FUN_1003c518c(session, sVar2)` 启动会话级定时器 |
| 语义（推断） | `0x1E` = 30；作为"等 DISC 完成/等 UA"的超时值 |

单位已由后续补证确定为 **100 ms/单位**（`analysis/04` C9.3）：默认 30 → **3.000 s**。`OPEN-RF-12` 已关闭。超时值来自配置结构 `+0x0A`，可被外部覆盖。

DLCI 级同样有定时器（`dlci[0x38]` 句柄，C3 步骤 2 取消），其值与用途见 `OPEN-RF-13`。

### C6 重连：会话复用与"链路句柄"查找 `PARTIAL`（节奏见 C8）

| 依据 | 内容 |
|---|---|
| `0x1003c1964` | 出向连接时按链路/设备查找**已存在会话** |
| `0x1003c1eac` | 复用已有会话的分支（`0x1003c20b8` 直接发 SABM） |
| `0x1003c1f78` | 分配新会话 |
| `0x1003c2d6c` | 无会话时的分支 |
| `0x1003c2b00` C 行 80 | 若会话状态已为 7 → 立即发 SABM（跳过复用器建立） |
| `0x1003c2394` + 日志 `OI_RFCOMM_Accept - linkhandle %d not found` | `OI_RFCOMM_Accept` 用 32 位链路句柄反查会话；查不到即失败 |
| 日志 `OBEX server RFCOMM disconnect on bogus link handle %x %!` | 同上，旧句柄会失败 |

即：**重连优先复用同设备的现有会话**；只要会话还在状态 7，新通道直连发 SABM，不重建复用器。若会话已销毁，则必须从 L2CAP 建立重新开始。

### C7 错误状态码传播链 `PARTIAL`

| 码 | 出现位置 | 语义（据上下文） |
|---|---|---|
| `0x399` (921) | 入向无注册服务端 | 该 DLCI 上没有服务 |
| `0x39A` (922) | 信用累加溢出 | 信用计数越界 |
| `0x39F` (927) | DISC 后发送失败、`dlci[0xa4]` | 断链应答发送失败 / 通道已断 |
| `0x3A1` (929) | 期望中却收到 DM | 对端异常断开 |
| `0x3A5` (933) | 状态 5 发 UA 失败 | 端口协商阶段发帧失败 |
| `0x3A6` (934) | 收到"非期望的远端拒绝" | 对端拒绝 |
| `0x38E` (910) | 出向连接参数非法 | baudrate/N1 参数越界 |
| `0x38F` (911) | DLCI 已存在 | 重复分配 |
| `0x65` (101) | 空参数 | 参数为空 |
| `0x6A` (106) | 内存分配失败 | 无内存 |

### C8 重连节奏与重试上限 `CONFIRMED`

补证轮次新增。目标：回答"断链后重连是否有退避、上限多少"（`OPEN-RF-15`，本轮**已关闭**）。

**C8.1 RFCOMM 层自身不重连** `CONFIRMED`

| 依据 | 内容 |
|---|---|
| `0x1003c6180` | 会话状态 7 遇断链 → 置状态 8 并启动 **3 s** 定时器（C5/C9.3） |
| `0x1003c5264`（定时器回调） | 到期后直接销毁会话：**没有重试计数、没有再次 connect 的分支** |
| `0x1003c2b00` | 出向连接只在被调用时执行一次；失败即返回错误码 |

即：**RFCOMM 层不做自动重连**，重连节奏由基带/连接管理层的 "Scan Core Page Scan" 模块决定。

**C8.2 重试计数与上限 = 5 次** `CONFIRMED`

| 依据 | 内容 |
|---|---|
| `0x1005fcb20` | `ldrb w19,[x19,#0x647]` —— 每设备的重试计数是 `u8 @ dev+0x647`（`0x1005fcaf8` 原样返回该字节） |
| `0x1001483d4`–`0x1001483dc` | `w0 = 计数; cmp w0,#4; b.hi` —— **计数 > 4 即判超限**（允许 0…4 共 5 次尝试） |
| `0x10014811c`–`0x100148140` | 另一条超限分支：`cmp w21,#0xa` 等条件后再判断 |
| `0x100148338` / `0x100148608` | 超限时打印 `0x100b19d73` / `0x100b19e5b`："Reached max Scan Core Page Scan retries for Device '%s'" |
| `0x1001483d0`–`0x100148478` | 未超限：重设基线 RSSI（仅在计数 ≤ 3 时，`cmp w0,#3; b.hi`） |

**C8.3 固定步长的两个定时器** `CONFIRMED`

| 依据 | 内容 |
|---|---|
| `0x100148424`–`0x10014843c` | 设备不在集合中时：插入并 "resetting timer for **%d** seconds"，常量 `#0x3c` = **60 s**（日志串 `0x100b19df6`） |
| `0x100147fac` / `0x10014827c` | `mov w1,#0x3c; bl 0x100139d70(dev, 60)` —— 页扫描定时器按 **60 s** 重设 |
| `0x1005fcc98`–`0x1005fccb8` | 退避定时器：`x1 = 0x45D964B800` = **300×10⁹ ns = 300 s**，`dispatch_source_set_timer(src, 300 s, never, 0)` |
| `0x1005fcc4c` | 同一函数的日志常量 `#0x12c` = 300，与 `0x100b07fdc` "Start Scan Core Page Scan backoff timer of 300 seconds" 一致 |
| `0x100148644` | 该退避定时器的唯一调用点（设备连接失败分支） |

**C8.4 连接请求看门狗：8 s 或 16 s** `CONFIRMED`

| 依据 | 内容 |
|---|---|
| `0x1005fcec0` | `w8 = 0x3B9ACA00`（10⁹）；`umull x1, w20, w8` → **秒 × 10⁹ ns** |
| `0x1005fced8`–`0x1005fcee4` | `dispatch_source_set_timer(src, now + 该值, never, 0)` |
| `0x100642c44` | `mov w21,#0x10`（16） |
| `0x100642c90`–`0x100642c94` | `mov w8,#8` + `csel w21, w8, w21, eq` —— 条件成立取 **8 s**，否则 **16 s** |
| `0x100642d9c` | `bl 0x1005fcd8c(dev, w21)` 启动看门狗 |
| `0x100b1363e` | 日志："… using watchdog stall timeout as **%d** seconds" |

**C8.5 结论：固定步长 + 硬上限，无指数退避** `CONFIRMED`

- 在这条重连路径上**没有**任何按次数增长的等待（无 `1<<n`、无 `×2`、无按计数索引的延迟表）；等待值是常量 **60 s / 300 s**，看门狗是常量 **8 s / 16 s**。
- 重试次数被硬性限制为 **5 次**，超限即放弃并把设备移出集合（日志 "Reached max … retries"）。
- 因此 `OPEN-RF-15` 已关闭：答案不是"指数退避"，而是"**固定等待 + 最多 5 次**"。

**C8.6 边界** `CONFIRMED`

以上是**基带/连接管理层**的节奏。`CarPlay/WiAP` 应用层在什么条件下重新发起连接（例如用户操作、配件重新上电）不在 RFCOMM 范围内，也不影响本层的时序参数。

## 3. 对实现的约束（进入 spec）

1. 断链必须先取消定时器、摘除链表、释放挂起缓冲，最后释放记录；顺序颠倒会留下悬空回调。
2. 收到合法且对应记录存在的 DISC 回 UA；记录已删除时不保证重复应答，清理/回调仍需幂等。
3. 复用器级协议违规（长度不符）应直接销毁底层链路，而不是逐通道断开。
4. 超时值必须可配置；缺省 30 单位 = **3.000 s**（100 ms/单位，已确认，见 `analysis/04` C9.3）。
5. 重连应优先复用状态 7 的会话。
6. 重连节奏用**固定等待 + 硬上限**：页扫描 60 s、退避 300 s、看门狗 8/16 s、最多 5 次尝试；不要引入无上限重试。
