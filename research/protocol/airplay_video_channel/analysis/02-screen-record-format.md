# 02 屏幕记录格式（128 字节头）

> 本文件回答第 3、4 项覆盖要求：屏幕流上的数据单元长什么样、长度字段多宽、记录有几种、时间戳怎么排。
> 所有偏移量都来自 `_screenstream_dequeueAndProcessSampleBuffer`（`0x2519b0014`）与 `_sbpd_createConfigBBuf`（`0x251b43fcc`）的原始指令。

## 02.1 共同外形

一条记录 = **128 字节头（`0x80`）+ 载荷**。头的分配在帧路径是 `calloc(1, 0x80)`：

| 指令 | 含义 |
|---|---|
| `0x2519b0e70` `mov w0, #1`；`0x2519b0e74` `mov w1, #0x80`；`0x2519b0e80` `bl #0x2580f6280` | 头固定 128 字节 |
| `0x2519b0e88` `str w23, [x0]` | +0x00 写长度 |
| `0x2519b0e8c` `strb wzr, [x0, #4]` | +0x04 写记录类型 = 0（帧） |

配置记录走 `_sbpd_createConfigBBuf`，同样 `0x80`（`0x251b44068` `mov w1, #0x80`；`0x251b44074` `bl #0x2580f6280`）。

## 02.2 帧记录（类型 0）

| 偏移 | 宽度 | 写入指令 | 已证语义 | 未证/备注 |
|---|---|---|---|---|
| `+0x00` | u32 | `0x2519b0e88` | 累计body长度，不含128B头 | 含额外长度及可选尾段，不能称明文长度，见06.4 |
| `+0x04` | u8 | `0x2519b0e8c` | 记录类型 = **0**（帧） | — |
| `+0x05` | u8 | `0x2519b1048` | bit7经+45c来自APInterestingFrame；bit4经+45d来自NotSync输出（analysis07） | 附件派生不是NAL IDR证明；forceKeyFrame因果链仍OPEN-VID-7 |
| `+0x08` | u64 | `0x2519b0f8c` | 网络时间戳（由流对象上的时间上下文转换得到，调用点 `0x2519b0f00` `blraa`） | 时间基准未闭合（`OPEN-VID-9`） |
| `+0x10` | u64 | `0x2519b0f98` | 来自 `[流对象+0x3e0]` 的 64 位值 | 语义未定 |
| `+0x18` | u32 | `0x2519b0f9c` `stp wzr, w27` | 恒 0 | — |
| `+0x1c` | u32 | 同上 | 可选尾段长度加storage+3a8；无尾段时为0 | 接收侧以E划分第二段；额外项来源待核，见06.4 |
| `+0x20` | u64 | `0x2519b1034` | 第二次时间转换结果 | 与 `+0x28`/`+0x58` 同源 |
| `+0x28` | u64 | `0x2519b0f90` | 第一次时间转换结果（`extr` 拼接） | — |
| `+0x58` | u64 | `0x2519b105c` | 与 `+0x20` 相同的值 | 重复存放 |
| `+0x60`–`+0x7f` | u16×16 | `0x2519b1118` `strh w28, [x22]` | **帧间隔数组**（毫秒），最多 16 项，`0xffff` 截断 | 数组来源 `[流对象+0x3e8]`，长度 `[+0x458]` |

### 02.2.1 帧间隔数组的填法（可照做）

循环（`0x2519b1090`–`0x2519b1128`）：

```text
i = 1
while i < count([流对象+0x458]) and i <= 16:
    d = UpTicksToMilliseconds(ts[i] - ts[i-1])  # 10ac sub，10b0调用
    if d >= 0x10000:              # 0x2519b10b8 cmp #0x10<<12
        记录 "bad timestamp" 日志，d = 0xffff
    header[0x60 + 2*(i-1)] = u16(d)
    i += 1
```

- 转换结果 **≥65536 ms**（`0x10000`）时写成`0xffff`（`0x2519b1110`），65535ms也自然编码为0xffff；原稿4096阈值错误；
- 数组**最多 16 项**：循环上限 `cmp x19, #0x11`（`0x2519b1124`），即 i 从 1 到 16；
- 数组记录转换后的相邻时间差，不是绝对时间；16槽不证明每批最多16个视频访问单元。

### 02.2.2 加密紧跟头之后

`0x2519b1160`调用包装器；存在可选尾段时12f0再次调用。记录拼装成功后+470按u32加1，
不证明网络发送成功，也不是nonce。头/载荷独立传参，详见03及06。

## 02.3 配置记录（类型 1）

`_sbpd_createConfigBBuf` 的写入序列（全部指令）：

| 偏移 | 宽度 | 指令 | 值/语义 |
|---|---|---|---|
| `+0x00` | u32 | `0x251b4407c` `str w21, [x0]` | 配置载荷长度（来自 display 配置的 CFData 长度） |
| `+0x04` | u8 | `0x251b44080` `strb w23, [x0, #4]`，`w23 = 1`（`0x251b44060`） | 记录类型 = **1**（配置） |
| `+0x05` | u8 | `0x251b44084`–`0x251b44088` | `[流对象+0x60]` 的低字节（变换/方向位） |
| `+0x06` | u8 | `0x251b4408c`–`0x251b440d0` | 基值 `0x12`；`[+0x1bc]≠0` → `0x13`；`[+0x198]≠0` → `|0x04`；`[+0x64]≠0` → `|0x40`；`[+8]≠0` → `|0x08` |
| `+0x07` | u8 | `0x251b440d8` `strb w8, [x22, #7]`，`w8 = 1` | 恒 1 |
| `+0x08` | u64 | `0x251b44178` `str x8, [x22, #8]` | 网络时间戳（同帧路径的转换器） |
| `+0x10`、`14`、`20`、`24`、`28`、`2c`、`30`、`34`、`38`、`3c` | float×10 | `0x251b4417c` 起 | 10个double→float，+18..1f留空，非连续float[10]，见06.5 |
| `+0x40`–`+0x7f` | — | 未写 | 保持 0 |

**注意**：配置记录的 `+0x06` 是"能力/方向位图"，与帧记录的 `+0x05` 是两套不同字段，**不要混用**。

## 02.4 记录类型取值

| 值 | 含义 | 证据强度 |
|---|---|---|
| `0` | 帧 | `BYTES` |
| `1` | 配置 | `BYTES` |
| `2` / `5` | 已核统计构造分支：storage+0x3c5为0写2，非0写5；控制位业务来源仍待核 | `BYTES`，`0x2519b07a8..7bc` |

`A02.8`补证：同一原切片 `f_2519b0014.s` 在 `0x2519b078c..79c` 分配128B头，
`0x2519b07a4` 写长度；接着 `ldrb w8,[x20,#0x3c5]; cmp w8,#0; mov w8,#5;
mov w9,#2; csel w8,w9,w8,eq; strb w8,[x0,#4]`，故两条类型路径无需抓包即可确定。
`0x2519b07c0..c4`把storage+0x3c0低字节写头+5；`0x2519b07e0`把可选数据长度转换后的float32写+0x7c，
不能套用帧记录的+0x60..7f间隔表解释统计头。

旧文档把UserData构造器与“另一个未知记录类型”绑定也不准确：**本函数的这条内联路径**
在 `0x2519b0e00..10` 将UserData缓冲写到sp+0x88；
`0x2519b0e38..4c`把该缓冲长度加storage+0x3a8形成w27，并计入总body长度w23；
随后 `0x2519b0e8c` 仍把帧头类型写0，`0x2519b0f9c`把w27写头+0x1c（+0x18清零）。
`0x2519b116c..74` 根据该缓冲是否存在选择 `0x2519b12e8` 的第二次wrapper路径；
不能因函数名createUserDataBBuf就额外编造一个独立type值。
这是本路径证据，不排除其它构建或未审计分支存在其它类型。

`OPEN-VID-2`缩小为2/5控制位来源、统计/用户数据完整schema与接收状态影响；
不再缺这两个类型字节。C10补充指令锚点及对+0x3c5全部256个byte值的局部分支检查，
不是固件执行或互通测试。

## 02.5 端序与宽度

- 头内整数为**小端**（ARM64 常规 `str`/`strh` 直接落内存）；
- 长度字段 **u32**、类型/标志 **u8**、时间戳 **u64**、帧间隔 **u16**；
- 头上限固定 128 字节，**没有**扩展头字段。

## 02.6 实现影响

1. 客户端按128B固定头及最终body长度构造记录；不能压缩头或把长度直接填为明文大小；
2. 帧间隔最多16项，经ticks→ms后≥65536写0xffff；
3. 配置记录必须在帧之前至少发一次（否则对端不知道几何）；发送时机见 `05.4`（未完全闭合）；
4. 类型 0/1 是唯一可证的两个值；其它类型不能猜。
