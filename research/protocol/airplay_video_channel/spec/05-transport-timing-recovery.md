# 05 传输、时序与恢复

> 回答第 9、10、11 项覆盖要求。

## 05.1 批与顺序

**R-5.1（MUST / CONFIRMED）** 已核路径在配置待发送时把配置记录放在帧记录之前；触发条件还需核验，不能从条件调用推出“绝不允许每帧配置”。

依据：`A05.1`、`A02.5`。

**R-5.2（MUST / CONFIRMED）** 头内最多存16项间隔，按R-2.7填充；不能将槽数解释为每批最多16帧或16个访问单元。

依据：`A02.4`。

## 05.2 时间

**R-5.3（SHOULD / INFERRED）** 按已核转换器来源分别构造时间字段，并与目标profile的时钟同步约定一致。当前证据不证明音视频共用同一对象，不能简单将本地墙钟填入所有字段。

依据：`A05.2`、`A02.2`。

**R-5.4（未定义 / OPEN）** 时间基准（NTP/媒体时间）、单位与音视频同步策略未证；实现必须把基准做成可配置项。

依据：`A05.2`。

## 05.3 关键帧与清屏

**R-5.5（MUST / CONFIRMED）** 实现必须能处理车机的 `forceKeyFrame` 命令：收到后尽快产生并发送一个关键帧（首帧、模式切换后、丢包后同样适用）。

依据：`A05.3`、`A04.6`。

**R-5.6（未定义 / OPEN）** 已知screenDidClear与handleClearScreen入口存在；清屏是否要求清解码参考、重建编码或发特定记录尚未闭合，不能由名字推出必须重置参考状态。

依据：`A05.4`。

## 05.4 断开与恢复

**R-5.7（SHOULD / INFERRED）** 应区分挂起、恢复、对端断开和致命错误等业务事件，避免所有事件均触发重连；具体状态迁移与资源清理须依据完整调用链，而非仅复制固件组件名。

依据：`A05.5`、`A05.6`。

**R-5.8（SHOULD / INFERRED）** 应按错误来源区分临时背压、断开及密码/记录状态错误；不能由fatalError组件存在推出所有发送错误必断流。重试前核验已发送字节和密码状态，禁止盲目复用已修改的原地载荷。

依据：`A05.5`。

**R-5.9（未定义 / OPEN）** 断流检测阈值、重连退避、重连后是否自动重发配置记录，均未证；实现必须把这三项做成可配置，并以抓包校准。

依据：`A05.5`。

## 05.5 传输

**R-5.10（MUST / INFERRED）** TCP 变体必须由发送端主动连接对端数据端口；UDP 变体必须按 `RTP/AVP/UDP` 的 SDP 描述建流。

依据：`A01.6`、`A01.7`。

**R-5.11（未定义 / OPEN）** UDP 变体的 RTP 头、payload type、SSRC 与 H.264 打包模式未证；实现不得在没有抓包的情况下声称兼容。

依据：`A05.7`。
