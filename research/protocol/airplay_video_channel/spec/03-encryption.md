# 03 加密

> 回答第5项覆盖要求。区分本地包装器、条件性cryptor分派和网络profile；不能仅按函数/类名选算法。

## 03.1 分段

**R-3.1（MUST / CONFIRMED）** 加密必须把 128 字节头与载荷作为**两个独立输入**处理；不得先拼接再加密，否则头内的长度/时间戳无法被对端读取。

依据：`A03.1`、`A02.7`。

**R-3.2（MUST / CONFIRMED）** 本包装器在加密上下文为空时直接返回0、不处理载荷；这不是允许联网明文降级的协商证据。实现不得因建键失败而自行继续发明文。

依据：`A03.2`。

**R-3.3（MUST / CONFIRMED）** 将记录构造计数与密码nonce分开。本地+0x470在拼装成功后按u32加1，另有清零路径，不证明socket发送完成或跨重连单调。

依据：`A02.7`、`A06.3`。

## 03.2 输出

**R-3.4（MUST / CONFIRMED）** 本包装器原地处理连续载荷，另将+0x1a0字节的附加输出追加到载荷末尾。独立实现可采用不同内存布局，但必须保持所选cryptor的字节顺序；不得把附加缓冲当全部密文。错误后的原地buffer/密码状态不能假定已回滚。

依据：`A03.3`、`A06.1`。

**R-3.5（未定义 / OPEN）** 目标profile的发送cryptor绑定、nonce布局和附加输出格式尚未全部闭合。接收侧特定ChaCha路径已证完整128B头作为AAD及单/双段边界；不得推广到所有算法，也不得把未知字段作为联网试探参数。

依据：`A03.4`。

## 03.3 算法

**R-3.6（MUST / CONFIRMED）** type110/111的已核分派受keyholder及内部属性门约束：G=0创建CTR，G≠0创建ChaCha(flag=0)。实现须绑定适用profile及派生路径，不得从CoreUtils类名或“现代车机”推出唯一算法，也不得将构造flag当成已证方向。

依据：`A03.5`、`A03.7`。

**R-3.7（MUST / CONFIRMED）** 在目标profile的发送绑定、密码状态及互通未验证前，只能按实际测试范围描述能力，不能以包装器测试通过声称“AirPlay视频加密兼容”。

依据：`A03.5`、`A03.4`。

**R-3.8（MUST / CONFIRMED）** 采用已核CoreUtils媒体KeyHolder接口时，salt为`DataStream-Salt`加传入u64的十进制表示，info分别为`DataStream-Input-Encryption-Key`（31B）和`DataStream-Output-Encryption-Key`（32B），均不含末尾NUL；输出密钥长度是独立实参。不得自造标签、假定首个ID为0/1或把Control/Events标签逐媒体流套用。Legacy的SHA512派生是另一条路径。

依据：`A03.6`、`A03.7`、`A06.2`。
