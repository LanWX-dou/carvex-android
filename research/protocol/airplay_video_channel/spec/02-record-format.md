# 02 屏幕记录格式

> 回答第 3、4 项覆盖要求。所有偏移量都是**头内偏移**，头长固定 128 字节。

## 02.1 外形

**R-2.1（MUST / CONFIRMED）** 每条记录 = 128 字节头 + 载荷；头长度不得变化。

依据：`A02.1`。

**R-2.2（MUST / CONFIRMED）** 头+0是u32小端，不含128B头；不能直接填编码帧明文长度。发送路径在写入前已加入额外长度及可选尾段长度；接收侧已核N为网络body读入长度。完整发送profile应将每段加密开销计入N，并在认证前形成最终头；具体开销须由cryptor绑定确认，不能猜固定16B。

依据：`A02.2`、`A02.7`、`A06.4`、`A03.4`。

**R-2.3（MUST / CONFIRMED）** 头 `+0x04`（u8）是记录类型：`0` = 帧记录，`1` = 配置记录。
另已核统计构造分支的2/5：storage+0x3c5为0写2，非0写5；这不是全局枚举全集。

依据：`A02.2`、`A02.5`、`A02.8`。

**R-2.4（未定义 / OPEN）** 统计2/5的控制位来源、完整payload schema与状态影响尚未闭合；不得因类型字节已知就猜测生成。
本构建已核的UserData内联路径仍使用type0，附加长度写头+0x1c；不得凭函数名另造一种记录类型。
接收/调试工具也不能无条件跳过未知记录并继续推进密码状态。

依据：`A02.8`。

## 02.2 帧记录

**R-2.5（MUST / CONFIRMED）** 限定所述构造路径：帧记录+05只写bit7/bit4，其余位为0。bit7来自APInterestingFrame附件==kCFBooleanTrue；bit4来自NotSync读取结果派生的storage+45d（无/空数组时为1）。生成规则见analysis07，不能任意复制内部状态或按“关键帧”猜bit7。

依据：`A02.3`。

**R-2.6（未定义 / OPEN）** +08、20、28、58的构造涉及时间转换；+10来自storage+3e0，其语义尚未闭合。不得把所有u64字段统一命名时间/序号或填相同墙钟值；按analysis02的各字段来源分别核验。

依据：`A02.2`、`A05.2`。

**R-2.7（MUST / CONFIRMED）** 帧记录+60..7f是最多16项u16间隔（毫秒）：

1. 对i从1开始且i<count，计算`UpTicksToMilliseconds(ts[i]-ts[i-1])`。
2. 转换结果≥65536时写0xffff，否则写低16位（65535也自然编码为0xffff）。
3. 最多填16项；这是头内槽上限，不是每批最多16帧的证明。
4. 未填项保留calloc的0。

依据：`A02.4`、`A06.4`。

## 02.3 配置记录

**R-2.8（MUST / CONFIRMED）** 配置记录 `+0x04 = 1`、`+0x07 = 1`；`+0x06` 基值 `0x12`，并按以下条件置位：显示标志 → `0x13`；有加密上下文 → `|0x04`；某显示属性 → `|0x40`；有附加对象 → `|0x08`。实现必须按"基值 + 条件位"构造，不得写死 `0x12`。

依据：`A02.5`。

**R-2.9（MUST / CONFIRMED）** 配置记录的10个float32依次写入+10、14、20、24、28、2c、30、34、38、3c（十六进制）；+18..1f留空，不能用连续float[10]代替。源double经浮点格式转换而非字节截断；+40..7f保留为0。

依据：`A02.6`、`A06.5`。

**R-2.10（MUST / CONFIRMED）** 配置记录 `+0x00` 是该配置载荷的长度，`+0x08` 是时间戳；两者与帧记录同宽度、同端序。

依据：`A02.5`、`A02.6`。

## 02.4 端序

**R-2.11（MUST / CONFIRMED）** 头内整数一律**小端**：u32 长度、u8 类型/标志、u64 时间、u16 间隔；不得做网络字节序转换。

依据：`A02.1`、`A02.2`。
