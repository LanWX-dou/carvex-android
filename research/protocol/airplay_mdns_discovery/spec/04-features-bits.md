# 04 — `features` 能力位

> 对应覆盖项 7（设备能力位）。
> 本阶段能证明的只有：**24A446 的发现路径会读 `features`（或 `fex`）并对值做两次位查询（索引 0x37、0x38）**。
> 位语义、位序（LSB/MSB）、全表——全部 `OPEN`。

## 4.1 规则

- **R-4.1**（MUST）`features` 必须按“整数 + 位集合”建模：先解析成整数，再按索引查询位；不得按字符串直接比较。
  依据：`A02.4`、`A02.5`、`A02.3`

- **R-4.2**（MUST）索引 `0x37` 与 `0x38`（十进制 55、56）是被 24A446 实际查询的两个位；实现必须能报出这两位的值。
  依据：`A02.4`（`0x24fd997a8`、`0x24fd997b8`）、`A02.7`

- **R-4.9**（MUST）位索引是**全局 64 位**索引：0–31 属 legacy 半，32–63 属 extended 半；因此 55/56 在 extended 的第 23/24 位。实现不得把 `features=0x…` 的第一段当成“全部能力”。
  依据：`A02.7`、`A02.8`

- **R-4.10**（MUST）`fex` 与 `features` 是两个独立键，`fex` 的值是字符串；不得假设两者数值等价。分支选择见 `R-4.7`：24A446 的 `_deviceFound` 路径优先取 `fex`，缺失时回退 `features`；该优先级是否适用于其他 build/profile 仍为 `OPEN-MDNS-15`。
  依据：`A02.8`、`A02.5`、`OPEN-MDNS-15`

- **R-4.3**（MUST NOT）在 `OPEN-MDNS-11` 关闭前，不得给任何位赋予“支持某能力”的语义，尤其不得写“某位 = 支持 CarPlay”。
  依据：`A02.4`、`OPEN-MDNS-11`

- **R-4.4**（MUST NOT）不得把 `flags`、`sf`、`ft`、`vv` 等字段并入 `features`，也不得用它们替代 `features`。
  依据：`A02.3`、`A02.4`

- **R-4.5**（MUST）位序未取证：实现不得假设“索引 0 = 最低位”或“索引 0 = 最高位”，必须把位索引与原始整数一起记录，便于事后对照。
  依据：`OPEN-MDNS-11`、`A02.5`

- **R-4.6**（MUST）当 `features` 缺失、非十六进制或超长时，按“无 features”处理并继续发现流程，不得因此丢弃实例。
  依据：`OPEN-MDNS-14`、`A02.5`

|---|---|---|---|
| `0x37` | 被查询，结果进 `w24` 相关分支 | `0x24fd997a8` | 读到了；语义 `OPEN-MDNS-11` |

## 4.3 `fex` 与 `features` 的关系

- **R-4.7**（MUST）在 24A446 中，若 TXT 同时有 `fex` 与 `features`，`_deviceFound` 先取 `fex`，取不到再取 `features`；实现应复现该 24A446 分支并在日志里记录实际用了哪个键。该结论依据 `A02.4/A02.5`，其中 `A02.5` 为 **INFERRED**（桩名被剥离）；其他 build/profile 不得直接套用，保持 `OPEN-MDNS-15`。
  依据：`A02.4`、`A02.5`、`OPEN-MDNS-15`

- **R-4.8**（MUST）`fex` 的内部结构未取证；不得假设它是 `features` 的另一种编码或某种压缩格式。
  依据：`OPEN-MDNS-15`、`A02.5`
