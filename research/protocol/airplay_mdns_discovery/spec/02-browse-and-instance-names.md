# 02 — 浏览、服务类型与实例名

> 对应覆盖项 3（服务类型与浏览）与覆盖项 4 的一半（实例名的表示）。
> 服务类型清单见 §1.4；本章只管“怎么发起浏览、实例名怎么表示与比较”。

## 2.1 浏览

- **R-2.1**（MUST）默认浏览 `_airplay._tcp.local.`：24A446 的 `_APBonjourBrowserCreate` 在 `w21 & 1 == 0` 时正是用 `_airplay._tcp.` + `local.` 建浏览器。
  依据：`A01.5`

- **R-2.2**（SHOULD）实现应支持把服务类型作为配置项（至少 `_airplay._tcp`、`_raop._tcp`、`_airplay-alt._tcp`、`_airplay-p2p._tcp`、`_sideplay._tcp`），因为 24A446 内同时存在这五个字符串且不同模式会切换。
  依据：`A01.1`、`A01.2`

- **R-2.3**（MUST）浏览必须能发出 `QNAME` 为服务类型全名、`QTYPE=PTR`、`QCLASS=IN` 的 PTR 查询；多个服务类型可以合并在同一 DNS 报文的多个 question 中，不得强制“一次浏览只发一条 question”。响应里 PTR 的 rdata 才是实例全名，不能用“答案里的名字”倒推实例。
  依据：`A02.1`、`[RFC 6763 §4]`

- **R-2.4**（MAY）需要单播回应时置 QU 位；不置时按组播接收。两种都要能处理。
  依据：`[RFC 6762 §5.4]`、`A02.1`

## 2.2 实例名

- **R-2.5**（MUST）实例名是 DNS-SD 的服务实例标签 + 服务类型 + 域，例如 `Living Room._airplay._tcp.local.`；实现必须以**全名**为键（服务类型 + 实例），不能只用实例短名。
  依据：`A02.1`、`[RFC 6763 §4.1]`

- **R-2.6**（MUST）线上名称必须按 DNS wire label（长度前缀 + 原始字节）编码；不能要求发送端保存某种文本转义形式。展示/配置字符串可按 DNS-SD 约定把标签内的 `.` 与 `\` 转义，但解析后应以 wire label/规范化全名作键。参考实现的 `split_labels` 只处理展示字符串，不能替代 wire 编解码。
  依据：`[RFC 6763 §4.1.1]`、`A02.1`

- **R-2.7**（MUST）名称比较按 DNS 规则大小写不敏感，但必须保留原始大小写用于展示；不得把实例名转成小写后回写。
  依据：`[RFC 6762 §16]`、`A02.1`

- **R-2.8**（MUST）实例名允许 UTF-8（含中文）；解析必须按字节读取标签再用 UTF-8 解码，解码失败用 `surrogateescape` 保留，不得整条丢弃。
  依据：`A02.1`、`[RFC 6763 §4.1.1]`

- **R-2.9**（MUST NOT）不得用“实例名相同”判断是同一台设备：不同服务类型下可以有同名实例；设备身份要看 TXT（`deviceid`/`serialNumber`）且这些也未被证明唯一。
  依据：`A02.3`、`OPEN-MDNS-17`

## 2.3 重复与合并

- **R-2.10**（MUST）同一实例的 PTR/SRV/TXT 可能分多条报文到达（answer 与 additional 分开、或后续响应补全）；实现必须按实例合并，后到的记录覆盖同名字段（以 TTL 与 cache-flush 为准）。
  依据：`A02.1`、`[RFC 6762 §10]`

- **R-2.11**（MUST）收到 TTL=0 的 PTR 时只删除该实例的“存在性”，SRV/TXT/A 可以按各自 TTL 自然过期；不得因为 PTR 撤销就假定地址立刻失效。
  依据：`[RFC 6762 §10.1]`、`A02.2`

## 2.4 反向服务

- **R-2.12**（MUST）实现不得假设发现是单向的：24A446 的手机侧还引用 `_carplay-ctrl._tcp`（`0x24fe6c193`），并由 `_APCarPlayControlServerAddInterface` 绑定接口；设备侧模拟 iPhone 时可能同时要应答车机对该服务的查询。该行为未取证，属边界提示。
  依据：`A01.7`、`OPEN-MDNS-8`
