# spec/08 — 一致性检查清单与定量附录

## 8.1 规范性约定

本规范使用三个规范性动词，与 `spec/00` §0.2 的状态一一对应：

| 动词 | 状态 | 含义 |
|---|---|---|
| **MUST** | `CONFIRMED` | 固件字节直接证明；实现必须一致 |
| **SHOULD** | `INFERRED` | 由结构/符号推断；实现应一致，但须自行验证 |
| **未定义** | `OPEN` | 尚缺证据；可配置用于试验，不表示任意值可互通；生产实现须补证或显式不支持 |

条款编号 `R-<章>.<序>`；本文件只做**汇总与检查项**，不引入新语义。

## 8.2 帧级测试向量

用 `spec/02` 的算法重算，结果必须逐位相同（`verify.py` C5 自动校验）。

| # | 输入字节 | 算法 | 期望 |
|---|---|---|---|
| V1 | `02 00 EE` | 8 位 | `0x10` |
| V2 | `04 00 02 04 EE` | 8 位 | `0x08` |
| V3 | `02 00 FE` | 8 位 | `0x00` |
| V4 | `FF 5A 00 09 80 00 00 00` | 16 位 | `0x581D` |
| V5 | `FF 5A 00 09 C0 00 00 00` | 16 位 | `0x57DC` |
| V6 | （空） | 16 位 | `0x0000` |

V4/V5 只测试校验算术（长度 9 不合法于 16 位帧），不可当 SYN/SYNACK 发送。空输入校验为 0 不等于无载荷帧要追加尾校验。整帧样例（可直接用于编解码单测）：

| 帧 | 完整字节 | 校验验证 |
|---|---|---|
| Detect | `FF 55 02 00 EE 10` | `cksum8(02 00 EE) = 0x10` ✔ |
| DetectNACK | `FF 55 04 00 02 04 EE 08` | `cksum8(04 00 02 04 EE) = 0x08` ✔ |
| RequestIdentify | `FF 55 02 00 FE 00` | `cksum8(02 00 FE) = 0x00` ✔（末字节按规则计算） |

`R-8.1`（MUST / CONFIRMED）实现必须能对上表 3 条传统帧与 6 条校验向量做单元测试，且不得把 `FF 55` 计入传统帧校验。

## 8.3 定时器清单

| 定时器 | id | 单位 | 缺省 | 推导链 | 状态 |
|---|---|---|---|---|---|
| ACK 超时 | `0xC` | 毫秒 | `1000` | `SYN[0x06]` → `iAP2TimeCallbackAfter(ms)`；`iAP2TimeGetCurTimeMs` 提供毫秒时基 | MUST / CONFIRMED（时长来源）/ SHOULD（毫秒单位） |
| 累积确认超时 | — | **未确认** | `10` | `SYN[0x08]` 存在且合法范围 `> 9`，但无调用点证据 | 未定义 / `OPEN-TMR-1` |
| SYN 重发 | — | **未确认** | — | 事件 `0x03` 绑定 `iAP2LinkDeviceActionResendSYNACK`，但超时值未定位 | 未定义 / `OPEN-TMR-2` |
| 重传定时器 | — | **未确认** | — | `link+0xc8` 被取消/重装（`link[0xc2]` 初值 `0xFF`），无时长证据 | 未定义 / `OPEN-TMR-3` |
| 会话/识别超时 | — | **未确认** | — | 消息层未取证 | 未定义 / `OPEN-MSG-3` |

`R-8.2`（MUST / CONFIRMED）实现必须显式配置上表 4 个"未确认"定时器，且缺省行为不得导致链路进入死锁（建议按对端 ACK 超时的整数倍退避）。

## 8.4 边界定量

| 量 | 值 / 公式 | 状态 |
|---|---|---|
| 头部固定长度 | 8 字节 | MUST |
| 头部总长 | 8 + 校验宽度（1 或 2）= 9 或 10 | MUST |
| 单帧最大载荷 | `min(link[0x1a6], link[0xc0], 会话上限) − (checksum16 ? 12 : 10)` | MUST |
| 最大接收包长缺省 | `0xFFFF`（`0xFFFF0100` 常量） | MUST |
| 确认窗口缺省 | `1` | MUST |
| 传统帧长度字段 | 1 字节可表示 0..255；整帧另加 4 字节，具体命令接受范围独立校验 | 编码范围，不代表所有长度合法 |
| 链路对象大小 | `0x268` | MUST |
| 运行循环头部 | `0x60` | MUST |
| 缓冲区总上限 | 未确认（`iAP2LinkGetBuffSize` 未解读） | 未定义 / `OPEN-BUF-1` |
| 分片策略 | 按 `R-1.13` 限制 iAP2 帧长；RFCOMM 栈的分段与 iAP2 应用消息分包不是一回事。使用系统 socket 不手写 RFCOMM 分片 | 已确认边界；超长消息按对应层策略处理 |

## 8.5 一致性检查项

每条检查都给出"怎么测"和"依据条款"；`CL-*` 可在实现方的测试套件里直接映射为用例。

| 检查 | 内容 | 期望 | 依据 |
|---|---|---|---|
| `CL-1` | 帧起始两字节 | `FF 5A` | `R-2.2` |
| `CL-2` | 长度字段字节序 | 大端，等于整帧字节数 | `R-2.2` |
| `CL-3` | 头部总长 | 9 或 10 | `R-2.1` |
| `CL-4` | 控制位取值 | `0x80/0x40/0x20/0x10/0x08` | `R-2.3` |
| `CL-5` | 16 位头部校验 | 重算等于帧内值 | `R-2.6` |
| `CL-6` | 8 位校验（传统帧） | 不含 `FF 55` | `R-2.10` |
| `CL-7` | Detect 帧 | 逐字节等于常量 | `R-2.11` |
| `CL-8` | 单帧最大载荷 | 符合公式 | `R-2.9` |
| `CL-9` | SYN 最短载荷长 | 10 字节 | `R-3.4` |
| `CL-10` | SYN 字段偏移 | 与 `R-3.4` 表一致（含 2–7 为大端 16 位） | `R-3.4` |
| `CL-11` | SYN 缺省值 | `1/1/30/0/0xFFFF/1000/10` | `R-3.2` |
| `CL-12` | 无重传判定 | 四个字段全零 | `R-3.8` |
| `CL-13` | 序号回绕 | `(b−a) & 0xFF` | `R-4.1` |
| `CL-14` | 初始序号 | 由毫秒时基派生 | `R-4.2` |
| `CL-15` | ACK 窗口缺省 | 1 | `R-4.3` |
| `CL-16` | 状态数 | 8 | `R-5.1` |
| `CL-17` | 事件上限 | 29 | `R-5.2` |
| `CL-18` | 迁移表 | 与 `R-5.3` 完全一致 | `R-5.3` |
| `CL-19` | 空 handler 条目不迁移 | 状态不变 | `R-5.4` |
| `CL-20` | 链式迁移 | 同一事件在新状态重跑一次 | `R-5.7` |
| `CL-21` | 非法事件 | 无副作用、仅日志 | `R-5.8` |
| `CL-22` | 识别消息集 | `0x1D01/0x1D05/0x1D06` | `R-6.2` |
| `CL-23` | 会话启动消息 | `0x4301` 唯一 | `R-6.8` |
| `CL-24` | detach 顺序 | 先事件 `0x0E` 再复原参数 | `R-7.1` |
| `CL-25` | attach/detach 幂等 | 重复执行结果不变 | `R-7.3` |
| `CL-26` | 只有 `0x14` 进 Failed | 其余事件不进入状态 7 | `R-7.4` |

`R-8.3`（MUST / CONFIRMED）实现方必须为 `CL-1`–`CL-26` 各提供至少一个自动化用例；`CL-5`/`CL-6`/`CL-7` 必须使用 `8.2` 的字面量而非自生成向量。
