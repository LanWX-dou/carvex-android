# spec/03 — SYN 协商

## 3.1 参数结构

`R-3.1`（MUST / CONFIRMED）固件内部 SYN 参数结构为 50（0x32）字节。工作块位于 `link+0x168`，生效块位于 `link+0x19a`；独立实现无需复制这些内存偏移，只须正确表达字段。字段如下（偏移相对结构首字节）：

| 偏移 | 宽度 | 字段 | 缺省 | 合法范围 |
|---|---|---|---|---|
| `0x00` | 1 | version | `1` | `minVersion..3`，调用方 minVersion 为 1..3；解析器支持读 version 0 不等于校验接受 |
| `0x01` | 1 | MaxOutstandingPackets | `1` | `1..127`；无重传模式另允许 0 |
| `0x02` | 1 | MaxRetransmissions | `30` | `1..30` |
| `0x03` | 1 | MaxCumAck | `0` | `0..MaxOutstandingPackets` |
| `0x04` | 2 | maxPacketSize（推断） | `0xFFFF` | `> 23` |
| `0x06` | 2 | ACK 超时（毫秒） | `1000` | `> 19` |
| `0x08` | 2 | CumAckTimeout | `10` | `10..32767`（启用重传时） |
| `0x0a` | 1 | 特性条目数 | `0` | `0..5` |
| `0x18` | 1 | 扩展字节数 | `0` | `0..5` |
| `0x19` | n | 扩展字节 | — | — |
| `0x1e` | 4×n | 特性条目 | — | 见 `R-3.5` |

依据：`A04.1`（`iAP2LinkCreate` 复制与覆盖 `0x1000341a4`–`0x1000341ec`，常量 `0x1001b3348`）、`A04.2`（`iAP2LinkSetDefaultSYNParam` `0x1000328b0`）。

`R-3.2`（MUST / CONFIRMED）固件创建时先将调用方参数的 50 字节复制到工作块 `+0x168`；随后给另一块 `+0x19a` 写下列缺省值。**不会无条件覆盖调用方工作参数**，缺省条目数 0 也不是可直接完成协商的有效 profile：

```
version=1, MOP=1, MR=30, MCA=0, maxPacket=0xFFFF, ackTimeout=1000, cumAckTimeout=10
```

依据：`A04.1`（`0x1000341a4`–`0x1000341ec`，两段不同目的地址）。

`R-3.3`（MUST / CONFIRMED）`0x06`（ACK 超时）的语义：发送**数据帧**且本地未处于"无重传"模式时，启动定时器 id `0xC`，时长取该字段（毫秒）。

依据：`A01.4`（`__iAP2LinkSendPacketCommon` `0x100007a58`–`0x100007a60`）。

## 3.2 线上格式

`R-3.4`（MUST / CONFIRMED）SYN 载荷最短 10 字节，字段顺序与结构顺序**不同**：

| 载荷偏移 | 宽度 | 字节序 | 对应结构字段 |
|---|---|---|---|
| 0 | 1 | — | `0x00` version |
| 1 | 1 | — | `0x01` MaxOutstandingPackets |
| 2–3 | 2 | 大端 | `0x04` maxPacketSize |
| 4–5 | 2 | 大端 | `0x06` ACK 超时 |
| 6–7 | 2 | 大端 | `0x08` CumAckTimeout |
| 8 | 1 | — | `0x02` MaxRetransmissions |
| 9 | 1 | — | `0x03` MaxCumAck |
| 10 | 1 | — | `0x18` 扩展字节数 `k` |
| `[11,11+k)` | k | — | 扩展字节（仅 version >= 2） |
| 11+k | 1 | — | `0x0a` 特性条目数 `n` |
| 12+k | 3n | — | 特性条目 |

依据：`A04.3`（`iAP2PacketParseSYNData` `0x100103230`）、`A04.4`（`iAP2PacketCreateSYNPacket` `0x10010304c` 起）。

`R-3.5`（MUST / CONFIRMED）特性条目每条 3 字节，第二字节的最高位拆成独立标志：

```
entry_in  = { e0, e1, e2 }
entry_out = { id = e0, value = e1 & 0x7F, second = e2, flag = e1 >> 7 }
约束：e0 != 0；(e1 & 0x7F) <= 4；flag == 0；
      至少一条条目满足 (e1 & 0x7F) == 0；接收校验路径还要求 n >= 1；
      id 与类型分别唯一；如调用方传入版本上下限表，e2 须在对应类型范围内。
```

这里的 `e1` 在合法性检查中指解析后结构里的低 7 位值；线上原始字节的最高位先被拆到 `flag`，而 `flag != 0` 会被拒绝。创建链路时内部缺省计数为 0 是初始化状态，不等于“零条目 SYN 一定能通过对端合法性检查”；版本 1 的 10 字节向量可用于编码/解析测试，但不能单独当作已验证的协商成功向量。

注意 `csinc w23,w23,wzr,ne` 在类型为 0 时置 1；旧版“不为 0”结论错误。后三行扩展布局仅适用 version >= 2；version 1 的条目从偏移 10 起，见 R-3.6。以上为目标固件校验行为，不替代所有 CarPlay profile 的协商规范。

依据：`A04.6`（`0x100103378`/`0x100103380`）、`A04.9`（`0x100032a30`–`0x100032ad4`）。

`R-3.6`（MUST / CONFIRMED）版本相关的尾部处理：

| version | 载荷总长 | 尾部 |
|---|---|---|
| `0` | 10 | 无 |
| `1` | 10 + 3n | 无扩展字节；`n = (len-10)/3` |
| `>=2` | 12 + k + 3n | `k`、扩展字节、`n`、条目 |

依据：`A04.5`（`0x1001032a0`–`0x1001032c0`、`0x1001032d0`–`0x100103314`）。

## 3.3 合法性校验

`R-3.7`（MUST / CONFIRMED）接收方必须按 `R-3.1` 的范围校验；当对端处于"无重传"模式（`R-3.8`）时，跳过 `0x06`/`0x08`/`0x02`/`0x03` 四项校验。

依据：`A04.7`、`A04.8`（`iAP2LinkIsNoRetransmit` `0x100008590`）。

`R-3.8`（MUST / CONFIRMED）"无重传"判定：`0x06 == 0 && 0x08 == 0 && 0x02 == 0 && 0x03 == 0` 四项全零。

依据：`A04.8`（`0x1000085ac`–`0x1000085c8`）。

## 3.4 协商结论

`R-3.9`（MUST / CONFIRMED）收到 SYN 后的处理顺序：

1. 解析对端 SYN 载荷（`R-3.4`），失败则不上报协商；
2. 校验本地/对端参数（`R-3.7`）；
3. 若本地为"无重传"而对端不是，则把本地参数改写为 `MOP=1, MR=30, MCA=0, maxPacket=0xFFFF, ackTimeout=1000, cumAckTimeout=10`；
4. 按已核对路径对 version、MR、MCA、ACK/CumAck 超时取较小值，并保存对端 MOP/包长；复制对端条目数和 `4*n` 字节条目到工作块；
5. `SendResetSYNACK` 路径复位发送侧并生成初始序号；不要将该动作当成所有 SYN 的无条件响应；
6. 在 `iAP2LinkDeviceActionNotifyConnection` 中，将工作块 50 字节提交到生效块。其 `+0x0a/+0x1e` 正是数据面所读的会话表项数/数组。此时旧 `link[0xd5]` 保存到 `0xd6`，生效 SYN version 写入 `0xd5`（校验宽度选择字段）。

依据：`A04.11`（`0x1000352cc`–`0x100035394`）、`A04.13`（`NotifyConnection` `0x10003009c`）、`A07.9`（`SendResetSYNACK` `0x10002f920`）。

`R-3.10`（SHOULD / INFERRED）协商失败时链路层向 FSM 投事件 `0x03`，由状态机决定后续（不回滚参数）。

依据：`A04.11` 步骤 1（`0x100035190`–`0x10003519c`）；完整处置为 `OPEN-SYN-2`。
