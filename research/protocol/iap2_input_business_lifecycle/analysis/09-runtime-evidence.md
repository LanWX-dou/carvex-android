## 9.2 这份抓包能证明什么

1. 识别消息 `0x1D00/0x1D01/0x1D02` 的真实字节与参数 ID 顺序（见 `sess/analysis/07` 与 `sess/spec/08`）；
2. 认证四步 `0xAA00/0xAA01/0xAA02/0xAA03` 的真实字节与长度（`sess/spec/11`）；
3. 会话号在 `hdr[7]` 上的取值（`0x02` / `0x03`），验证 `sess/R-2.x`；
4. 设备侧在认证后**主动**发 `0x5702` 和 `0x4E0D`/`0x4E0E`（设备信息），再发一次 `0x5702`，车机回 `0x5703`（Wi‑Fi 配置）的顺序。

## 9.3 这份抓包**不能**证明什么（本阶段必须写清楚）

| 不能证明 | 后果 | 登记 |
|---|---|---|
| HID 任何一条（`0x6800/0x6801/0x6802/0x6803/0x6804/0x6805/0x6807`）的真实字节 | HID 线上字节和 profile 适用性仍只有固件侧证据；`0x6805` 的字段顺序已有平台桥接证据 | `OPEN-INP-1` |
| NowPlaying 任何一条（`0x5000/0x5001/0x5002/0x5003`） | 缺真实互通样本，不否定A14已证分组/字段去向 | `OPEN-INP-ALL`；历史 `OPEN-NP-1`/`OPEN-NP-2`已按静态范围关闭 |
| 导航任何一条（`0x5200/0x5201/0x5202/0x5203/0x5204/0x0D00/0x0D01/0x0D02`） | 字段映射只有固件侧证据 | `OPEN-NAV-2`、`OPEN-NAV-3` |
| AssistiveTouch（`0x5400..0x5404`） | 同上 | `OPEN-INP-3` |
| 挂起/恢复（SUS/ACK 控制包） | 生命周期只有固件侧证据 | `OPEN-LIFE-3` |
| 车机差异（另一台车机/另一版固件） | 第 12 项只能是 `OPEN` | `OPEN-LIFE-6` |

`A09.1`：本阶段**没有任何一条业务消息**的线上字节。这不是遗漏，是素材限制；
不能声称这些业务已在真实车机验证；固件解析/构造器仍可证明本构建的线上格式，
必须标为STATIC并限定构建，不能因缺抓包撤销这些静态结论。

## 9.4 采集计划（下一轮要补的最小集合）

| 目标 | 触发方式 | 需要的观测点 |
|---|---|---|
| HID 组件注册 + 按键 | 车机进入 CarPlay 后按方向盘键/旋钮 | `0x6800` 一次、`0x6802` 多次 |
| HID getReport | 车机请求报告（部分车机在挂挡/切页时） | `0x6804` → `0x6805` 配对 |
| NowPlaying 订阅 | 车机打开媒体页 | `0x5000` 一次 → `0x5001` 多次 |
| NowPlaying 退订 | 车机切走媒体页 | `0x5002` |
| 导航开始/更新/停止 | 车机启动导航并设目的地 | `0x5200` → `0x5201/0x5202/0x5204` → `0x5203` |
| 目标检测 | 车机进入辅助驾驶界面 | `0x0D00` → `0x0D01` → `0x0D02` |
| 挂起/恢复 | 熄火/点火（或锁车/解锁） | 链路控制包（非 16 位消息） |
| 断开 | 拔线/关蓝牙 | `link` detach 事件 |

**采集注意**：必须在同一构建（24A446）或明确标注构建差异；跨构建的常量只能作旁证。
