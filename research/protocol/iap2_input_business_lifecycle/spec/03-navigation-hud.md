# spec/03 — 导航 / HUD（特性 17）

## 3.1 消息集合与必需声明

`R-3.1` 导航在**开始**（`0x5200`）之前，配件 MUST 在识别阶段声明支持下列消息；
这是设备端固件的必需表检查，不是车机侧行为；设备视角方向见下表。
依据：A05.1、A06.3。

| msg_id | 方向 | 是否必需 |
|---|---|---|
| `0x5200` | 入站 | 必需 |
| `0x5201` | 出站 | 必需 |
| `0x5202` | 出站 | 必需 |
| `0x5203` | 入站 | 必需 |
| `0x5204` | 出站 | 可选 |

`R-3.2` 目标检测有独立的必需声明表：

| msg_id | 方向 | 是否必需 |
|---|---|---|
| `0x0D00` | 出站 | 必需 |
| `0x0D01` | 入站 | 必需 |
| `0x0D02` | 出站 | 必需 |
| `0x0900` | 入站 | 可选 |

依据：A05.2。

## 3.2 `0x5200` 开始导航

`R-3.3` `0x5200` 的参数0若出现 MUST 为U16；每个值加入组件列表，可重复出现。
当前处理器无参数路径仍可推进，不能据此强制参数0始终必填；具体车机profile条件另验。
依据：A05.3、A12.5。

`R-3.4` `0x5200` MAY 携带参数1–5，每个 MUST 是总长4的空值标记。
它们设置 options 布尔位，不是子参数组，也不是文本上限；组件列表来自参数0。
依据：A05.3、A12.5。

`R-3.5` 参数1–5非空或同一标记重复时，已核处理器进入失败路径并返回0；
实现 MUST 先验证通用TLV长度/父边界，不把0–3字节也当作合法空参数。
依据：A12.4、A12.5。

## 3.3 `0x5203` 停止导航

`R-3.6` `0x5203` 用于停止导航；设备 MUST 在收到后停止所有导航类更新。
依据：A05.3。

## 3.4 `0x0D01` 目标检测更新

`R-3.7` `0x0D01` 的参数按"逐个参数处理"的方式解析，MUST 逐个读取参数 ID 并分派，
MUST NOT 假定固定的参数个数。
依据：A05.4（`部分确认`，参数全集见 `OPEN-NAV-3`）。

## 3.5 出站更新

`R-3.8` 设备 MUST 用下列消息推送导航状态：

| msg_id | 语义 |
|---|---|
| `0x5201` | 路况/路线指引更新 |
| `0x5202` | 机动点更新 |
| `0x5204` | 车道指引更新 |
| `0x0D00` | 开始目标检测 |
| `0x0D02` | 停止目标检测 |

依据：A01.3、A05.2。

`R-3.9` 字段名按"类型号 → 键"的映射给出；本地 `keyForType` 一族不是车机代码；类型号与字段映射尚须补证，
不同版本可能不同。
依据：A05.5（`部分确认`，见 `OPEN-NAV-4`）。

## 3.6 顺序

`R-3.10` 设备 SHOULD 按 `0x5200` → `0x5201`/`0x5202`/`0x5204` → `0x5203` 的顺序使用导航；
更新先于开始的行为未定义。
依据：A05.1（`OPEN-NAV-5`）。

`R-3.11` 目标检测 SHOULD 按 `0x0D00` → `0x0D01` → `0x0D02` 的顺序使用。
依据：A05.2。

## 3.7 HUD 字段边界

`R-3.12` 文本类字段的最大长度与容量 MUST 取自**识别阶段**的导航显示能力声明（7 项：当前道路名、
目的地名、机动后道路名、机动描述、机动容量、车道描述、车道容量），MUST NOT 从 `0x5200` 反推。
依据：A11.3。
