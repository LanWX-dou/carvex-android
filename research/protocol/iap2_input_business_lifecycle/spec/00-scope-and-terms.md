# spec/00 — 范围与术语

## 0.1 适用范围

`R-0.1` 本规范覆盖 iAP2 控制会话建立并完成认证、识别之后，**输入与业务**相关消息：
HID（特性 11）、NowPlaying（特性 14）、导航/HUD（特性 17）、触摸/辅助触控（特性 3），
以及挂起、恢复、断开与资源清理。
依据：A01.1、A06.1。

`R-0.2` 本规范**不覆盖**：链路建立（见 `link/`）、会话表与特性注册（见 `sess/`）、
音频/视频、FairPlay、AirPlay 控制面、`0x4301` 的字段映射（见 `sess/OPEN-SES-2`）。
依据：A01.1。

`R-0.3` 本规范中"设备"指车厢内的播放源一侧（协议上是 accessory 的对端），
"车机"指发起 HID 注册、订阅 NowPlaying、启动导航的一侧。
依据：A03.1、A04.1、A05.1。

## 0.2 术语

| 术语 | 定义 | 依据 |
|---|---|---|
| 入站 | 由车机发往设备，带 16 位消息 ID，由特性处理器分派 | A01.2 |
| 出站 | 由设备发往车机 | A01.3 |
| 组件 ID | HID 组件的标识，U16；组件描述在识别阶段登记 | A03.2 |
| 子参数组 | 参数值本身又是一段"参数"序列，逐项带参数 ID | A04.2（导航1–5不是子参数组，见A12.5） |
| 必需消息表 | 每个特性可选的"必须在识别阶段声明"的消息 ID 清单 | A05.1、A06.3 |
| 用户计数 | 每个业务域各自维护的引用计数 | A08.1 |

## 0.3 方向约定

`R-0.4` 消息方向的判定依据是固件里的必需消息表与构造点，**不得**按编号区间推断。
依据：A01.3、A05.1。

`R-0.5` 同一条消息在不同特性下可能有不同方向语义，跨特性复用时必须分别核对。
依据：A05.2（`0x0D00/0x0D02` 出站、`0x0D01` 入站）。

## 0.4 强制级别

`R-0.6` 本文用 `MUST`（必须）、`MUST NOT`（禁止）、`SHOULD`（建议）、`未定义`（固件未约束）。
"未定义"不等于"可以随意"，只表示固件不校验。
依据：A09.1。

## 0.5 证据等级

`R-0.7` 每条条款的"依据"必须能点回 `analysis/A-conclusions.md` 的编号；
`部分确认` 的条款必须同时给出一个 `OPEN` 编号。
依据：A09.1（本阶段无业务消息抓包）。
