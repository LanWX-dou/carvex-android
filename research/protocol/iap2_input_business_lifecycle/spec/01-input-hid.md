# spec/01 — HID（特性 11）

## 1.1 消息集合

| msg_id | 方向 | 语义 |
|---|---|---|
| `0x6800` | 入站 | 注册/启用 HID 组件 |
| `0x6801` | 出站 | 输出报告 |
| `0x6802` | 入站 | 车机上报输入报告（按键/旋钮等） |
| `0x6803` | 入站 | 停止组件（不关闭接口） |
| `0x6804` | 出站 | 请求报告 |
| `0x6805` | 入站 | 对请求的应答 |
| `0x6807` | 出站 | 组件使能/更新 |

`R-1.1` 上表七条消息的方向以"是否出现在特性 11 的处理器表"与"构造点立即数"为准。
依据：A01.3、A03.1。

## 1.2 `0x6800` 注册组件

`R-1.2` `0x6800` MUST 携带参数 0，类型 U16，其值在**参数头层面**必须是 2 字节
（参数总长 = 6）；长度不符时该参数按解析失败处理，消息被忽略。
依据：A03.2。

`R-1.3` `0x6800` 的参数值依次为：

| 参数 ID | 类型 | 语义 |
|---|---|---|
| 0 | U16 | 组件 ID |
| 1 | U16 | 作为注册字典中的一个独立 16 位值；与参数 2 共用临时槽但不应编码为线上 U32 |
| 2 | U16 | 作为注册字典中的另一个独立 16 位值；字段名/业务单位仍未证 |
| 3 | U8（总长 = 5） | 单字节字段 |
| 4 | 变长（通用TLV总长≥4，语义有效性另验） | 描述符数据块 |

依据：A03.2（`部分确认`，参数 1/2 的字段名/单位见 `OPEN-INP-1`）。

`R-1.4` 对应本设备端接收路径，组件ID须通过识别组件校验：类型字段为0、功能值<=10且ID匹配。
这不是车机侧拒收行为，也不证明已完成StartHID（见analysis/13）。
依据：A03.3。

`R-1.5` StartHID以参数4提供描述符，处理器要求非NULL CFData，但未强制数据长度至少1。
客户端必须另验描述符有效性后再解释输入；不能把结构合法的空TLV当有效HID描述符。
依据：A03.3、A03.4。

## 1.3 `0x6802` 输入报告

`R-1.6` `0x6802` MUST 携带参数 0（U16，组件 ID）与参数 1（变长数据，输入报告本体）。
依据：A03.4、A03.5。

`R-1.7` 设备 MUST NOT 假定"收到 `0x6802` 就等于某个按键生效"：报告字节的含义由 `0x6800`
描述符与组件功能类型决定，固件只做搬运。
依据：A03.4。

## 1.4 `0x6803` 停止组件

`R-1.8` `0x6803` MUST 携带参数 0（U16，组件 ID）。
依据：A03.6。

`R-1.9` 收到 `0x6803` 后，设备 MUST 仅把该组件标记为停用，MUST NOT 因此关闭整条 HID 通道
或注销描述符；这是固件的既定行为（日志明确"保留 HID 接口注册"）。
依据：A03.6。

## 1.5 `0x6805` 请求应答

`R-1.10` `0x6805` MUST 携带四个参数：

| 参数 ID | 类型 | 语义 |
|---|---|---|
| 0 | U16 | 组件 ID |
| 1 | U8（总长 = 5） | 报告类型 |
| 2 | U8 | 报告 ID |
| 3 | 变长（通用TLV总长≥4，语义有效性另验） | 报告内容 |

依据：A03.7、A11.1及analysis/13（原字节数据流确认顺序；不证明实际互通）。

`R-1.11` `0x6804` 为设备请求、`0x6805` 为车机应答。客户端应按连接/组件/报告类型/ID关联请求，
不把异步投递等同匹配成功；已读接收处理器没有未完成请求表比较，超时/重复应答策略尚未闭合。
依据：A03.8。

## 1.6 出站

`R-1.12` 设备 MAY 主动发送 `0x6801`（输出报告）、`0x6804`（请求报告）、`0x6807`（组件使能）；
三者都必须满足门控（见 `R-5.x`）。
依据：A01.3、A06.1。

## 1.7 时序

`R-1.13` [客户端安全策略] 有效描述符与启动/启用状态具备前，不向本地应用注入输入。
公共组件校验只验识别身份/类型/功能，不能据此宣称固件强制 `0x6800` 先于所有报告/Stop。
依据：A03.3、A03.6。
