# spec/07 — 资源清理与幂等

## 7.1 用户计数

`R-7.1` [本地安全策略] 每个已启用业务域的资源所有权 MUST 可独立追踪，申请与释放配对。
固件使用各域计数，独立实现也可用所有权对象或统一注册表，不强制四套计数。
依据：A08.1。

`R-7.2` 释放时 SHOULD 做下溢保护；固件侧下溢行为未确认。
依据：A08.1（`OPEN-LIFE-4`）。

## 7.2 注册回滚

`R-7.3` 注册类操作失败时 MUST 回滚已注册的资源（先注销再返回）；
HID 组件注册提供了该范式的现成证据。
依据：A08.2。

## 7.3 清理顺序

`R-7.4` [本地安全策略] 销毁 MUST 先禁止新业务，并撤销通知、取消或排空相关回调后释放资源。
固件已观察到注销通知、同步、停 run loop、三个会话 cleanup 的局部调用顺序；
不能据此要求所有平台复制对象/线程结构或完整销毁顺序。
依据：A08.4、A11.6。

`R-7.5` 清理 MUST 幂等：同一资源被清理两次 MUST NOT 导致崩溃或重复释放。
依据：A08.2、A03.6。

## 7.4 可证与不可证

`R-7.6` 目前只有 HID 的"停止组件"能证到幂等（按 ID 查表，查不到只记日志）；
NowPlaying/导航的重复停止是否幂等未确认。
依据：A08.1（`OPEN-LIFE-4`）。

`R-7.7` 设备侧 MUST NOT 把"收到停止消息"当作"资源已释放"；释放完成须由本地所有权与未完成回调确认，单个计数归零仍不保证没有在途工作。
依据：A08.1。
