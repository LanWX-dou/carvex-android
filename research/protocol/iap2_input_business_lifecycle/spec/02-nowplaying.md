# spec/02 — NowPlaying（特性 14）

## 2.1 消息集合

| msg_id | 方向 | 语义 |
|---|---|---|
| `0x5000` | 入站 | 开始订阅属性更新 |
| `0x5001` | 出站 | 属性更新 |
| `0x5002` | 入站 | 停止订阅 |
| `0x5003` | 入站 | 设置播放信息 |

`R-2.1` 四条消息的方向见上表，依据为处理器表与构造点。
依据：A01.3、A04.1。

## 2.2 `0x5000` 订阅

`R-2.2` `0x5000` MAY 携带参数 0、1、2，语义如下：

| 参数 ID | 结构 | 语义 |
|---|---|---|
| 0 | 子参数组 | 媒体项属性 ID |
| 1 | 子参数组 | 播放属性 ID（子项0x11另携带U32值） |
| 2 | 子参数组（线上不是直接U32位图） | 空值子参数 ID 作为位序号，固件内部逐位构造32位掩码 |

依据：A04.2、A14.1（历史 `OPEN-NP-1` 已按原镜像数据流关闭）。

`R-2.3` 参数0/2的子项、参数1除ID `0x11`外的子项，在已通过通用TLV边界校验后
MUST 是总长4的空值参数。参数1的子项 `0x11` 使用U32，总长8。
非空标记/错误U32长度进入处理失败，不是忽略继续。不可把 helper 的 `cset lo` 读成 >=5。
依据：A04.3、A12.4。

`R-2.4` [本地防御策略] 参数2子项ID未有profile证据时 SHOULD 限于0–31；
固件32位寄存器移位使用ID低5位，>=32会产生别名，并非CPU未定义行为。此建议不是已证线上上限。
依据：A04.2、A12.4。

`R-2.5` 未识别的参数 ID MUST 被忽略（只记日志），MUST NOT 导致整条消息被丢弃。
依据：A04.2。

## 2.3 `0x5002` 退订

`R-2.6` `0x5002` 用于移除订阅者；它与 `0x5000` 的订阅是一对。
依据：A04.1、A04.7。

## 2.4 `0x5003` 设置播放信息

`R-2.7` `0x5003` MAY 携带U32参数0、1、2，分别设置播放时间、播放队列索引、
队列列表窗口起点。参数2为0xffffffff时启用自动选择；不是任意非零布尔值。
参数2的即时窗口请求还受Start参数1子项0x11的出现位控制。
时间单位、平台有效值/失败反馈尚未闭合，不得凭字段名自行换算。
依据：A04.4、A14.3（`OPEN-NP-3`剩余边界）。

## 2.5 `0x5001` 更新

`R-2.8` 设备 MUST 用 `0x5001` 推送属性更新（媒体项属性、播放属性、队列变化、队列信息共用这一条消息），
消息体用**组参数**承载多类属性。
依据：A04.5、A11.2。

`R-2.9` 设备 MUST NOT 把封面图片塞进 `0x5001`：封面走文件传输，消息体只带传输标识。
依据：A04.6。

## 2.6 订阅者与初始更新

`R-2.10` 车机订阅后，设备 SHOULD 立即推送一次全量更新（初始更新）。
依据：A04.1（日志"发送初始更新"）。

`R-2.11` 成功解析的新 `0x5000` 替换该endpoint的旧属性数组；固件先提交旧子特性移除再添加新订阅。
[本地实现策略] 设备 SHOULD 避免重复订阅造成引用数累积；不得把CFArray当成自动去重集合。
本构建的PlaybackQueueList清理、实际平台计数及异步副作用尚未全闭合，不能声称固件完全幂等。
依据：A04.7、A14.2（`OPEN-NP-4`）。

## 2.7 顺序

`R-2.12` [本地实现策略] 设备 SHOULD 在建立有效订阅后发送 `0x5001`。
这与车机发送 `0x5003` 的顺序是两个问题：本处理器参数0/1没有Start active门，
参数2即时窗口请求有订阅子项门；不得从局部准入推导平台已经执行成功。
依据：A04.7、A14.3（`OPEN-NP-5`）。
