# spec/08 — 设备侧施工指南

本文件把前面各章落成"先做什么、后做什么、哪里会卡住"，供实现方对照。

## 8.1 启动顺序

`R-8.1` 设备侧实现 MUST 按下列顺序推进，任一步失败都要能停在这一步并给出原因：

1. 链路建立并使用协商确认的控制会话条目；
2. 按相邻 control/spec/09 的版本门推进：version2识别优先，非2认证优先；
3. 识别方向为设备 `0x1d00` → 车机 `0x1d01` 自述 → 设备 `0x1d02` 接受（须先校验适用 profile）；
4. 完成认证/识别及方向能力检查，再启用适用业务；不能把读侧集合误写成设备上报全部 ID；
5. 按各域的订阅、组件、开始/停止条件处理业务。2/6只是24A446内部状态值。

参见 analysis/12 的证据边界，集合完整填充链仍待核。

依据：A06.1、A06.2、A06.3。

## 8.2 第 2 步是最容易漏的一步

`R-8.2` [排障建议] 业务不生效时 SHOULD 核对方向能力、认证/识别及特性状态，
再区分未发、未收到、门控拒绝、解析失败和平台未执行；不能将无响应一律归因于“设备漏报 ID”。
依据：A06.3、A06.4。

## 8.3 HID

`R-8.3` HID 实现 MUST 能在收到 `0x6800` 后建立"组件 ID → 描述符"的映射，
并把 `0x6802` 的报告按描述符解析；`0x6803` 只停组件。
依据：A03.1–A03.6。

## 8.4 NowPlaying

`R-8.4` NowPlaying 实现 MUST 支持"订阅 → 初始全量更新 → 增量更新"，
并且封面走文件传输。
依据：A04.1、A04.5、A04.6。

## 8.5 导航

`R-8.5` 导航实现 MUST 按设备视角检查 `0x5200/0x5203` 入站、`0x5201/0x5202` 出站必需能力；
`0x5204` 可选，不强制先后声明顺序。类型号映射来自本地平台函数，完整线上语义仍待核。
依据：A05.1、A05.5。

## 8.6 生命周期

`R-8.6` 实现 MUST 区分链路层挂起/恢复与断开，并覆盖所有域的资源清理（可统一协调）；
两者不得互相替代。
依据：A07.1、A07.5。

## 8.7 验收标准

`R-8.7` 设备侧"能跑起来"的最小证据集合：

| 证据 | 说明 |
|---|---|
| 适用认证/识别与能力门通过 | 2/6是固件内部枚举，不是线上字段 |
| 收到至少一条 `0x6800` 并能回放 `0x6802` | HID 通路 |
| 收到 `0x5000` 并发出 `0x5001` | NowPlaying 通路 |
| 收到 `0x5200` 并发出 `0x5201` | 导航通路 |
| 挂起后停止发送、恢复后继续 | 生命周期 |

依据：A03.4、A04.5、A05.1、A07.1。

## 8.8 不能承诺的事

`R-8.8` 在拿到含业务消息的抓包之前，实现方 MUST NOT 声称"与真车互通已验证"。
依据：A09.1。
