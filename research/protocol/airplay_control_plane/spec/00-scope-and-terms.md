# 00 · 范围与术语

## 0.1 范围

本规范描述**设备侧**（模拟 iPhone，下称"设备"）与**车机**（accessory）之间 AirPlay 控制面的行为：
从发现结果得到目标地址起，经 RTSP 控制连接、Pair-Setup/Pair-Verify、加密会话、`SETUP`，到把流交给上层隧道为止。

不在本规范内：服务发现（mDNS/TXT 解析）、iAP2 会话、RTP/RTCP 时序、音视频编解码、FairPlay 帧级密钥、`type=130` 隧道内部的 iAP2 语义。

## 0.2 术语

| 术语 | 含义 |
|---|---|
| 设备 | 发起连接的客户端（本规范的实现对象） |
| 车机 | 接受连接的 accessory |
| 控制面 | 承载 RTSP 请求/响应的那条 TCP 连接 |
| 事件通道 | 单独的、用 `Events-*` 密钥加密的反向通知连接 |
| 流 | `SETUP` 建立的一条传输通道（音频/视频/隧道） |
| 交接 | 控制面把某条流交给上层（隧道）使用的动作 |

## 0.3 证据级别

- `A` 编号：有本 docset 内的指令或字节证据（见 `analysis/A-conclusions.md`）；
- `INFERRED`：由已确认事实推出，正文里显式标注；
- `OPEN-AP-n`：未闭合，进 `08-open-items.md`，**不得**在实现里当作已知行为。

## 0.4 规范用语

"必须"=MUST，"应"=SHOULD，"可以"=MAY。凡涉及对端行为的句子，一律写成"设备应……"，不假设车机会怎么做。

## 0.5 平台中立

本规范不出现任何平台 API 名（`NSURLSession`、`CFSocket`、`ObjC` 方法名等）。实现者自行选择运行环境。
