# 超时、重试和恢复

超时只能证明指定观察窗口没有完成事件，不证明对端不支持、不证明认证错误。
所有超时必须记录起止事件、单调时钟、取消条件、实际配置及来源。

| 阶段 | 起止/来源 | 重试与停止策略（POLICY） |
|---|---|---|
| RFCOMM首次字节/Detect/建链 | 引用control/spec/09 §8.8的T_first_byte=2s、T_detect=5s、T_link=30s（均为建议，非固件常量） | 不重复定义数值；按该profile执行有限建链尝试并允许取消 |
| iAP2 ACK与重传 | 本次SYN协商的参数；完整最大重试动作仍有link OPEN | 不把应用重发与链路重传相加；记录每包序号、重试来源和剩余预算 |
| 识别/认证 | 从发送完成到所期望阶段完成；本版没有通用秒数 | 有界等待；失败关闭业务门，不通过置状态来绕过；未知profile停止并报告 |
| Pair-Setup/Verify | 每个实际握手阶段；完整超时值未证 | 不默认所有阶段幂等；保留阶段、临时对象和重复消息策略证据，不能盲发旧密文 |
| RTSP请求 | 从实际提交到匹配CSeq的完整响应 | timeout与conn_id/epoch/op_id绑定；响应不明时不盲重复SETUP/TEARDOWN |
| 媒体启动/无数据 | 流协商后到首个认证/解码/呈现分别计时 | 无包先查端口/方向；有包无输出再查认证/解码；禁明文降级 |
| 麦克风/输入空闲 | 应用请求与业务启动状态决定是否应有数据 | 用户不讲话/不操作不等于网络超时，不固定空闲断开 |
| 挂起/恢复 | 按link/spec/07和input/spec/06 | 平台唤醒先查实际链路；复查有效门；不发送反向0x5000；旧epoch回调丢弃 |

退避可作为本地策略：配置最大尝试次数、总时间预算、退避上限与抖动，禁止无限循环；
未经profile证明不要给对端发送新“心跳”命令。尝试次数耗尽、用户取消或认证/安全条件失败就停止。
恢复同一未完成TCP写时继续原密文；新建连接是否可复用配对状态需要协议证据，不能复用旧媒体nonce状态。

修改一次超时配置须保留原值和依据，重新运行相同场景与正常对照。
本章没有证明“解密失败必断开”“SETUP重试必须先TEARDOWN”或“Verify可随时重发”。

依据：E-CONTROL/E-VERIFY/E-GATE；
