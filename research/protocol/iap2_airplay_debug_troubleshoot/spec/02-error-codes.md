# 错误域、返回值与可推断范围

记录至少包含 domain、数值、产生函数/层、方向、conn_id/epoch、阶段。
同一个数字在不同域不等价。下表不是RTSP→OSStatus→根因的转换表。

## iAP2与本地固件值

| 域/值 | 来源 | 能证明 | 不能证明/下一步 |
|---|---|---|---|
| iAP2控制字节 RST位0x10 | E-LINK；link参考codec | 已识别帧携带RST位；不是错误返回码 | 查发起方向与先前状态，不能仅凭RST认定校验错 |
| seq/ack | E-LINK；头5/6 | 8位模256计数 | 255→0不是丢包；ACK要结合窗口与会话代际 |
| FSM事件0x14 | link/spec/07，24A446 | 内部失败事件，各状态动作不同 | 不是线上字段/通用平台errno，最大重试判定仍有OPEN |
| Sender -0x4178（-16760，32位0xffffbe88） | E-VIDEO；0x2519b52c4 | 此调用链payload连续长度不等于总长 | 不是固定“密钥错”码；检查CMBlockBuffer连续性与长度，别重配对 |
| CoreUtils -0x1a4f（-6735，0xffffe5b1） | E-DERIVE；0x18be50244 | 此派生入口内部type为0或>6时拒绝 | 不是线上TLV值；核对选中的provider/对象类型 |
| CoreUtils -0x1a35（-6709，0xffffe5cb） | E-DERIVE；0x18be50324 | type/state组合不符，或type1/2材料指针/长度为空 | 不证明对端密钥错误；检查握手完成门，不跳过认证 |
| 平台socket错误 | 操作系统API返回（本版无固定数值表） | 该次调用在某API域失败 | 必须保留域与系统版本；POSIX errno、WinSock、Bluetooth HCI不能互套 |

十六进制显示须明确位宽/有无符号。不把日志格式`%#m`打印名称当跨版本稳定错误枚举。

## RTSP响应（仅标准语义，不声称真车已出现）

来源：[RFC2326](https://www.rfc-editor.org/rfc/rfc2326.html) §7/11/12.17（E-RTSP）。
按当前连接/epoch中的CSeq匹配请求；2xx、4xx、5xx是状态类别，不是所有内部操作的完成证明。

| 状态 | 有限解释 | 排查建议 |
|---|---|---|
| 400/401/403 | 请求格式或授权相关拒绝，具体原因仍需上下文 | 检查请求与当前认证阶段；不把401直接当配对TLV错误 |
| 405/501 | 资源不允许该方法 / 服务未实现该能力 | 核对method、路径、Allow（若有）及profile；不盲换方法 |
| 451/461 | 参数或传输描述不被支持 | 对比协商数据与实际请求，不用固定端口猜 |
| 454/455 | 会话标识或当前状态不适用 | 检查是否带旧Session、旧epoch响应或顺序错误 |
| 500/503 | 服务侧错误状态 / 不可用 | 保留关联上下文；不能单凭状态认定车机bug |
| 未知三位值 | 扩展或未支持状态 | 保留数值并报未知；不能据名字猜重试或回退 |

HTTP式控制、RTSP响应和配对TLV须保留各自容器类型；没有证据将某个RTSP值映射成上表固件负数。

## 配对与加密

- E-AUTH：车机证书解析、路径信任、用途/有效期、挑战签名分别记录成功/失败；样本验签成功不证明完整信任链。
- E-VERIFY：M4的“bad status”来自TLV7，不是“非HTTP 200”。ACL错误构造Error/State TLV有条件，不能泛化到每个验签错误。
- E-DERIVE：TLV加密密钥、ECDH共享秘密、控制方向密钥、媒体密钥用途不同；只记材料来源类别/长度/代际编号，不记值。
- E-SCREEN/E-AUDIO：认证失败可能涉及错误provider/key/nonce/AAD/段边界或数据改动，单次失败不能区分。先证明记录完整、坐标正确，再用受控夹具逐项排除。
- E-CONTROL：部分socket写应续发原密文缓存；重新加密会改变记录状态。不能将所有socket错误恢复策略写成固定重连。
- 不因NULL cryptor、短段返回0或能解析RTP头而允许明文回退。未认证载荷不得交给业务/解码器。
