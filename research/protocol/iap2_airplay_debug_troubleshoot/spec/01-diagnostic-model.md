# 分层定位与30分钟工作表

这是时间分配建议，不是性能承诺或协议超时。先冻结可重现的失败，不盲改多项配置。

## 0–5分钟：确定实验身份

登记客户端版本、OS/蓝牙适配器、车机型号/固件、无线或有线路径、构建profile、
成功基线、失败触发操作、最后一次正常时间、抓包接口/方向/时钟来源。
本仓库23G90是iAP2样本，24A446是静态镜像；不能将两者写成同一次运行。
每条新连接分配本地conn_id与epoch；重用同一个线上会话号也不能复用epoch。

## 5–15分钟：找最后成功边界与第一个未通过边界

以下是依赖检查表，不是假定所有CarPlay profile都按同一总顺序执行。
音频、视频、麦克风、输入分别追踪；mDNS是否必经取决于实际profile。

| 边界 | 最低成功证据 | 不能作为成功的证据 | 下一步观测 |
|---|---|---|---|
| 平台蓝牙/RFCOMM | 目标通道打开且双向字节流可读写 | UI显示已配对 | socket返回域/码、通道来源、HCI或双方字节流日志 |
| iAP2链路 | 重组完整帧校验通过、SYN会话条目与确认匹配 | 仅收到ACK位或FF5A | seq/ack/session、协商校验宽度、重传队列与时间线 |
| 识别/认证 | 当前profile解析与验证成功，门控允许 | 只收到AA01、验CN、将对端根设为信任锚 | handler入口/结果、可信验证策略；不打印证书原文 |
| IP/端点 | 目标接口、地址/IPv6 scope、端口可用 | 只看到mDNS名字或4301 | 实际地址路由、接口切换、DNS TTL、连接结果 |
| Pair-Verify/控制 | 当前阶段校验成功，控制记录读写进入适用模式 | TCP打开、HTTP 200、某条“paired”日志 | TLV阶段/错误字段、provider/角色与密钥代际编号 |
| 流协商 | 匹配请求的成功响应且描述符通过本地profile检查 | SETUP返回2xx就认定画面已显示 | type/stream ID/端口/方向、资源创建结果 |
| 媒体 | 接收、认证、解码、呈现分别有证据 | send成功、包被抓到、RTP可解析 | 字节/段长度、时钟、队列、解码/呈现计数 |
| 输入/业务 | 收到→门控→解析→组件/订阅→应用实际处理 | 报告已收到或辅助触控已启动 | 描述符版本、组件有效性、事件投递/消费计数 |
| 恢复 | 当前epoch各域门复查通过，旧回调被拒绝 | 链路ACK、平台唤醒、恢复定时器到期 | 暂停原因、旧绑定失效、首个恢复业务的前置条件 |

## 15–25分钟：一次只排除一个假设

1. 相同时间窗口内比较发送方入队/实际写出/接收方读取/解析/门控/平台执行。
2. 缺一端数据就写“不可区分”，不宣称“对端丢弃”。发送API成功常只表示本地接收了数据。
3. 抓包缺帧先查捕获过滤器、接口切换、snaplen、丢包计数、权限及加密/隧道边界。
4. TCP按字节流重组，不能按单次recv或单个TCP段划RTSP/媒体记录。
5. 在合成夹具或停车台架重放一次最小变体；不能在线行驶中注入故障。

## 25–30分钟：交付一个可复查结论

填写：现象；最后成功边界；第一个已证失败检查；证据引用与帧号/事件编号；
候选原因；已排除项；单变量实验；处置/回滚；仍缺什么。
“认证失败”与“凭证不匹配”不同；前者是观察，后者需要更具体的验证失败原因。
无证据时交付下一条具体取证动作：若断言涉及字段、默认值、状态门或错误传播，
先给出并追踪对应固件调用点；若涉及目标运行结果，再明确所需日志/采集点。
不能用不断重连代替定位，也不能把“代码未追完”改写成用户必须抓包。

## 已静态查清的业务/视频诊断分界

- NowPlaying字段错位：0x5000参数0是媒体项属性，1是播放属性；检查解析/路由是否反写，不需要等新样本才能修正规范。
- 重复订阅：成功Start先提交旧子订阅移除再替换数组；这不保证底层计数幂等。
  PlaybackQueueList与其余三类的清理链需分别核查，不能从收到0x5000就断言发生订阅泄漏。
- 0x5003参数2无即时效果：先查Start参数1是否携带0x11子项，以及feature+51门；
  参数2=0xffffffff表示自动窗口选择，与参数1的“播放队列索引设置”不是同一操作。
- 视频未知类型：已核统计分支会产生2/5；不能把所有非0/1记录直接称为损坏帧，
  也不能因为知道类型就断言统计payload可解码或安全跳过。
- 音频SETUP字段类型：audioFormat应是整数格式标识，不能发送本地CODEC/rate名称字符串。
  检查编码器映射与方向选择，不用“车机不支持此codec”掩盖字段类型错误。
- 格式集合误作单个格式：spec11已列出原转换器的59个单个位ID；多位组合不能直接传入转换器或当最终选择。
  保留bit63，不按宿主有符号负值提前拒绝；表内可描述不等于车机支持或本机已实现codec。
- PCM/压缩描述混用：基础、传输和HAL描述分开；PCM传输flags OR2而HAL清2。
  aac等压缩ASBD bits=0不代表无解码位深，要看可选bits输出；HAL的1F/packet不能覆盖传输帧长。
- 能力存在却未选中：检查数组顺序。前面的未指定audioType项会遮住后面的精确项，mask0也停止；
  default仅保留停止前的最后一项，0会覆盖旧值，并受manufacturer的Apple前缀门限制。
- 候选获取成功但不能配置codec：记录基础过滤和后置过滤各自的mask。基础AND后空集合返回-6705，
  后置telephony/raw103限制清空却不再报该错误；成功返回不是“已选到格式”或“播放已就绪”。
- 包长偏差：已核spf为整数、pps向零截断；48000/512得到93而非94。此公式不代替MTU/分片规则。
- 突发与重传：raw107的本机burst偏好缺失默认200不等于车机缺键默认；
  独立resume路径仅LowLatencyAudio相等时写disableRetransmits=true，不能按“能力字典含键”复刻。
- 视频关键帧误判：bit7来自APInterestingFrame，bit4来自NotSync派生；均不代替NAL IDR检查。
  bit4取首个合法布尔NotSync的反相，false也停止查找；不能用all/any汇总数组。
  已核avcC缓存变化→type1配置并组装于帧前；若初始化失败继续查内部参数集和profile，不再只搜索avcC名字。

依据：E-NOWPLAY/E-RECORD/E-CONFIG/E-FORMAT/E-CAPABILITY；局部静态/原指令仿真路径，不是真实故障归因或完整平台执行证据。

依据：E-LINK/E-AUTH/E-GATE/E-VERIFY/E-CONTROL及本地诊断策略。
